Anatomia do Programa DEVOPSPL.cbl

Program-ID
DEVOPSPL
Tipo
Batch COBOL — sem I/O de arquivo
Entrada
Constante em Working-Storage (WS-FALHA-SIMULADA)
Saída
DISPLAY (SYSOUT) + RETURN-CODE (0 ou 8)
Dependências externas
Nenhuma (sem COPY, sem CALL, sem DB2/CICS)
Etapas modeladas
7 registros em WS-TABELA-ETAPAS (OCCURS 7)
Return-Code de falha
8 — parada controlada na etapa com falha

Estrutura de Parágrafos

•
000-MAIN
Ponto de entrada. Inicializa, itera sobre as 7 etapas, chama aborto se necessário, exibe resumo e executa GOBACK.
•
100-INICIALIZAR / 110-CARREGAR-TABELA
Captura data/hora (FUNCTION CURRENT-DATE), preenche WS-TABELA-ETAPAS com os 7 estágios DevOps e seus produtos IBM.
•
200-EXECUTAR-ETAPA / 240-AVALIAR-STATUS
Exibe nome, produto e atividade da etapa atual. Compara WS-IDX com WS-FALHA-SIMULADA: se iguais → FALHA + ESTEIRA-ABORTADA = 'S'.
•
800-ABORTAR-ESTEIRA
Exibe alerta com nome da etapa falha e define RETURN-CODE = 8.
•
900-RESUMO-FINAL
Exibe tabela de status de todas as etapas (SUCESSO / FALHA / NAO EXEC.), total de etapas concluídas e Return-Code final.

Detalhamento de Cada Fase

🔍 ZCodeScan maxRC = 4

Análise estática obrigatória antes da compilação.

  • Linguagens: COBOL e PLI
  • Encoding: IBM-1047
  • RC ≤ 4: WARNING aceitável
  • RC > 4: pipeline bloqueada
  • Regras ativas: +40 regras COBOL configuradas
  • Relatório: zcodescan.log + JUnit/SonarQube
  • Config: zcodescan/zcodescan-config.yml

🔨 Build — IBM DBB compile RC≤4 link RC=0

Compilação dependente com gerenciamento automático de copybooks.

  • Compilador: IGYCRCTL (COBOL V6.2)
  • Opções: LIB (batch sem CICS/SQL)
  • Link-edit: IEWBLINK (MAP,RENT)
  • Datasets: HLQ.COBOL, HLQ.OBJ, HLQ.LOAD
  • deployType: LOAD
  • Config: dbb-app.yaml + Cobol.yaml

🧪 TAZ — Test Accelerator for Z RC = 0

Execução de testes unitários automatizados no contexto z/OS.

  • Casos de teste definidos via zapp.yaml (EDT profile)
  • Verifica RETURN-CODE do programa (0 = sucesso, 8 = falha)
  • Cenário de teste base: WS-FALHA-SIMULADA = 0
  • Cenário de falha: WS-FALHA-SIMULADA = N (etapa N)
  • Valida saída SYSOUT via DISPLAY statements
  • Resultado: relatório JUnit integrado ao pipeline

🚀 Wazi Deploy RC = 0

Empacotamento e implantação controlada do módulo de carga.

  • Artefato: HLQ.LOAD(DEVOPSPL)
  • deployType: LOAD
  • Pacote gerado pelo DBB build result
  • Deploy para ambiente-alvo via API Wazi
  • Rollback automático em caso de falha
  • Auditoria completa de versão implantada

Artefatos: Configuração da Pipeline

pipeline-devopspl.yaml — Orquestração Completa

# pipeline-devopspl.yaml
# Esteira DevOps IBM Z para DEVOPSPL (Batch COBOL)
# Tecnologias: ZCodeScan → DBB → TAZ → Wazi Deploy → OMEGAMON

pipeline:
  name: Bank-of-Z DEVOPSPL Batch Pipeline
  application: Bank-of-Z-main
  trigger:
    branches: [main, develop]
    paths: ["src/base/batch/cobol/DEVOPSPL.cbl"]

stages:

  # ─────────────────────────────────────────
  # ETAPA 1 — PLAN  (manual gate)
  # ─────────────────────────────────────────
  - name: plan
    displayName: "1/7 — PLAN: Análise de Impacto"
    type: manual-gate
    tools: [IBM Z Understand, IBM EWM]
    approval_required: true

  # ─────────────────────────────────────────
  # ETAPA 2 — CODE  (automatico: lint local)
  # ─────────────────────────────────────────
  - name: code
    displayName: "2/7 — CODE: Validação do Commit"
    type: automated
    tools: [IBM Z Open Editor]
    on_failure: block-push

  # ─────────────────────────────────────────
  # ETAPA 3 — Z CODE SCAN
  # ─────────────────────────────────────────
  - name: zcodescan
    displayName: "3/7 — Z CODE SCAN: Análise Estática"
    type: automated
    tool: IBM ZCodeScan
    config: zcodescan/zcodescan-config.yml
    rules: zcodescan/zcodescan-rules.yaml
    params:
      encoding: IBM-1047
      languages: [COBOL, PLI]
      maxReturnCode: 4
      export_formats: [junit, sonarqube]
      log: zcodescan.log
    on_failure: abort
    publish_report: true

  # ─────────────────────────────────────────
  # ETAPA 4 — BUILD (IBM DBB)
  # ─────────────────────────────────────────
  - name: build
    displayName: "4/7 — BUILD: Compilação DBB"
    type: automated
    tool: IBM Dependency Based Build
    config: dbb-app.yaml
    targets:
      - source: "src/base/batch/cobol/DEVOPSPL.cbl"
        language: Cobol
        deployType: LOAD
    steps:
      - step: compile
        pgm: IGYCRCTL
        parm: LIB
        maxRC: 4
      - step: linkEdit
        pgm: IEWBLINK
        parm: "MAP,RENT"
        maxRC: 0
    on_failure: abort
    publish_artifacts: ["${HLQ}.LOAD(DEVOPSPL)", "${HLQ}.OBJ(DEVOPSPL)"]

  # ─────────────────────────────────────────
  # ETAPA 5 — TEST (IBM TAZ)
  # ─────────────────────────────────────────
  - name: test
    displayName: "5/7 — TEST: TAZ Automatizado"
    type: automated
    tool: IBM Test Accelerator for Z
    test_scenarios:
      - name: happy_path
        ws_falha_simulada: 0
        expected_rc: 0
        expected_output: "ESTEIRA FINALIZADA COM SUCESSO"
      - name: falha_etapa_3
        ws_falha_simulada: 3
        expected_rc: 8
        expected_output: "ESTEIRA INTERROMPIDA NA ETAPA: Z CODE SCAN"
      - name: falha_etapa_4
        ws_falha_simulada: 4
        expected_rc: 8
        expected_output: "ESTEIRA INTERROMPIDA NA ETAPA: BUILD"
    on_failure: abort
    publish_report: junit

  # ─────────────────────────────────────────
  # ETAPA 6 — DEPLOY (IBM Wazi Deploy)
  # ─────────────────────────────────────────
  - name: deploy
    displayName: "6/7 — DEPLOY: Wazi Deploy"
    type: automated
    tool: IBM Wazi Deploy
    package:
      artifact: "${HLQ}.LOAD(DEVOPSPL)"
      deploy_type: LOAD
      target_env: ${TARGET_ENV}
    rollback_on_failure: true
    on_failure: rollback-and-abort

  # ─────────────────────────────────────────
  # ETAPA 7 — MONITOR
  # ─────────────────────────────────────────
  - name: monitor
    displayName: "7/7 — MONITOR: OMEGAMON"
    type: continuous
    tools: [IBM OMEGAMON, IBM Z Anomaly Analytics]
    window_minutes: 30
    alert_threshold: warning
    on_alert: notify-and-hold

Pontos de Integração: DEVOPSPL.cbl ↔ Pipeline

Elemento do ProgramaIntegração na Pipeline
WS-FALHA-SIMULADA PIC S9(04) VALUE 0 TAZ sobrescreve via LINKAGE ou JCL PARM para simular falha em qualquer etapa
RETURN-CODE = 8 (800-ABORTAR-ESTEIRA) DBB e TAZ capturam o RC 8 para acionar abort e publicar falha no relatório
RETURN-CODE = 0 (fluxo normal) Wazi Deploy só executa se esta condição for satisfeita pelo passo de test
DISPLAY '*** ESTEIRA FINALIZADA ***' TAZ valida o conteúdo do SYSOUT para confirmar a saída esperada
WS-TABELA-ETAPAS OCCURS 7 Documenta exatamente as 7 fases da pipeline que o programa modela
Sem COPY/CALL/DB2/CICS Build usa apenas opção LIB; não requer SDFHLOAD, SDSNLOAD ou copybooks externos
FUNCTION CURRENT-DATE Saída de data/hora usada para timestamping no log de execução do job

Plano de Apresentação Técnica

Slide 1 Visão Geral — DevOps no IBM Z com Bank of Z
  • O que é o Bank of Z e por que DevOps em mainframe importa
  • Desafio: qualidade, velocidade e conformidade em ambientes z/OS
  • Solução: esteira automatizada de 7 etapas com ferramentas IBM nativas
  • Demonstração ao vivo: DEVOPSPL.cbl como modelo executável da pipeline
Slide 2 O Programa DEVOPSPL — Código que Documenta a Própria Esteira
  • Programa COBOL batch que simula e exibe cada etapa da pipeline via DISPLAY
  • Arquitetura: tabela interna com 7 etapas, loop com detecção de falha
  • Saída: SYSOUT com status de cada etapa + RETURN-CODE (0=sucesso, 8=falha)
  • Ponto-chave: WS-FALHA-SIMULADA permite injetar falha em qualquer etapa para testes
Slide 3 Fase ZCodeScan — Qualidade e Conformidade Antes do Build
  • +40 regras COBOL ativas (segurança, desempenho, boas práticas)
  • Execução obrigatória antes da compilação; bloqueio automático se RC > 4
  • Exportação para SonarQube e JUnit integrada à pipeline
  • Para DEVOPSPL: ausência de SQL, CICS, HANDLE CONDITION → baseline limpo esperado
Slide 4 Fase Build — IBM DBB: Compilação Dependente e Inteligente
  • Detecta automaticamente alterações em fontes e copybooks
  • COBOL V6.2 (IGYCRCTL) + Link-edit (IEWBLINK MAP,RENT)
  • DEVOPSPL: compilado com opção LIB — sem CICS/SQL/IMS flags
  • Artefato gerado: HLQ.LOAD(DEVOPSPL) — deployType = LOAD
Slide 5 Fase TAZ — Testes Automatizados para COBOL Batch
  • 3 cenários de teste: happy path, falha na etapa 3 (ZCodeScan), falha na etapa 4 (BUILD)
  • Validação dupla: RETURN-CODE esperado + conteúdo do SYSOUT
  • WS-FALHA-SIMULADA é o ponto de controle para injeção de cenários
  • Resultado exportado como JUnit XML para rastreabilidade no repositório
Slide 6 Fase Deploy + Monitor — Wazi Deploy e OMEGAMON
  • Wazi Deploy empacota artefatos do DBB e os implanta no ambiente alvo de forma controlada
  • Rollback automático se deploy falhar — zero downtime para batch
  • OMEGAMON monitora por 30 minutos pós-deploy; anomalias disparam alerta
  • Z Anomaly Analytics detecta desvios de desempenho baseados em histórico
Slide 7 Benefícios e Métricas de Sucesso
  • Velocidade: redução do ciclo de entrega de dias para horas com DBB incremental
  • Qualidade: violações detectadas antes do build; zero surpresas em produção
  • Confiabilidade: testes automatizados (TAZ) eliminam regressões manuais
  • Rastreabilidade: cada artefato vinculado ao commit, build, teste e deploy
  • Conformidade: regras ZCodeScan aplicadas uniformemente em todos os commits
