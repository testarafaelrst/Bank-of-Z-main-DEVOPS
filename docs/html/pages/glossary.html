Glossary

This glossary defines the terms, acronyms, and concepts used across the Bank of Z documentation. It covers the application itself, the z/OS middleware it runs on, and the tools used to build, deploy, and operate it.

1. Overview

1.1 Purpose

Bank of Z is a sample hybrid banking application. It demonstrates modern z/OS application development, integration, build, deployment, and operational workflows. The documentation uses many acronyms and product names from the IBM Z ecosystem, and this page defines them in one place.

1.2 How the Terms Are Organized

The terms fall into the following groups:

Transaction processing and data CICS, IMS TM, IMS DB, Db2, Account History Db2 Database, BMS

2. System Architecture

2.1 High-Level Component View

Bank of Z is a hybrid application. A web application calls z/OS services through z/OS Connect, and requests are processed by either CICS or IMS TM. Both paths share common services and data resources. IBM MQ connects Bank of Z to the external Bank of Q system for money transfer scenarios.

graph TD U[User / Web Application] --> ZC[z/OS Connect API Framework] ZC --> CR{Customer Routing} CR -->|ID begins with C| CICS[CICS Transactions] CR -->|ID begins with I| IMS[IMS TM Transactions] CICS --> DB2[(Db2 for z/OS)] IMS --> IMSDB[(IMS DB)] CICS --> MQ[IBM MQ] IMS --> MQ MQ --> BOQ[Bank of Q External System] DB2 --> HIST[(Account History Db2 Database)]

This diagram shows how the glossary terms relate at runtime:

  • z/OS Connect provides the interface between the web application and the CICS and IMS transaction environments.
  • Customer Routing chooses the environment from the customer identifier.
  • Db2 stores customer, account, and transaction information. The Account History Db2 Database holds historical data for inquiry and reporting.
  • IMS DB is the hierarchical database used by the IMS processing path.
  • IBM MQ provides asynchronous communication with external systems such as Bank of Q.

2.2 Customer Routing Model

Customer Routing is the central rule of the Hybrid Architecture. It decides which transaction manager handles a request.

flowchart LR A[Incoming request with Customer ID] --> B{First character} B -->|C| C[CICS transaction] B -->|I| D[IMS TM transaction] C --> E[Shared services and data resources] D --> E E --> F[Unified user experience]

2.3 Development and Delivery Toolchain

Separate from the runtime architecture is the toolchain used to develop, build, and deploy Bank of Z.

graph TD DEV[Developer] --> IDE[VS Code or Bob IDE] IDE --> GIT[Git] IDE --> ZCLI[Zowe CLI] ZCLI --> RSE[RSE API] RSE --> USS[z/OS USS] GIT --> PIPE[Pipeline] PIPE --> DBB[DBB] DBB --> ZB[zBuilder] ZB --> ART[Build Artifacts] ART --> WD[Wazi Deploy] WD --> ODE[On-Demand Environment] SCAN[ZCodeScan] -.analyzes source.-> GIT ZCFG[zconfig] -.configures middleware.-> ODE

In this view:

  • Developers work in VS Code or Bob IDE and use Git for version control.
  • Zowe CLI and the RSE API let tools reach z/OS datasets and USS files.
  • DBB and zBuilder compile and link the code.
  • Wazi Deploy deploys the resulting artifacts.
  • ZCodeScan performs static analysis of source quality.
  • zconfig applies configuration as code to middleware.

3. Application and Architecture Terms

3.1 Bank of Z and Bank of Q

Term Definition
Bank of Z A sample hybrid banking application that demonstrates modern z/OS application development, integration, build, deployment, and operational workflows.
Bank of Q A sample external banking system used to demonstrate inter-application communication and money transfer scenarios through IBM MQ.

3.2 Hybrid Architecture and Customer Routing

Term Definition
Hybrid Architecture An application architecture that integrates multiple transaction-processing environments and technologies into a unified user experience. Requests are processed through either CICS or IMS TM and share common services and data resources.
Customer Routing The mechanism that routes requests to either CICS or IMS TM based on the customer identifier pattern.

4. Transaction Processing, Data, and Integration Terms

4.1 Transaction Managers

  • CICS (Customer Information Control System) is an IBM transaction-processing system for online business transactions. Customers with identifiers beginning with C are routed to CICS transactions.
  • IMS TM (IBM Information Management System Transaction Manager) is the other transaction-processing environment. Customers with identifiers beginning with I are routed to IMS TM transactions.
  • BMS (Basic Mapping Support) is a CICS facility that defines terminal screen layouts and user interactions.

4.2 Data Stores

  • Db2 (IBM Db2 for z/OS) is a relational database that stores customer, account, and transaction information.
  • Account History Db2 Database is a Db2 database that stores historical account and transaction information for inquiry and reporting.
  • IMS DB (IBM Information Management System Database) is a hierarchical database used by the IMS processing path.

4.3 Integration Technologies

  • API (Application Programming Interface) is a defined interface that lets applications and services communicate.
  • z/OS Connect is an API framework that enables REST-based access to z/OS applications and services. It connects the web application to the CICS and IMS transaction environments.
  • IBM MQ is messaging middleware for asynchronous communication between applications and external systems.

4.4 Programming Assets

  • COBOL (Common Business-Oriented Language) is the primary language for Bank of Z business logic.
  • Copybook is a reusable source file containing data structure definitions shared across COBOL programs.
  • JVM (Java Virtual Machine) is the runtime environment that executes Java applications and services.

5. Development, Build, and Deployment Terms

5.1 Development Tools

Term Definition
Bob IDE IBM Premium Bob for Z, an integrated development environment that supports IBM Z application development workflows.
VS Code Visual Studio Code. A development environment commonly used to develop, build, and manage Bank of Z assets.
Git A distributed version control system used to manage source code and support collaborative development.
Zowe CLI A command-line interface for interacting with z/OS systems, services, datasets, USS files, and development workflows.
RSE API Remote System Explorer API. A service used by Zowe CLI and development tools to interact with z/OS resources.
ZOAU IBM Z Open Automation Utilities. A collection of utilities and APIs that automate z/OS administration and development tasks.
ZCodeScan A static analysis tool that analyzes source code quality and identifies potential issues.

5.2 Build and Deployment

Term Definition
DBB IBM Dependency Based Build. A build framework used to compile, link, and manage z/OS application builds.
zBuilder A build framework used with DBB to automate compilation, linking, and build orchestration for z/OS applications.
Wazi Deploy IBM deployment automation tooling used to deploy application artifacts and configuration changes.
Pipeline An automated sequence of build, packaging, deployment, and validation activities executed through Bank of Z development workflows.
zconfig The z/OS Middleware Configuration Tool, a command-line tool that configures and creates artifacts for CICS TS, Db2 for z/OS, IMS, and z/OS Connect. It introduces configuration as code to z/OS middleware.

5.3 Workflows

A Workflow is a defined development process used to build, deploy, test, and validate application changes. Bank of Z supports two workflows:

  • The VS Code workflow.
  • The GRUB workflow. GRUB (Git Remote User Build) synchronizes local changes to z/OS USS and runs setup and build processes without requiring a commit for every change.
sequenceDiagram participant Dev as Developer participant GRUB as GRUB Workflow participant USS as z/OS USS participant Build as DBB / zBuilder Dev->>GRUB: Make local changes (no commit required) GRUB->>USS: Synchronize changed files GRUB->>USS: Run setup process USS->>Build: Trigger build Build-->>USS: Build artifacts USS-->>Dev: Build results

The sequence above shows why GRUB shortens the inner development loop: changes are synchronized and built on z/OS directly, without a commit and push for each change.

5.4 Runtime Environment Terms

  • USS (UNIX System Services) is the POSIX-compliant environment within z/OS. It hosts source code, scripts, build artifacts, and application assets.
  • ODE (On-Demand Environment) is a preconfigured development and testing environment used to provision and run Bank of Z components.

7. Examples

The glossary defines the terms through a table and one behavioral rule, Customer Routing. The examples below show both.

7.1 Customer Routing Rule

This pseudocode restates the glossary’s description of Customer Routing. It is illustrative and is not an excerpt of the application source.

TEXT 
IF customer-id begins with "C"
    route request to CICS transaction
ELSE IF customer-id begins with "I"
    route request to IMS TM transaction
Customer ID Routed To
C… CICS
I… IMS TM
