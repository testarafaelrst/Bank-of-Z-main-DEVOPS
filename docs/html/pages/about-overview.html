Project Overview

Bank of Z is an open-source sample banking application created to demonstrate modern IBM Z development, build, deployment, and modernization practices. It provides a browser-based banking experience backed by enterprise transaction-processing systems on IBM Z. At the application level, Bank of Z is designed as a realistic learning and demonstration platform that combines familiar digital banking interactions with core IBM Z technologies such as CICS, IMS Transaction Manager (IMS TM), and Db2 for z/OS.

Its primary value is not as a production banking product, but as a practical environment for IBM Z education, modernization demonstrations, and proof-of-concept projects. It helps teams understand how traditional transaction-processing systems can participate in modern development workflows while continuing to use proven IBM Z runtime capabilities.

1. Overview

Bank of Z is intended to help users explore how enterprise applications on IBM Z can be developed, built, deployed, maintained, and modernized using contemporary practices and tooling. The application presents a browser-based front end for common banking operations and routes requests through a hybrid backend architecture.

The platform is especially suited for the following scenarios:

  • IBM Z education and skills development
  • Application modernization demonstrations
  • DevSecOps and deployment automation evaluation
  • Proof-of-concept implementations
  • Hands-on experimentation with IBM Z development tools
  • Extension and customization of a realistic banking sample

Bank of Z demonstrates how modern user-facing experiences can coexist with established enterprise transaction systems. In this model, customer requests are processed by either CICS or IMS TM, while both environments share common banking data stored in Db2 for z/OS.

1.1 Goals

The goals of Bank of Z are to provide a practical application that can be used to:

  • Learn IBM Z development workflows
  • Explore hybrid application architectures
  • Demonstrate enterprise application capabilities
  • Evaluate build and deployment automation
  • Experiment with modernization approaches
  • Extend a sample banking application for custom use cases

1.2 Intended Use Cases

Bank of Z is specifically intended for:

  • Education: teaching IBM Z development concepts, workflows, and architecture
  • Demonstrations: showcasing modernization patterns and enterprise integration
  • Proof of concept: validating tools, pipelines, and implementation approaches
  • Technical experimentation: testing enhancements, deployment changes, and architecture ideas

It is best understood as a reference-style learning application rather than a production-ready banking solution.

2. System Architecture

At a high level, Bank of Z uses a hybrid IBM Z architecture. A browser-based client initiates banking actions, and backend processing is handled by IBM Z transaction managers. The architecture intentionally demonstrates multiple transaction-processing paths while maintaining a shared system of record in Db2 for z/OS.

The core architectural characteristics are:

  • Browser-based user interface
  • Hybrid request processing through CICS or IMS TM
  • Shared banking data in Db2 for z/OS
  • Realistic enterprise-style transaction flow
  • Support for modernization and demonstration scenarios

2.1 Architectural Style

Bank of Z follows a hybrid transaction-processing architecture. This is important because it reflects a realistic modernization landscape in which multiple IBM Z subsystems can support the same application domain.

Key architectural themes include:

  • Separation between user interaction and transaction execution
  • Shared persistence across multiple processing environments
  • Demonstration of coexistence between different IBM Z transaction managers
  • Support for learning and experimentation without abstracting away core enterprise components

4. End-to-End Data Flow and Processing

Bank of Z is designed so that user-driven banking actions begin in the browser and are fulfilled by IBM Z backend systems. The request may be processed through CICS or IMS TM, but both paths ultimately rely on the same shared data platform.

graph TD A[Customer Action in Browser] --> B[Bank of Z Request] B --> C{Processing Path} C --> D[CICS Transaction] C --> E[IMS TM Transaction] D --> F[Read or Update Banking Data] E --> F[Read or Update Banking Data] F --> G[Db2 for z/OS] G --> H[Response Returned to User]

This flow illustrates the hybrid nature of the application. Although there can be multiple transaction-processing routes, the user experiences a unified banking application. Shared access to Db2 for z/OS ensures consistency at the data layer across the demonstrated backend paths.

4.1 Typical Processing Pattern

A typical processing pattern in Bank of Z is:

  1. A user performs an action in the browser-based interface.
  2. The application submits a banking request.
  3. The request is handled by either CICS or IMS TM.
  4. The transaction reads or updates shared banking data in Db2 for z/OS.
  5. A result is returned to the application interface.
  6. The user sees the response as part of a single banking experience.

5. Sequence of Operations

The following sequence represents a conceptual operation flow for a banking request.

sequenceDiagram participant U as User participant W as Web Interface participant T as Transaction Processor participant D as Db2 for z/OS U->>W: Submit banking action W->>T: Send request for processing T->>D: Query or update banking data D-->>T: Return data or status T-->>W: Return transaction result W-->>U: Display response

This sequence abstracts the specific transaction manager and focuses on the operational model that Bank of Z demonstrates. In the actual architecture, the Transaction Processor may represent either CICS or IMS TM, depending on the request path being exercised.

5.1 Hybrid Transaction Execution

A distinguishing feature of Bank of Z is that the transaction-processing role is not limited to a single subsystem. Instead, the application demonstrates how different IBM Z middleware environments can support a common application domain while using shared enterprise data.

That makes the platform useful for:

  • Comparing processing approaches
  • Demonstrating interoperability patterns
  • Teaching architectural trade-offs
  • Showing modernization without discarding core IBM Z assets

9. Summary

Bank of Z is a sample banking application built to demonstrate modern IBM Z development, deployment, and modernization practices in a realistic enterprise context. Its application-level design combines a browser-based user experience with hybrid backend processing through CICS and IMS TM, supported by shared data in Db2 for z/OS.

As a result, it serves as a strong platform for:

  • IBM Z education
  • Modernization demonstrations
  • DevSecOps and workflow evaluation
  • Proof-of-concept projects
  • Hands-on experimentation with enterprise application patterns

The project’s value lies in showing how established IBM Z technologies can participate in modern application delivery and modernization journeys without losing the strengths of enterprise transaction processing and shared data management.
