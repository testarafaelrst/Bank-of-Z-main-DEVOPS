Project Overview

Bank of Z is an open-source banking application designed to demonstrate modern IBM Z development, build, deployment, and modernization practices. It provides a browser-based banking interface that integrates with IBM Z transaction-processing systems, combining traditional enterprise technologies with modern development workflows to create a realistic environment for learning, demonstrations, and experimentation.

1. Overview

Bank of Z delivers a fully functional, hybrid banking application hosted on IBM Z. Customer-facing requests flow through a browser-based front end and are handled by either CICS or IMS Transaction Manager (IMS TM) on the back end, with all banking data persisted in Db2 for z/OS. This architecture mirrors real-world enterprise patterns, making it an ideal platform for exploring IBM Z capabilities without needing a purpose-built production system.

The application is open-source and freely available via the Bank of Z GitHub Repository, enabling teams to clone, extend, and customize it to suit their specific learning or demonstration goals.

Bank of Z is designed for the following audiences:

1.2 Use Cases

Bank of Z can be used to:

  • Learn IBM Z development workflows in a safe, non-production environment
  • Explore application modernization approaches on IBM Z
  • Demonstrate enterprise application capabilities to stakeholders
  • Evaluate build and deployment automation tooling
  • Experiment with IBM Z development tools and runtimes
  • Extend and customize a sample banking application for specific scenarios

Note: Bank of Z is intended exclusively for educational, demonstration, and proof-of-concept purposes. It is not designed for production use.

2. System Architecture

Bank of Z is built on a hybrid architecture that combines a modern browser-based front end with proven IBM Z middleware and data management technologies. The two back-end transaction paths — CICS and IMS TM — operate independently but share a common Db2 for z/OS database, reflecting how many real-world enterprise Z applications are structured.

2.1 High-Level Architecture Diagram

The following diagram illustrates the major layers and components of Bank of Z:

graph TD A[Browser-Based Front End] --> B{API / Web Layer} B --> C[CICS Transaction Manager] B --> D[IMS Transaction Manager] C --> E[CICS Application Programs] D --> F[IMS Application Programs] E --> G[(Db2 for z/OS)] F --> G G --> H[Banking Data] style A fill:#0062ff,color:#fff style B fill:#6929c4,color:#fff style C fill:#009d9a,color:#fff style D fill:#009d9a,color:#fff style E fill:#198038,color:#fff style F fill:#198038,color:#fff style G fill:#b28600,color:#fff style H fill:#b28600,color:#fff

The browser-based front end submits banking requests through a web/API layer, which routes them to either the CICS or IMS TM back end depending on the transaction path configured. Both paths share the same Db2 for z/OS database, ensuring data consistency regardless of which transaction manager handles the request.

2.2 Transaction Request Flow

The sequence below shows how a typical banking request travels from the user’s browser through the IBM Z middleware stack and back:

sequenceDiagram actor User as End User (Browser) participant Web as Web / API Layer participant CICS as CICS TM participant IMS as IMS TM participant DB2 as Db2 for z/OS User->>Web: Submit banking request alt CICS path Web->>CICS: Route transaction CICS->>DB2: Read / Write banking data DB2-->>CICS: Return data CICS-->>Web: Transaction response else IMS path Web->>IMS: Route transaction IMS->>DB2: Read / Write banking data DB2-->>IMS: Return data IMS-->>Web: Transaction response end Web-->>User: Display result

The dual-path design allows teams to compare CICS and IMS TM transaction patterns side-by-side within the same application context, which is particularly useful for modernization and migration studies.

3. Purpose and Goals

Bank of Z helps demonstrate how enterprise applications can be developed, built, deployed, and maintained on IBM Z using modern development practices and tooling. It bridges the gap between classic IBM Z technologies and contemporary DevOps and modernization methodologies.

3.1 Key Demonstrations

The application is structured to support the following guided scenarios:

  • Installing and configuring the Bank of Z application environment
  • Building and deploying the application using automated pipelines
  • Modifying CICS and Db2 application components
  • Modifying IMS TM and IMS DB application components
  • Adding functional enhancements to the banking application
  • Investigating application performance issues
  • Exploring hybrid application architectures

3.2 Learning Outcomes

After working with Bank of Z, practitioners should be able to:

  1. Understand how CICS and IMS TM transaction managers process banking requests
  2. Navigate and modify a real IBM Z application codebase
  3. Execute build and deployment automation workflows on IBM Z
  4. Apply DevSecOps practices in an IBM Z context
  5. Evaluate and compare hybrid Z application architecture patterns

5. Documentation Toolchain

The Bank of Z documentation is built and published using a Jekyll-based static site with an automated DITA-to-Markdown conversion pipeline.

5.1 Documentation Pipeline

graph TD A[Author writes DITA XML in Docs/ folder] --> B[Run conversion script] B --> C[convert_dita_to_md.py generates Markdown] C --> D[toc.yml auto-generated for navigation] D --> E[Commit and push to GitHub] E --> F[GitHub Actions workflow triggered] F --> G[Jekyll builds static site] G --> H[GitHub Pages publishes site] H --> I[Live docs at ibm.github.io/Bank-of-Z]

5.2 Quick Start for Documentation Contributors

To contribute to the documentation locally:

BASH 
# Clone the repository
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z-doc

# Install dependencies
pip3 install pyyaml
bundle install

# Convert DITA source files to Markdown
python3 scripts/convert_dita_to_md.py

# Preview locally
bundle exec jekyll serve
# Visit http://localhost:4000/Bank-of-Z-doc/

6. Contributing and Support

Bank of Z is an open-source project. Contributions to both the application and its documentation are welcome.

6.1 How to Contribute

  1. Fork the Bank of Z repository
  2. Create a feature branch
  3. Add or edit DITA source files in the Docs/ directory
  4. Run the conversion script: python3 scripts/convert_dita_to_md.py
  5. Commit your changes and submit a pull request

6.2 Support Channels

  • Open an issue in the GitHub repository
  • Review existing documentation at ibm.github.io/Bank-of-Z
  • Consult the IBM Z Documentation for platform-level reference
