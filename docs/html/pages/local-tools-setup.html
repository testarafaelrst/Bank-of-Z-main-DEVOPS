Local Tools Setup

1. Overview

This page describes how to install and configure the local toolchain used for Bank of Z development. It covers four areas:

  • IDE: IBM Bob Premium Package for Z, or Visual Studio Code with the required IBM Z extensions. You use it to browse, edit, and manage the source code.
  • Zowe profile: a single ~/.zowe/zowe.config.json file. IDE extensions and the Zowe CLI both use it to connect to z/OS.
  • Zowe CLI: the deployment tooling for the Zowe CLI workflow. It includes the IBM RSE API plug-in.
  • GRUB (Git Remote User Build): the deployment tooling for the GRUB workflow. It syncs local changes to z/OS USS and runs a post-sync hook.

Before you begin, clone the Bank of Z repository to your local machine. Git is required for all workflows.

Which tools you need depends on the deployment workflow you choose:

Workflow Local tooling required
Zowe CLI IDE, Zowe profile, Zowe CLI and IBM RSE API plug-in
GRUB IDE, Zowe profile (for the IDE extensions), GRUB with post-sync hook
Direct USS No additional local deployment tooling. Connect to z/OS USS over SSH and run the setup scripts manually.

IDE setup is independent of the deployment workflow you choose.

2. System Architecture

The local workstation hosts the IDE, the Zowe profile, and the deployment tooling. The Zowe profile is the shared connectivity layer. The IDE extensions and the Zowe CLI read it to reach the z/OS services. GRUB uses its own remote host, user, and path settings and connects to USS directly.

2.1 Component Responsibilities

Component Responsibility
IDE Browse, edit, and manage Bank of Z source code
IBM Z extensions Language support, debugging, Zowe Explorer, and CICS, IMS, Db2, z/OS Connect and test tooling

3. IDE Setup

An IDE is required to browse, edit, and manage Bank of Z source code. For the best experience, and to follow the tutorials in the documentation, use IBM Bob Premium Package for Z. Visual Studio Code is the alternative. Complete this setup before you continue to the deployment tooling.

3.1 Prerequisites

Java 21 is required to run the IDE and its embedded tooling. Install IBM Semeru Runtime for Java 21 or later, and then verify the installation:

BASH 
java -version

3.2 Required Extensions

Install the following extensions in your IDE.

Note: If you use IBM Bob Premium Package for Z and an extension is unavailable in the Open VSX Marketplace, download the VSIX package and install it manually.

Extension Description VS Code Marketplace Open VSX VSIX

Note: There is no IBM extension for IBM MQ in the VS Code Marketplace. See the IBM MQ Console extension, available from the ibm-messaging GitHub group.

3.3 Installation Methods

3.3.1 Install Extensions from a Marketplace

  1. Open the Extensions view in your IDE.
  2. Search for the extension by name.
  3. Select Install.

3.3.2 Install VSIX Packages Manually

  1. Download the VSIX file using the link in the table above.
  2. Open the Extensions view.
  3. Select More Actions (…) → Install from VSIX…
  4. Browse to the downloaded file and complete the installation.

3.3.3 Automated VSIX Download and Install

Bank of Z includes scripts that download and install all required VSIX packages in one step.

sequenceDiagram participant Dev as Developer participant DL as download-vsix.js participant Dir as vsix-extensions directory participant Inst as install-*-vsix.js participant IDE as Bob IDE / VS Code Dev->>DL: node scripts/download-vsix.js [output-directory] DL->>Dir: Save VSIX packages Dev->>Inst: node scripts/install-bobide-vsix.js or install-vscode-vsix.js Inst->>Dir: Read VSIX packages Inst->>IDE: Install extensions through the CLI command in PATH

Download all packages:

BASH 
node scripts/download-vsix.js [output-directory]

The default output directory is ./vsix-extensions.

Install into IBM Bob Premium Package for Z:

BASH 
# First add bobide to PATH:
# View > Command Palette > Shell Command: Install 'bobide' command in PATH

node scripts/install-bobide-vsix.js [output-directory]

Install into VS Code:

BASH 
# First add code to PATH:
# View > Command Palette > Shell Command: Install 'code' command in PATH

node scripts/install-vscode-vsix.js [output-directory]

For more information, see scripts/README.md.

3.4 Verify the IDE Configuration

  1. Launch the IDE.
  2. Confirm all required extensions are installed and enabled.
  3. Open the Bank of Z repository and confirm that the workspace tasks are available from Terminal → Run Task.

Next, continue to Zowe Profile Setup to configure connectivity to your z/OS system.

4. Zowe Profile Setup

A Zowe profile stores the connection details that IDE extensions (such as Zowe Explorer and IBM Z Open Debug) and the Zowe CLI use to communicate with your z/OS system. Configure it once. The IDE and the Zowe CLI deployment tooling share the same profile.

4.1 Profile Structure

The BankOfZDemo team profile has one parent configuration. It holds the shared host and credentials, and it has a nested profile for each service type. The defaults section maps each profile type to its nested profile.

graph TD Root[zowe.config.json] --> BOZ[BankOfZDemo
host, rejectUnauthorized, secure: user/password] BOZ --> RSE[rseapi

port 10443] BOZ --> SSH[ssh
port 22] BOZ --> TSO[tso
account, codePage 1047, logonProcedure] BOZ --> DBG[zOpenDebug
dpsPort 8192, rdsPort 8194] Root --> DEF[defaults] DEF -.-> RSE DEF -.-> ZOSMF DEF -.-> SSH DEF -.-> TSO DEF -.-> DBG

4.2 Create the Profile

Create ~/.zowe/zowe.config.json with the following content. Update these fields for your environment:

  • host: the host name or IP address of your z/OS system.
  • account: your TSO account number.
  • logonProcedure: your TSO logon procedure.
  • Ports: update these values if your environment uses non-default ports.
JSON 
{
  "$schema": "./zowe.schema.json",
  "profiles": {
    "BankOfZDemo": {
      "properties": {
        "host": "<your host>",
        "rejectUnauthorized": false
      },
      "secure": ["user", "password"],
      "profiles": {
        "rseapi": {
          "type": "rse",
          "properties": {
            "port": 8195,
            "basePath": "rseapi",
            "protocol": "https"
          }
        },
        "zosmf": {
          "type": "zosmf",
          "properties": {
            "port": 10443
          }
        },
        "ssh": {
          "type": "ssh",
          "properties": {
            "port": 22
          }
        },
        "tso": {
          "type": "tso",
          "properties": {
            "account": "<account>",
            "codePage": "1047",
            "logonProcedure": "<logon procedure>"
          }
        },
        "zOpenDebug": {
          "type": "zOpenDebug",
          "properties": {
            "dpsPort": 8192,
            "rdsPort": 8194,
            "dpsContextRoot": "api/v1",
            "dpsSecured": true,
            "authenticationType": "basic",
            "uuid": "4267a0f6-b756-4f3c-b900-0b959b4567c3"
          }
        }
      }
    }
  },
  "defaults": {
    "zosmf": "BankOfZDemo.zosmf",
    "tso": "BankOfZDemo.tso",
    "ssh": "BankOfZDemo.ssh",
    "rse": "BankOfZDemo.rseapi",
    "zOpenDebug": "BankOfZDemo.zOpenDebug"
  },
  "autoStore": true
}

4.3 Profile Reference

Nested profile Type Key properties
rseapi rse port 8195, basePath rseapi, protocol https
zosmf zosmf port 10443
ssh ssh port 22
tso tso account, codePage 1047, logonProcedure
zOpenDebug zOpenDebug dpsPort 8192, rdsPort 8194, dpsContextRoot api/v1, dpsSecured true, authenticationType basic, uuid

The user and password values are declared in the secure array, so Zowe stores them in the secure credential store instead of the plain-text file. With autoStore set to true, Zowe saves prompted values back to the configuration.

For more information about profile types and configuration options, see the IBM Z Open Editor documentation.

4.4 Verify Connectivity

To verify the profile, connect to your z/OS system from the Zowe Explorer view in your IDE. If the Zowe CLI is installed, you can also run:

BASH 
zowe zosmf check status
zowe rse check status

If the connection fails, check the following:

  • The host, ports, and credentials are correct.
  • The corresponding services are running on z/OS.

5. Zowe CLI Setup

The Bank of Z deployment scripts use Zowe CLI to communicate with z/OS USS. It creates workspace directories, clones the repository on USS, and runs remote setup commands. It is required for the Zowe CLI deployment workflow.

5.1 Prerequisites

  • A configured Zowe profile (see section 4).
  • Node.js >=22.22.1 <23. Verify the version with node -v.
  • npm >=10.9.4 <10.10.0. Verify the version with npm -v.

5.2 Install Zowe CLI

BASH 
npm install -g @zowe/cli@zowe-v3-lts

Verify the installation:

BASH 
zowe --version

5.3 Install the IBM RSE API Plug-in

setup-local.sh needs the IBM RSE API plug-in to run USS commands and manage files on the target z/OS system.

BASH 
zowe plugins install @ibm/rse-api-for-zowe-cli

Verify that the plug-in is installed:

BASH 
zowe plugins list

5.4 Verify the Installation

Verify that Zowe CLI can connect to your z/OS system with your configured profile:

BASH 
zowe zosmf check status
zowe rse check status

6. GRUB Setup

GRUB (Git Remote User Build) syncs local file changes directly to z/OS USS without requiring a Git commit. It then runs a configured post-sync script on USS. Bank of Z uses this to run the setup and deployment scripts automatically after each sync. It is required for the GRUB deployment workflow.

6.1 Install GRUB

Follow the GRUB installation instructions for your environment. GRUB is available from the IBM Z development tooling portfolio.

6.2 Configure GRUB for Bank of Z

After you install GRUB, configure it with these settings:

Setting Description
Remote host Host name or IP address of your z/OS USS system
Remote user Your USS user ID
Remote path The path where the Bank of Z repository is synchronized on z/OS USS. It should match sandbox.path in .setup/config/config.yaml with /Bank-of-Z appended, for example /usr/local/sandboxes/bank-of-z/Bank-of-Z
Post-sync command The command GRUB runs on USS after each synchronization

Post-sync command:

CODE 
bash <remote-path>/.setup/setup-remote.sh

Refer to the GRUB documentation for the configuration procedure for your version.

6.3 How GRUB Works with Bank of Z

When you trigger a GRUB sync:

  1. GRUB computes a patch that contains the local changes since the previous sync. No commit is required.
  2. The patch is applied to the Bank of Z directory on z/OS USS.
  3. The post-sync hook runs setup-remote.sh on z/OS USS.
  4. setup-remote.sh detects that it is running inside the Bank-of-Z repository and automatically runs all three setup stages.
sequenceDiagram participant Dev as Developer participant GRUB as GRUB (local) participant USS as z/OS USS Bank-of-Z directory participant Hook as setup-remote.sh Dev->>GRUB: Trigger sync GRUB->>GRUB: Compute patch of local changes (no commit) GRUB->>USS: Apply patch GRUB->>Hook: Run post-sync command Hook->>Hook: Detect Bank-of-Z repository Hook->>USS: Run all three setup stages Hook-->>GRUB: Complete GRUB-->>Dev: Sync finished

After the initial deployment, later syncs are typically fast because only changed files are transferred.

7. Direct USS Workflow

The Direct USS workflow needs no additional local deployment tooling. Connect directly to z/OS USS over SSH and run the setup scripts manually. You still need the IDE. You need the Zowe profile only if you use the IDE extensions that rely on it.
