Local Tools Setup

This page describes how to install and configure all local development tools required for Bank of Z development. It covers IDE setup, Zowe profile configuration, Zowe CLI installation, and GRUB deployment tooling. Before proceeding, ensure you have cloned the Bank of Z repository to your local machine — Git is required for all workflows.

1. Overview

The Bank of Z local tooling stack enables developers to write, edit, deploy, and debug mainframe applications from their own workstations. The setup is organized into three logical layers:

  1. IDE — Browse, edit, and manage source code using IBM Bob Premium Package for Z or Visual Studio Code with IBM Z extensions.
  2. Zowe Profile — Establish secure connectivity between your local tools and your z/OS system.
  3. Deployment Tooling — Push local changes to z/OS using one of three supported workflows: Zowe CLI, GRUB, or Direct USS (SSH).

Each layer is independent; however, the recommended order is: IDE → Zowe Profile → Deployment Tooling.

2. System Architecture

The diagram below illustrates how the local development environment connects to the z/OS system and which tooling components participate in each path.

The Zowe profile is the central configuration artifact. Both the IDE extensions (Zowe Explorer, debugger) and the Zowe CLI deployment tooling read from ~/.zowe/zowe.config.json to resolve host, port, and credential information. GRUB operates independently, maintaining its own remote host configuration but deploying to the same USS path.

3. IDE Setup

An IDE is required to browse, edit, and manage Bank of Z source code. For the best experience and to follow the tutorials in the documentation, use IBM Bob Premium Package for Z. Alternatively, Visual Studio Code is fully supported.

IDE setup is independent of your chosen deployment workflow. Complete this step before configuring deployment tooling.

3.1 Prerequisites

Java 21 is required to run the IDE and its embedded tooling. Install IBM Semeru Runtime for Java 21 or later, then verify the installation:

BASH 
java -version

Expected output should indicate version 21.x.x or later.

3.2 Required Extensions

Install the following extensions in your IDE. If you are using IBM Bob Premium Package for Z and an extension is unavailable in the Open VSX Marketplace, download the VSIX package and install it manually.

Note: For IBM MQ there is no IBM extension in the VS Code Marketplace. See the IBM MQ Console extension available from the ibm-messaging GitHub group.

3.3 Install Extensions from a Marketplace

  1. Open the Extensions view in your IDE.
  2. Search for the extension by name.
  3. Select Install.

3.4 Install VSIX Packages Manually

  1. Download the VSIX file using the link in the table above.
  2. Open the Extensions view.
  3. Select More Actions (…) → Install from VSIX…
  4. Browse to the downloaded file and complete the installation.

3.5 Automated VSIX Download and Install

Bank of Z includes scripts to download and install all required VSIX packages in a single step.

Download all packages:

BASH 
node scripts/download-vsix.js [output-directory]

The default output directory is ./vsix-extensions.

Install into IBM Bob Premium Package for Z:

BASH 
# First add bobide to PATH:
# View > Command Palette > Shell Command: Install 'bobide' command in PATH

node scripts/install-bobide-vsix.js [output-directory]

Install into VS Code:

BASH 
# First add code to PATH:
# View > Command Palette > Shell Command: Install 'code' command in PATH

node scripts/install-vscode-vsix.js [output-directory]

For more information, see scripts/README.md.

3.6 Verify the IDE Configuration

After completing the installation:

  1. Launch the IDE.
  2. Confirm all required extensions are installed and enabled.
  3. Open the Bank of Z repository and confirm that the workspace tasks are available from Terminal → Run Task.

4. Zowe Profile Setup

A Zowe profile is required to connect your IDE extensions (Zowe Explorer, debugger) and the Zowe CLI deployment tooling to your z/OS system. This configuration must be completed before using either the IDE connectivity features or the Zowe CLI deployment workflow.

The Zowe profile is stored at ~/.zowe/zowe.config.json and acts as the single source of truth for host, port, and credential configuration across all Zowe-aware tools.

sequenceDiagram participant Dev as Developer participant CLI as Zowe CLI participant CFG as ~/.zowe/zowe.config.json participant zOS as z/OS System Dev->>CLI: zowe config init CLI->>CFG: Create/update profile Dev->>CFG: Set host, port, credentials Dev->>CLI: zowe zosmf check status CLI->>CFG: Read connection settings CLI->>zOS: Test z/OSMF connection zOS-->>CLI: Connection response CLI-->>Dev: Profile verified ✓

This diagram shows the flow for initializing and verifying the Zowe profile. Once the profile is verified, all Zowe-aware tools — including Zowe Explorer in the IDE and the Zowe CLI — will use these settings automatically.

5. Zowe CLI Setup

The Zowe CLI, combined with the IBM RSE API plug-in, provides a scriptable command-line interface for deploying Bank of Z changes to z/OS. This is required if you are using the Zowe CLI deployment workflow.

5.1 Install Zowe CLI

Install Zowe CLI globally using npm:

BASH 
npm install -g @zowe/cli

Verify the installation:

BASH 
zowe --version

5.2 Install the IBM RSE API Plug-in

The IBM RSE API plug-in extends Zowe CLI with capabilities needed to interact with z/OS USS and datasets through the RSE API:

BASH 
zowe plugins install @ibm/rse-api-for-zowe-cli

Verify the plug-in installation:

BASH 
zowe plugins list

5.3 Verify Zowe CLI Connectivity

Once both the CLI and the plug-in are installed, and your Zowe profile is configured (see Section 4), verify end-to-end connectivity:

BASH 
zowe zosmf check status

A successful response confirms that your workstation can reach the z/OS system using the configured profile.

6. GRUB Setup

GRUB (Git Remote User Build) syncs local file changes directly to z/OS USS without requiring a Git commit, then automatically runs a configured post-sync script on USS. Bank of Z uses this capability to run setup and deployment scripts automatically after each sync.

This is required for the GRUB deployment workflow.

6.1 Install GRUB

Follow the GRUB installation instructions for your environment. GRUB is available from the IBM Z development tooling portfolio.

6.2 Configure GRUB for Bank of Z

After installing GRUB, configure it with the following settings:

Setting Description Example Value
Remote host Host name or IP address of your z/OS USS system myzos.example.com
Remote user Your USS user ID IBMUSER
Remote path USS path where the Bank of Z repository is synchronized. Must match sandbox.path in .setup/config/config.yaml with /Bank-of-Z appended. /usr/local/sandboxes/bank-of-z/Bank-of-Z
Post-sync command Command GRUB runs on z/OS USS after each synchronization bash <remote-path>/.setup/setup-remote.sh

Example post-sync command:

BASH 
bash /usr/local/sandboxes/bank-of-z/Bank-of-Z/.setup/setup-remote.sh

Refer to the GRUB documentation for the configuration procedure specific to your version.

6.3 How GRUB Works with Bank of Z

The following diagram illustrates the GRUB sync and deployment process:

sequenceDiagram participant Dev as Developer participant GRUB as GRUB (Local) participant USS as z/OS USS participant Script as setup-remote.sh Dev->>GRUB: Trigger sync GRUB->>GRUB: Compute patch\n(changed files only) GRUB->>USS: Apply patch to Bank-of-Z directory USS-->>GRUB: Patch applied GRUB->>USS: Execute post-sync hook USS->>Script: bash setup-remote.sh Script->>Script: Detect Bank-of-Z repo context Script->>USS: Run all three setup stages USS-->>Script: Setup complete Script-->>GRUB: Exit 0 GRUB-->>Dev: Sync complete ✓

The GRUB workflow operates as follows:

  1. Patch computation — GRUB computes a patch containing only the local changes since the previous sync. No Git commit is required.
  2. Remote patch application — The patch is applied to the Bank of Z directory on z/OS USS.
  3. Post-sync hook execution — GRUB runs setup-remote.sh on z/OS USS automatically.
  4. Automated setup — setup-remote.sh detects that it is running inside the Bank-of-Z repository and automatically runs all three setup stages.

After the initial deployment, subsequent syncs are typically fast because only changed files are transferred.

7. Deployment Workflow Comparison

The table below summarizes the three supported deployment workflows and their tooling requirements:

Workflow Local Tools Required Requires Git Commit Notes
Zowe CLI Zowe CLI + IBM RSE API plug-in + Zowe Profile Yes Scriptable, CI/CD friendly
GRUB GRUB + Zowe Profile (for IDE) No Fast incremental syncs
Direct USS SSH client + Zowe Profile (for IDE) No Manual; no additional tooling needed

8. Next Steps

Once all required tools are installed and configured, proceed with your chosen deployment workflow:

  • Zowe CLI workflow — Use zowe commands to deploy changes from your workstation.
  • GRUB workflow — Trigger a sync from your IDE or terminal; GRUB handles the rest automatically.
  • Direct USS workflow — SSH into z/OS USS and run the setup scripts manually.
