Installation & Setup

1. Overview

Bank of Z is a self-contained sample hybrid banking application that demonstrates modern IBM Z development, deployment, and DevSecOps practices. The repository includes application source code, infrastructure configuration, automation scripts, build tooling, deployment assets, and supporting documentation required to install and configure the complete environment.

The application integrates core IBM Z technologies — CICS, IMS Transaction Manager (IMS TM), IMS DB, Db2 for z/OS, z/OS Connect, and IBM MQ — providing a realistic environment for learning, testing, and workflow validation.

The installation process is fully automated once the repository is cloned and the environment is configured. All three supported deployment paths (Direct USS, Zowe CLI, and GRUB) run the same underlying deployment stages and produce an identical deployed environment.

2. System Architecture

Bank of Z is a multi-tier hybrid application that runs on z/OS. The diagram below illustrates the major components and how they relate to one another at runtime.

graph TD subgraph Local["Local Developer Machine"] IDE["IDE\n(IBM Bob Premium / VS Code)"] ZoweCLI["Zowe CLI\n(RSE API Plug-in)"] GRUB["GRUB\n(Git Remote User Build)"] end subgraph zOS["z/OS USS"] USS["USS Workspace\n(.setup / Bank-of-Z)"] DBB["IBM DBB\nBuild Engine"] WaziDeploy["Wazi Deploy\nDeployment Engine"] end subgraph Middleware["z/OS Middleware"] CICS["CICS Region"] IMS["IMS Region\n(TM + DB)"] Db2["Db2 for z/OS"] MQ["IBM MQ"] zOSConnect["z/OS Connect\nAPI Server"] Liberty["Liberty Frontend\nServer"] end Browser["Browser / API Client"] IDE -->|"SSH (Direct USS)"| USS ZoweCLI -->|"RSE API"| USS GRUB -->|"File Sync + Post-Sync Hook"| USS USS --> DBB DBB --> WaziDeploy WaziDeploy --> CICS WaziDeploy --> IMS Browser --> Liberty Liberty --> zOSConnect zOSConnect --> CICS zOSConnect --> IMS CICS --> Db2 CICS --> MQ IMS --> Db2

The frontend Liberty server receives browser requests and routes them through z/OS Connect to the CICS and IMS regions. CICS and IMS interact with Db2 for persistent data and IBM MQ for messaging. DBB compiles all application sources (COBOL, PL/I, Assembler, BMS, Java, and z/OS Connect APIs), and Wazi Deploy packages and deploys the build outputs to the runtime environment.

3. Installation Workflow

The Bank of Z installation consists of six sequential stages regardless of which deployment path you choose.

graph TD A["1. Verify Prerequisites"] --> B["2. Configure Target Environment"] B --> C["3. Install & Configure Local Tools"] C --> D["4. Build the Application"] D --> E["5. Deploy Resources & Services"] E --> F["6. Verify the Installation"]

Each stage is described in detail in the sections that follow. Stages 4, 5, and 6 are automated by the setup-common.sh script and its subcommands.

4. Local Tools Setup

Before deploying, configure the local tooling on your developer workstation. The tools you need depend on your chosen deployment workflow.

4.1 Prerequisites

  • Git — Required for all workflows to clone the repository.
  • Java 21 — Required to run the IDE and its embedded tooling. Install IBM Semeru Runtime 21 or later and verify:
BASH 
java -version
  • Node.js ≥ 22.22.1 < 23 and npm ≥ 10.9.4 < 10.10.0 — Required for the Zowe CLI workflow.
BASH 
node -v
npm -v

4.2 IDE Setup

An IDE is required to browse, edit, and manage Bank of Z source code. IDE setup is independent of your chosen deployment workflow.

Supported IDEs:

  • IBM Bob Premium Package for Z (recommended)
  • Visual Studio Code

4.2.1 Required Extensions

Install the following extensions. If you are using IBM Bob Premium Package for Z and an extension is unavailable in the Open VSX Marketplace, download the VSIX package and install it manually.

Extension Description
IBM® Developer for z/OS® Enterprise Edition (IDzEE) Extension Pack Core IBM Z extensions: Z Open Editor, Z Open Debug, Compiled Code Coverage, Zowe Explorer, Zowe Explorer for IBM CICS
IBM CICS Interdependency Analyzer Extension for Zowe Explorer CICS application and resource analysis
IBM IMS Explorer for VS Code IMS application development support
IBM Db2 for z/OS Developer Extension Db2 development and SQL tooling
IBM z/OS Connect development tools API development and management for z/OS Connect
IBM TAZ Early Development Testing Test automation and early development testing

Note: For IBM MQ there is no IBM extension in the VS Code Marketplace. See the IBM MQ Console extension available from the ibm-messaging GitHub group.

4.2.2 Install from Marketplace

  1. Open the Extensions view in your IDE.
  2. Search for the extension by name.
  3. Select Install.

4.2.3 Install VSIX Packages Manually

  1. Download the VSIX file.
  2. Open the Extensions view.
  3. Select More Actions (…) → Install from VSIX…
  4. Browse to the downloaded file and complete the installation.

4.2.4 Automated VSIX Download and Install

Bank of Z includes scripts to download and install all required VSIX packages in a single step.

Download all packages:

BASH 
node scripts/download-vsix.js [output-directory]

The default output directory is ./vsix-extensions.

Install into IBM Bob Premium Package for Z:

BASH 
# First add bobide to PATH:
# View > Command Palette > Shell Command: Install 'bobide' command in PATH

node scripts/install-bobide-vsix.js [output-directory]

Install into VS Code:

BASH 
# First add code to PATH:
# View > Command Palette > Shell Command: Install 'code' command in PATH

node scripts/install-vscode-vsix.js [output-directory]

4.3 Zowe Profile Setup

A Zowe profile stores the connection details used by IDE extensions (Zowe Explorer, IBM Z Open Debug) and Zowe CLI to communicate with your z/OS system. Configure this once — both your IDE and the Zowe CLI deployment tooling share the same profile.

Create ~/.zowe/zowe.config.json with the following content, updating the fields marked for your environment:

JSON 
{
  "$schema": "./zowe.schema.json",
  "profiles": {
    "BankOfZDemo": {
      "properties": {
        "host": "<your host>",
        "rejectUnauthorized": false
      },
      "secure": ["user", "password"],
      "profiles": {
        "rseapi": {
          "type": "rse",
          "properties": {
            "port": 8195,
            "basePath": "rseapi",
            "protocol": "https"
          }
        },
        "zosmf": {
          "type": "zosmf",
          "properties": {
            "port": 10443
          }
        },
        "ssh": {
          "type": "ssh",
          "properties": {
            "port": 22
          }
        },
        "tso": {
          "type": "tso",
          "properties": {
            "account": "<account>",
            "codePage": "1047",
            "logonProcedure": "<logon procedure>"
          }
        },
        "zOpenDebug": {
          "type": "zOpenDebug",
          "properties": {
            "dpsPort": 8192,
            "rdsPort": 8194,
            "dpsContextRoot": "api/v1",
            "dpsSecured": true,
            "authenticationType": "basic",
            "uuid": "4267a0f6-b756-4f3c-b900-0b959b4567c3"
          }
        }
      }
    }
  },
  "defaults": {
    "zosmf": "BankOfZDemo.zosmf",
    "tso": "BankOfZDemo.tso",
    "ssh": "BankOfZDemo.ssh",
    "rse": "BankOfZDemo.rseapi",
    "zOpenDebug": "BankOfZDemo.zOpenDebug"
  },
  "autoStore": true
}

Key fields to update:

  • host — Host name or IP address of your z/OS system.
  • account — Your TSO account number.
  • logonProcedure — Your TSO logon procedure.
  • Ports — Update if your environment uses non-default ports.

Verify connectivity:

BASH 
zowe zosmf check status
zowe rse check status

4.4 Zowe CLI Setup

Zowe CLI is required for the Zowe CLI deployment workflow. It creates workspace directories, clones the repository on USS, and executes remote setup commands.

Install Zowe CLI:

BASH 
npm install -g @zowe/cli@zowe-v3-lts

Verify:

BASH 
zowe --version

Install the IBM RSE API plug-in:

BASH 
zowe plugins install @ibm/rse-api-for-zowe-cli

Verify the plug-in:

BASH 
zowe plugins list

Verify end-to-end connectivity:

BASH 
zowe zosmf check status
zowe rse check status

4.5 GRUB Setup

GRUB (Git Remote User Build) syncs local file changes directly to z/OS USS without requiring a Git commit, then runs a configured post-sync script on USS. This is required for the GRUB deployment workflow.

After installing GRUB from the IBM Z development tooling portfolio, configure it with the following settings:

Setting Value
Remote host Host name or IP address of your z/OS USS system
Remote user Your USS user ID
Remote path Path matching sandbox.path in config.yaml with /Bank-of-Z appended, e.g. /usr/local/sandboxes/bank-of-z/Bank-of-Z
Post-sync command bash <remote-path>/.setup/setup-remote.sh

5. Deployment Paths

All three deployment workflows run the same three stages and produce an identical environment. Choose the path that best fits your tooling and access model.

graph TD Start["Clone Repository\n& Edit config.yaml"] --> Choice{Choose Deployment Path} Choice -->|"Direct USS"| D1["SSH to z/OS USS"] Choice -->|"Zowe CLI"| D2["Push Branch to Remote\nRun setup-local.sh"] Choice -->|"GRUB"| D3["Trigger GRUB Sync\n(No commit required)"] D1 --> Stage1 D2 --> Stage1 D3 --> Stage1 subgraph Stages["Automated Deployment Stages (z/OS USS)"] Stage1["Stage 1: validate-prereqs\nVerify tool versions & connectivity"] Stage1 --> Stage2["Stage 2: environment\nProvision CICS, IMS, Db2, z/OS Connect, Liberty"] Stage2 --> Stage3["Stage 3: install-bank-of-z\nDBB Build → Wazi Deploy → Populate test data"] end Stage3 --> Verify["Verify Deployment\nOpen frontend in browser"]

The following subsections provide step-by-step instructions for each path.

5.1 Deploy Using Direct USS Access

This is the most transparent option. You run each command manually over SSH and can observe every stage of the deployment.

Prerequisites: SSH access to z/OS, Git installed on USS, environment meeting all prerequisites.

5.1.1 SSH to z/OS

BASH 
ssh user@your-zos-host

5.1.2 Clone the Repository

BASH 
export BANK_OF_Z_WORK_DIR=/usr/local/sandboxes/bank-of-z
mkdir -p $BANK_OF_Z_WORK_DIR
cd $BANK_OF_Z_WORK_DIR
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

5.1.3 Edit the Configuration File

BASH 
vi .setup/config/config.yaml

5.1.4 Validate Prerequisites

BASH 
.setup/setup-common.sh validate-prereqs

Verifies that all required tools (DBB, ZOAU, zconfig, Wazi Deploy, Java, Git) are installed at the required versions. Resolve any failures before continuing.

5.1.5 Provision Middleware

BASH 
.setup/setup-common.sh environment

Provisions the complete application runtime, including Db2 tables, a CICS region, an IMS region and database, a z/OS Connect server, and the Liberty frontend server. Expect this to take several minutes.

Note: This stage requires a pre-existing Db2 subsystem (DBD1). All other middleware is provisioned automatically.

5.1.6 Build and Deploy

BASH 
.setup/setup-common.sh install-bank-of-z

Runs a complete DBB build, packages the outputs, deploys via Wazi Deploy, and populates Db2 and IMS with test data. The initial build and deployment typically takes 15 to 20 minutes.

Note: Warnings related to the YAML scanner and chown failures are expected and do not indicate a problem.

5.1.7 Verify the Deployment

Open the Bank of Z frontend in a browser:

CODE 
http://<your-zos-host>:9081/admin.html
https://<your-zos-host>:9445/admin.html

5.1.8 Run Post-Install Verification Tests

BASH 
.setup/setup-common.sh verify-installation

Runs the integration test suite in tests/ against the deployed application. Tests exercise the CICS and IMS API paths and report a pass/fail result for each. All tests must pass before the installation is considered complete.

5.2 Deploy Using Zowe CLI

This workflow clones your current branch from GitHub onto z/OS USS and runs all three setup stages automatically. SSH access to USS is not required.

Prerequisites: Zowe CLI installed, RSE API plug-in installed, Zowe profile configured (see sections 4.3 and 4.4).

Note: The script clones your branch from GitHub on USS. Your branch must be pushed to the remote before running the script. Local commits that have not been pushed will not be included.

5.2.1 Clone the Repository Locally

BASH 
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

5.2.2 Edit the Configuration File

Open .setup/config/config.yaml in your local editor and update it for your environment.

5.2.3 Push Your Branch

BASH 
git add .setup/config/config.yaml
git commit -m "Configure for my environment"
git push

5.2.4 Run the Setup Script

BASH 
bash .setup/setup-local.sh

Alternatively, in Visual Studio Code, select Command Palette → Tasks: Run Task → Setup Bank of Z Environment.

5.2.5 What Runs Automatically

The following sequence illustrates what the script does end-to-end:

sequenceDiagram participant Local as Local Machine participant ZoweCLI as Zowe CLI participant USS as z/OS USS participant GitHub as GitHub Local->>ZoweCLI: bash .setup/setup-local.sh ZoweCLI->>USS: Create USS workspace directory (RSE API) ZoweCLI->>USS: Invoke setup-remote.sh USS->>GitHub: git clone GitHub-->>USS: Repository cloned USS->>USS: validate-prereqs USS->>USS: environment (CICS, IMS, Db2, z/OS Connect, Liberty) USS->>USS: install-bank-of-z (DBB build + Wazi Deploy + test data) USS-->>Local: Logs written to /tmp/remote-setup.log

Logs are written to /tmp/remote-setup.log on your local machine. The initial deployment typically takes 15 to 20 minutes.

5.2.6 Verify the Deployment

CODE 
http://<your-zos-host>:9080/bank-frontend-vanilla

5.3 Deploy Using GRUB

GRUB syncs your local file changes directly to z/OS USS and triggers the setup scripts automatically. No commit or push to a remote is required before deploying.

Prerequisites: GRUB installed and configured with the Bank of Z remote path and post-sync hook (see section 4.5).

5.3.1 Clone the Repository Locally

BASH 
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

5.3.2 Edit the Configuration File

Open .setup/config/config.yaml in your local editor and update it for your environment. You do not need to commit your changes — GRUB syncs the file as-is.

5.3.3 Trigger a GRUB Sync

Trigger a GRUB sync from your local machine using the command or UI action for your GRUB installation. GRUB transfers only the files that have changed since the previous sync.

5.3.4 What Runs Automatically

sequenceDiagram participant Local as Local Machine participant GRUB as GRUB Agent participant USS as z/OS USS Local->>GRUB: Trigger sync GRUB->>GRUB: Compute patch (changed files only) GRUB->>USS: Apply patch to Bank-of-Z directory USS->>USS: Post-sync hook: bash setup-remote.sh USS->>USS: validate-prereqs USS->>USS: environment (CICS, IMS, Db2, z/OS Connect, Liberty) USS->>USS: install-bank-of-z (DBB build + Wazi Deploy + test data) USS-->>Local: Deployment complete

After the initial deployment, subsequent syncs are typically faster because only changed files are transferred.

5.3.5 Verify the Deployment

CODE 
http://<your-zos-host>:9080/bank-frontend-vanilla

6. Deployment Stages Reference

All three workflows run the same three stages as subcommands of setup-common.sh. This section provides a consolidated reference.

6.1 Stage 1 — Validate Prerequisites

BASH 
.setup/setup-common.sh validate-prereqs

Verifies that all required tools are installed on z/OS USS at the versions specified in config.yaml. This includes DBB, ZOAU, zconfig, Wazi Deploy, Java, Git, and network connectivity to GitHub. Resolve all failures before proceeding to Stage 2.

6.2 Stage 2 — Provision Middleware

BASH 
.setup/setup-common.sh environment

Provisions the complete application runtime from scratch. The following steps run in sequence:

  1. Stops any existing Bank of Z tasks (CICS, IMS, z/OS Connect, frontend)
  2. Cleans up existing application datasets
  3. Clones the IBM DBB accelerators repository from GitHub
  4. Copies the zBuilder build framework
  5. Creates Db2 database tables
  6. Provisions a CICS region using zconfig
  7. Provisions an IMS region using zconfig
  8. Creates IMS database objects
  9. Starts IMS Bank of Z message processing regions
  10. Creates and starts a z/OS Connect server
  11. Creates and starts a frontend Liberty server

6.3 Stage 3 — Build and Deploy

BASH 
.setup/setup-common.sh install-bank-of-z

Builds the application from source and deploys the generated artifacts to the provisioned runtime:

  1. Runs a full DBB build for all application sources (COBOL, PL/I, Assembler, BMS, Java, z/OS Connect APIs)
  2. Packages the build outputs into a deployment archive
  3. Runs Wazi Deploy to deploy the archive to the CICS and IMS environments
  4. Populates Db2 with application test data
  5. Populates the IMS database with application test data

The initial build and deployment typically takes 15 to 20 minutes.

7. Incremental Builds

After the initial deployment is complete, most day-to-day development can be performed using an incremental build and deploy rather than rebuilding the entire environment.

The incremental workflow rebuilds and deploys only the application components affected by your source code changes, reducing build time while preserving the existing runtime environment. This is supported by both the Zowe CLI and GRUB workflows.

graph LR A["Edit Source Files"] --> B["Zowe CLI or GRUB Sync"] B --> C["Incremental DBB Build\n(Changed files only)"] C --> D["Wazi Deploy\n(Affected artifacts only)"] D --> E["Updated Runtime\n(CICS / IMS)"]
