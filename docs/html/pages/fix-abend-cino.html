Fix: OMEN ABEND CINO

Brief overview: This document provides a targeted fix guide for resolving the OMEN ABEND CINO error (Abend 4038 / IOERR) observed in the Bank of Z CICS environment. It covers the root cause, evidence from system logs, corrective actions, verification steps, and preventive recommendations for CICS administrators and application support teams.

1. Overview

The CICS transaction OMEN, executed by user RAFAELT on region CICSAOR1, abended with code 4038 (IOERR) on October 24, 2026. The abend was triggered because the Transient Data Queue (TDQUEUE) named CINO was in a closed state. When the program BNKMENU attempted to open the queue via a SET TDQUEUE command, CICS returned RESP(IOERR) RESP2(14) — indicating that the underlying VSAM dataset associated with CINO was not found in the catalog.

The fix requires a CICS administrator with appropriate RACF authority to reopen the TDQUEUE and verify that the transaction executes cleanly afterward.

The critical failure point is the VSAM dataset backing TDQUEUE CINO. Because it was not found in the MVS catalog, CICS was unable to open the queue, causing BNKMENU to abend with code 4038.

3. Root Cause Analysis

3.1 Failure Sequence

The TDQUEUE CINO — an Extrapartition Transient Data Queue (output queue) in the CICSAOR1 region — was in a CLOSED state at the time of the transaction. The program BNKMENU attempted to programmatically open it using:

COBOL 
EXEC CICS SET TDQUEUE('CINO') OPENSTATUS(OPEN)

CICS responded with:

CODE 
RESP(IOERR)  RESP2(14)
Response Code Meaning
RESP(IOERR) I/O error — general input/output failure
RESP2(14) SYSIDERR — the VSAM dataset associated with the TDQUEUE was not found in the system catalog

This SYSIDERR condition means the MVS catalog had no entry for the VSAM dataset that CINO depends on, making it impossible for CICS to open the queue. The resulting state caused BNKMENU to abend with code 4038, which was captured by CICS message DFHAC2236.

3.2 Probable Triggers

The following conditions may have caused the VSAM dataset to become unavailable:

  • Dataset deletion or uncataloging — the VSAM dataset was removed or uncataloged inadvertently.
  • Intentional closure — someone issued CEMT S TDQUEUE(CINO) CLOSE without a corresponding open.
  • z/OS Debugger instability — with DEBUGTOOL=NO in the region SIT, abruptly terminated debug sessions may leave enclaves in an inconsistent state (CEE2529S), triggering cascading failures.
  • CICS warm/cold start — the queue was not recovered correctly after a region restart.

4. Evidence from System Logs

4.1 Log Entries (MSGUSR — DD 106)

The following messages were captured in the CICS system log, confirming the abend sequence:

CODE 
DFHAP1900 10/24/2026 17:14:56 CICSAOR1 MVS10189 RAFAELT OMEN
          SET TDQUEUE(CINO) OPENSTATUS(OPEN) RESP(IOERR) RESP2(14).

DFHAC2236 10/24/2026 17:14:56 CICSAOR1
          Transaction OMEN transaction number 69904 abend 4038
          in program BNKMENU term 0189.
  • DFHAP1900 — CICS Application Program error message. Confirms the failing SET TDQUEUE command and the RESP(IOERR) RESP2(14) return.
  • DFHAC2236 — CICS Abend notification. Records the transaction, program, terminal, and abend code (4038).

4.2 Terminal and Session State

Additional messages confirmed the state of user sessions at the time of the incident:

  • DFHZC3462 and DFHZC6966 — Terminals 0189 and 0190 of user RAFAELT were terminated by the system as a result of the abend.
  • The file EQADPFMB contained only 1 active profile (JCMARCA) — no pending debug profiles for RAFAELT remained.

5. Corrective Actions

5.1 RACF Authority Constraint

User RAFAELT does not have RACF UPDATE authority on the required resource and therefore cannot perform the corrective action directly:

CODE 
MVS.MODIFY.STC.CICSAOR1.CICSAOR1  CL(OPERCMDS)
ACCESS INTENT(UPDATE)   ACCESS ALLOWED(READ)

⚠️ The steps below must be performed by a CICS Administrator with UPDATE access on the OPERCMDS RACF class.

5.2 Fix Sequence

The diagram below shows the recommended sequence of steps for the CICS administrator to resolve the abend and verify the fix.

sequenceDiagram participant Admin as CICS Administrator participant MVS as MVS Console / CEMT participant CICS as CICSAOR1 Region participant User as User RAFAELT Admin->>MVS: F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN MVS->>CICS: Open TDQUEUE CINO CICS-->>MVS: TDQUEUE CINO STATUS(OPEN) Admin->>MVS: F CICSAOR1,CEMT I TDQUEUE(CINO) MVS-->>Admin: STATUS( OPEN ) confirmed Admin->>User: Notify RAFAELT — retry transaction OMEN User->>CICS: Execute Transaction OMEN CICS-->>User: Transaction completes successfully Admin->>MVS: Confirm no DFHAC2236 abend 4038 in MSGUSR

5.3 Option A — MVS Console Command

If the administrator has direct console access, the quickest fix is to issue the following MVS Modify command:

CODE 
F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN

This instructs the CICSAOR1 region to set the status of TDQUEUE CINO to OPEN.

5.4 Option B — JCL Batch Job

If console access is not available, the administrator can submit the following JCL job using an ID with UPDATE authority on OPERCMDS:

JCL 
//FIXCINO  JOB (ACCT),'FIX CINO TDQUEUE',CLASS=A,MSGCLASS=H,
//         MSGLEVEL=(1,1),NOTIFY=&SYSUID
//*---------------------------------------------------------*
//* CORRECTION: OPEN TDQUEUE CINO IN REGION CICSAOR1        *
//* ABEND 4038 TRANSACTION OMEN / PROGRAM BNKMENU           *
//*---------------------------------------------------------*
//STEP1    EXEC PGM=IKJEFT01,REGION=0M
//SYSTSPRT DD SYSOUT=*
//SYSTSIN  DD *
  CONSOLE
  F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN
  F CICSAOR1,CEMT I TDQUEUE(CINO)
  END
/*

This job uses IKJEFT01 (TSO/E terminal monitor program) to issue console commands in batch. The CEMT I TDQUEUE(CINO) command at the end confirms the queue state after the open attempt.

6. Verification

6.1 Confirm TDQUEUE Status

After executing either Option A or Option B above, verify that the TDQUEUE is open:

CODE 
F CICSAOR1,CEMT I TDQUEUE(CINO)

Expected output:

CODE 
STATUS(  OPEN ) ...

6.2 Re-execute Transaction OMEN

Ask user RAFAELT to re-execute transaction OMEN from either terminal. Confirm that:

  • The transaction completes without abend.
  • No new DFHAC2236 message with abend code 4038 appears in the MSGUSR log (DD 106).

6.3 Verification Checklist

Step Action Expected Result
1 CEMT I TDQUEUE(CINO) STATUS( OPEN )
2 Re-execute OMEN transaction No abend, clean completion
3 Check MSGUSR log No DFHAC2236 with abend 4038
4 Confirm terminals 0189/0190 Available for new sessions

7. Prevention

7.1 Investigate Why CINO Was Closed

Determine the root cause of the queue closure before declaring the incident resolved:

  • Check if the VSAM dataset associated with CINO was deleted, uncataloged, or renamed.
  • Review operator logs for any CEMT S TDQUEUE(CINO) CLOSE commands issued intentionally or by automation.
  • Review CICS startup JCL and CSD definitions to confirm the dataset name is correctly cataloged.

7.2 Review DEBUGTOOL Parameter

The SIT (System Initialization Table) for CICSAOR1 currently has DEBUGTOOL=NO. With this setting, z/OS Debugger sessions that terminate abruptly may leave enclaves in an inconsistent state, generating CEE2529S conditions and cascading failures. Consider:

  • Reviewing the use of the Debugger in production vs. test regions.
  • Ensuring that DEBUGTOOL is set appropriately and that debug sessions are properly closed before region restarts.

7.3 Define CINO Dataset as RECOVERABLE

To prevent the same failure from occurring after future region restarts or dataset issues, consider updating the CICS CSD (CICS System Definition) to mark the VSAM dataset of CINO as RECOVERABLE:

  • A RECOVERABLE definition instructs CICS to automatically reopen the queue after a failure and recover its state.
  • This reduces the need for manual administrator intervention for transient data queue closures.

7.4 RACF Authority Review

Ensure that authorized support personnel have the correct RACF UPDATE access on OPERCMDS resources so that time-sensitive fixes like this can be applied promptly without escalation delays:

CODE 
MVS.MODIFY.STC.CICSAOR1.CICSAOR1  CL(OPERCMDS)
ACCESS INTENT(UPDATE)
