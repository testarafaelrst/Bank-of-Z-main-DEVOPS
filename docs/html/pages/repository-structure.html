Repository Structure

1. Overview

The Bank of Z repository holds everything needed to build and deploy the application. It contains these artifact types:

  • Application source
  • Setup automation
  • Build assets
  • Deployment configuration
  • Supporting documentation

This page describes how the repository is laid out and where each type of artifact lives.

1.1 Top-Level Structure

Directory / File Description
src/ Application source code: COBOL, BMS, IMS, z/OS Connect APIs, and the web frontend
.setup/ All automation for provisioning, building, and deploying Bank of Z
.vscode/ VS Code task definitions for triggering setup and pipeline scripts
scripts/ Utility scripts for downloading and installing IDE extensions
docs/ Product documentation
zcodescan/ ZCodeScan configuration for static analysis
dbb-app.yaml DBB application descriptor
zapp.yaml z/OS application manifest

2. System Architecture

The repository separates what is built (src/) from how it is built and deployed (.setup/). Developer tooling (.vscode/, scripts/), documentation (docs/), and static analysis configuration (zcodescan/) support those two areas. The root-level descriptors (dbb-app.yaml, zapp.yaml) describe the application to DBB and to z/OS tooling.

graph TD Repo[Bank of Z Repository] Repo --> SRC[src/ - Application source] Repo --> SETUP[.setup/ - Automation] Repo --> VSC[.vscode/ - VS Code tasks] Repo --> SCR[scripts/ - IDE extension scripts] Repo --> DOCS[docs/ - Documentation] Repo --> ZCS[zcodescan/ - Static analysis config] Repo --> DBBAPP[dbb-app.yaml - DBB descriptor] Repo --> ZAPP[zapp.yaml - z/OS app manifest] VSC -->|triggers| SETUP SETUP -->|builds and deploys| SRC ZCS -->|scans| SRC DOCS -->|describes| SRC

The diagram shows the relationships between the top-level areas. The VS Code tasks trigger the setup automation. The automation builds and deploys the code in src/. ZCodeScan analyzes that same code.

3. Application Source (src/)

The src/ directory is divided by runtime path and tier: CICS, IMS, batch, API, and frontend.

Directory Description
src/base/cics/ COBOL programs, BMS maps, and copybooks for the CICS transaction path
src/base/ims/ COBOL programs and copybooks for the IMS transaction path
src/base/batch/ Batch application components
src/api/ z/OS Connect API project. Its Gradle-based build produces the API deployment artifact
src/frontend/ Browser-based frontend: HTML, CSS, JavaScript, and a Node.js dev server
graph TD SRC[src/] SRC --> BASE[base/] SRC --> API[api/ - z/OS Connect, Gradle] SRC --> FE[frontend/ - HTML, CSS, JS, Node.js] BASE --> CICS[cics/ - COBOL, BMS, copybooks] BASE --> IMS[ims/ - COBOL, copybooks] BASE --> BATCH[batch/ - Batch components]

3.1 Core Application (src/base/)

  • CICS path (src/base/cics/): COBOL programs, BMS maps, and copybooks.
  • IMS path (src/base/ims/): COBOL programs and copybooks. It has no BMS maps.
  • Batch (src/base/batch/): batch application components.

3.2 API and Frontend

  • src/api/ is a z/OS Connect API project. Gradle builds it and produces the API deployment artifact.
  • src/frontend/ is the browser-based UI. It consists of HTML, CSS, and JavaScript, plus a Node.js dev server.

4. Setup Automation (.setup/)

The .setup/ directory holds all automation for provisioning, building, and deploying Bank of Z.

4.1 Orchestration Scripts

Script Runs on Description
setup-local.sh Local machine Creates the USS workspace, clones the repository on USS, and invokes setup-remote.sh via Zowe CLI. Used by the Zowe CLI workflow.
setup-remote.sh z/OS USS Chains the three setup stages in sequence. Used by both the Zowe CLI and GRUB workflows.
setup-common.sh z/OS USS Implements the three setup stages: validate-prereqs, environment, and install-bank-of-z.
pipeline-local.sh Local machine Uploads pipeline assets and invokes pipeline-remote.sh via Zowe CLI. Used by the Zowe CLI workflow for incremental builds.
pipeline-remote.sh z/OS USS Runs the DBB build and Wazi Deploy on USS. Used by both workflows for incremental builds.

The scripts fall into two groups by where they run. The -local scripts run on the developer’s machine and use Zowe CLI to reach z/OS. The -remote and -common scripts run on z/OS USS.

graph LR subgraph Local[Local machine] SL[setup-local.sh] PL[pipeline-local.sh] end subgraph USS[z/OS USS] SR[setup-remote.sh] SC[setup-common.sh] PR[pipeline-remote.sh] end SL -->|Zowe CLI| SR SR --> SC PL -->|Zowe CLI| PR

4.2 Setup Stages

setup-remote.sh chains three stages, and setup-common.sh implements them:

  1. validate-prereqs
  2. environment
  3. install-bank-of-z
sequenceDiagram participant Dev as Developer (local) participant SL as setup-local.sh participant Zowe as Zowe CLI participant SR as setup-remote.sh (USS) participant SC as setup-common.sh (USS) Dev->>SL: Run setup SL->>Zowe: Create USS workspace, clone repo SL->>Zowe: Invoke setup-remote.sh Zowe->>SR: Execute on USS SR->>SC: validate-prereqs SR->>SC: environment SR->>SC: install-bank-of-z SC-->>SR: Stages complete SR-->>Dev: Setup finished

In the GRUB workflow, setup-remote.sh is used directly, without setup-local.sh. This is why setup-remote.sh is shared by both workflows.

4.3 Incremental Build Pipeline

sequenceDiagram participant Dev as Developer (local) participant PL as pipeline-local.sh participant Zowe as Zowe CLI participant PR as pipeline-remote.sh (USS) Dev->>PL: Run pipeline PL->>Zowe: Upload pipeline assets PL->>Zowe: Invoke pipeline-remote.sh Zowe->>PR: Execute on USS PR->>PR: DBB build PR->>PR: Wazi Deploy PR-->>Dev: Build and deploy complete

4.4 Configuration and Assets

Directory Description
.setup/config/ config.yaml, the environment configuration for all setup scripts
.setup/build/ DBB build configuration: datasets.yaml, dbb-build.yaml, language scripts, and zosattributes
.setup/deploy/ Wazi Deploy configuration and deployment method definitions
.setup/jcl/ JCL assets, including Db2-grant.jcl
.setup/zconfig/ zconfig definitions for provisioning CICS and IMS regions
.setup/tasks/ Individual task scripts for DBB build, Wazi Deploy, and ZCodeScan
.setup/setup/ Individual setup stage scripts (Db2, CICS, IMS, z/OS Connect, frontend)
.setup/lib/ Shared shell library functions used by the orchestration scripts
graph TD S[.setup/] S --> CFG[config/ - config.yaml] S --> BLD[build/ - DBB build config] S --> DEP[deploy/ - Wazi Deploy config] S --> JCL[jcl/ - Db2-grant.jcl] S --> ZC[zconfig/ - CICS and IMS region definitions] S --> TSK[tasks/ - DBB, Wazi Deploy, ZCodeScan tasks] S --> STP[setup/ - Db2, CICS, IMS, z/OS Connect, frontend] S --> LIB[lib/ - Shared shell functions]

The orchestration scripts use these assets as follows:

  • config/ supplies the environment settings.
  • lib/ supplies shared shell functions.
  • setup/ supplies the individual stage scripts.
  • tasks/ supplies the build, deploy, and scan task scripts.
  • build/, deploy/, jcl/, and zconfig/ hold the inputs consumed by those scripts.
