Tutorial: Incremental Build

The incremental build workflow in Bank of Z enables developers to modify application code and compile, link-edit, and deploy only the changed components and their direct dependencies. Using IBM Dependency Based Build (DBB) and Git on z/OS UNIX System Services (USS), the pipeline identifies altered source files, minimizing build times and system resource consumption.

1. Overview

In this tutorial, you make a source code modification to a COBOL program within the Bank of Z application and run an incremental build pipeline. The pipeline uses Git tracking and IBM DBB to detect modifications and compile only the affected program (BNKMENU.cbl), followed by deployment verification in CICS.

1.1 Prerequisites

Before starting this tutorial, ensure you have the following prerequisites in place:

  • Completed the Deploy Bank of Z tutorial
  • A running and successfully deployed Bank of Z application environment
  • An active Bank of Z development environment (IDE / local workstation)
  • Access to the Bank of Z Git repository
  • SSH access to the target z/OS USS environment

1.2 Learning Objectives

By completing this tutorial, you will learn how to:

  • Modify an existing COBOL source program (BNKMENU.cbl).
  • Commit and push changes to a remote Git repository branch.
  • Pull updated code into the z/OS USS filesystem.
  • Execute an incremental build using the pipeline-remote.sh build script.
  • Verify that IBM DBB accurately discovers the changed COBOL source file.
  • Confirm that only modified modules are recompiled and packaged.
  • Validate the updated behavior within the CICS transaction runtime.

2. System Architecture

The Bank of Z build system integrates modern source code management (Git) with z/OS build automation (IBM DBB) and mainframe runtime environments (CICS).

2.1 Architectural Components

graph TD subgraph Workstation["Developer Workstation"] A[COBOL Source: BNKMENU.cbl] -->|git commit & push| B[Remote Git Repository] end subgraph zOS["z/OS UNIX System Services (USS)"] B -->|git pull| C[Local z/OS Git Workspace] C --> D[pipeline-remote.sh] D --> E[IBM Dependency Based Build DBB] E -->|Analyze Git Diff & Collections| F{Impacted Files} end subgraph MainframeRuntime["z/OS & CICS Runtime"] F -->|Compile & Link-Edit| G[Load Module PDS/PDSE] G -->|NEWCOPY / Phase In| H[CICS Region Transaction] end

The system components interact across three main boundaries:

  • Developer Workstation: Houses the developer’s working tree where source files such as BNKMENU.cbl are edited and tracked via standard Git commands.
  • z/OS USS Environment: Hosts the local repository clone and build runner (pipeline-remote.sh). IBM DBB interacts with Git metadata and DBB collections to determine source-to-target dependencies and calculate the minimum set of files to compile.
  • Mainframe Runtime: Receives the newly generated binaries into partitioned datasets (PDS/PDSE) and refreshes CICS program definitions (via CEMT NEWCOPY or automated scripts) to run the new logic.

2.2 Incremental Build Lifecycle

sequenceDiagram autonumber actor Dev as Developer participant Git as Remote Git participant USS as z/OS USS participant DBB as IBM DBB participant CICS as CICS Region Dev->>Dev: Edit BNKMENU.cbl (Update invalid-key message) Dev->>Git: git push origin Dev->>USS: Connect via SSH & git pull Dev->>USS: Execute ./pipeline-remote.sh USS->>DBB: Invoke build scripts with Git context DBB->>DBB: Compare commits & check DBB metadata DBB->>DBB: Detect BNKMENU.cbl as changed DBB->>USS: Compile & Link-edit BNKMENU only USS->>CICS: Refresh program (NEWCOPY) Dev->>CICS: Execute transaction & verify new message

3. Step-by-Step Tutorial

3.1 Part 1: Make and Push the COBOL Change

In this step, modify the menu presentation logic in BNKMENU.cbl to alter the message displayed when a user enters an invalid selection key.

  1. Open your local Bank of Z workspace in your IDE.
  2. Locate and open cobol/BNKMENU.cbl.
  3. Locate the error messaging section and update the invalid-key response message string:
COBOL 
*================================================================*
      * PROCESS USER INPUT AND VALIDATE KEYSTROKES                     *
      *================================================================*
           EVALUATE EIBAID
               WHEN DFHENTER
                   PERFORM PROCESS-SELECTION
               WHEN DFHCLEAR
                   EXEC CICS SEND CONTROL ERASE FREEKB END-EXEC
                   EXEC CICS RETURN END-EXEC
               WHEN OTHER
                   MOVE 'INVALID KEY PRESSED - PLEASE TRY AGAIN'
                     TO MSGO OF BNKMENUO
                   PERFORM SEND-MENU-SCREEN
           END-EVALUATE.
  1. Verify your current branch, stage the modified file, and push the change to your remote repository:
BASH 
# Check branch status
git status

# Stage the modified file
git add cobol/BNKMENU.cbl

# Commit the change
git commit -m "Update invalid-key message in BNKMENU"

# Push to the remote branch
git push origin feature/update-menu

3.2 Part 2: Run and Verify the Incremental Build

Connect to the z/OS USS environment to pull the changes and trigger the incremental build pipeline.

  1. Open an SSH session to the z/OS host and navigate to your Bank of Z repository directory:
BASH 
cd /u/user/bank-of-z
  1. Confirm your working branch matches your development branch and pull the latest commit:
BASH 
# Ensure branch alignment
git checkout feature/update-menu

# Pull latest commits
git pull origin feature/update-menu
  1. Execute the remote pipeline build script:
BASH 
./pipeline-remote.sh
  1. Inspect the build console output. Verify that IBM DBB analyzes the Git commit history, detects that only BNKMENU.cbl has changed, and skips unchanged source files:
TEXT 
** Build start at 2025-05-10 14:30:15
** Git repository: /u/user/bank-of-z
** Current commit: a1b2c3d (Update invalid-key message in BNKMENU)
** Analyzing changed files for incremental build...
[DBB] Scanning dependencies...
[DBB] Changed file detected: cobol/BNKMENU.cbl
[DBB] 1 file(s) marked for compilation.

** Compiling cobol/BNKMENU.cbl ...
** Link-editing BNKMENU ...
** Target load module generated: USER.BANKZ.LOAD(BNKMENU)
** Build completed successfully. RC=0

3.3 Part 3: Verify the Application in CICS

Once the build has completed:

  1. Connect to your 3270 terminal session and log into the target CICS region.
  2. If the deployment pipeline did not issue an automatic refresh, issue the NEWCOPY command for the affected program:
TEXT 
CEMT SET PROGRAM(BNKMENU) NEWCOPY
  1. Launch the Bank of Z main menu transaction.
  2. Press an unassigned function key or invalid action key (such as PF4 or an unmapped aid key).
  3. Verify that the updated message (INVALID KEY PRESSED - PLEASE TRY AGAIN) is displayed on the screen.

4. Outcome and Summary

By completing this tutorial, you have:

  • Successfully edited and pushed a COBOL source change (BNKMENU.cbl).
  • Pulled the update to z/OS USS and initiated an incremental build via pipeline-remote.sh.
  • Verified that IBM DBB accurately isolated the single altered source file and compiled only the necessary components.
  • Validated the updated program behavior inside the active CICS region.
