Project Introduction

1. Overview

Bank of Z is an open-source sample banking application. It shows modern IBM Z development, DevSecOps, build, deployment, and modernization practices. It gives users a browser-based banking interface that supports common banking operations and connects to IBM Z transaction-processing systems.

The application uses a hybrid architecture. Customer requests are processed by either CICS or IMS Transaction Manager (IMS TM). Both paths share common banking data stored in Db2 for z/OS. Bank of Z combines traditional enterprise technologies with modern development workflows. This gives learners and teams a realistic environment for learning, demonstrations, and experimentation.

This page covers four things:

  • What Bank of Z is
  • Why it exists
  • Who it is for
  • How the documentation is organized

1.1 What Bank of Z Is

Aspect Description
Type Open-source sample online banking application
Interface Browser-based banking interface
Transaction processing CICS and IMS TM
Data Shared banking data in Db2 for z/OS
Focus Modern IBM Z development, build, deployment, and modernization
Repository https://github.com/IBM/Bank-of-Z

1.2 Why It Exists

Bank of Z demonstrates how enterprise applications can be developed, built, deployed, and maintained on IBM Z with modern practices and tooling. You can use the project to:

  • Learn IBM Z development workflows
  • Explore application modernization approaches
  • Demonstrate enterprise application capabilities
  • Evaluate build and deployment automation
  • Experiment with IBM Z development tools
  • Extend and customize a sample banking application

Bank of Z is intended for educational, demonstration, and proof-of-concept purposes.

2. System Architecture

2.1 High-Level Architecture

Bank of Z has a browser-based front end. Customer requests are routed to one of two IBM Z transaction managers, CICS or IMS TM. Both share banking data stored in Db2 for z/OS. The diagram below shows this at a conceptual level. The detailed component design is in the Architecture section of the documentation.

graph TD U[Customer / Browser] --> UI[Browser-Based Banking Interface] UI --> CICS[CICS Transaction Processing] UI --> IMS[IMS Transaction Manager - IMS TM] CICS --> DB2[(Db2 for z/OS - Shared Banking Data)] IMS --> DB2

2.2 Core Components

Component Role
Browser-based banking interface Gives customers access to common banking operations
CICS Processes customer requests as one of the two transaction-processing paths
IMS TM Processes customer requests as the alternative path. The tutorials also cover IMS DB applications
Db2 for z/OS Stores the common banking data shared by both paths

2.3 Request Flow

A customer request goes through the interface and is handled by either CICS or IMS TM. The transaction manager reads or updates the shared data in Db2 for z/OS and returns the result to the customer.

sequenceDiagram participant User as Customer participant UI as Banking Interface participant TM as CICS or IMS TM participant DB as Db2 for z/OS User->>UI: Banking request UI->>TM: Route request TM->>DB: Read / update banking data DB-->>TM: Result TM-->>UI: Response UI-->>User: Display result

2.4 Documentation Architecture

The documentation is also built as a system. Writers author content as DITA XML in the Docs/ folder. A Python conversion script generates Markdown and a Table of Contents. Jekyll and GitHub Pages publish the result. The sidebar navigation is generated automatically from _data/toc.yml.

graph LR A[DITA XML in Docs/] --> B[convert_dita_to_md.py] B --> C[Generated Markdown in docs/] B --> D[_data/toc.yml] C --> E[Jekyll Build] D --> E E --> F[GitHub Pages Site] G[GitHub Actions convert-docs.yml] -.optional automation.-> B

4. Working with the Documentation

4.1 Authoring Content

Documentation is written in DITA XML. Here is an example topic:

XML 
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE topic PUBLIC "-//OASIS//DTD DITA Topic//EN" "topic.dtd">
<topic id="getting_started" xml:lang="en-us">
<title>Getting Started</title>
<body>
<section>
<title>Introduction</title>
<p>This guide will help you get started with Bank of Z.</p>
<ul>
<li>Step 1: Install prerequisites</li>
<li>Step 2: Clone the repository</li>
</ul>
</section>
</body>
</topic>

The conversion script handles titles and headings, paragraphs and lists (including nested ones), external and internal links (<xref>), trademarks (<tm>), file paths (<filepath>), and code formatting.

4.2 Publishing Workflow

sequenceDiagram participant W as Writer participant S as convert_dita_to_md.py participant G as GitHub participant P as GitHub Pages W->>W: Add or edit DITA files in Docs/ W->>S: Run conversion script S-->>W: Markdown and toc.yml updated W->>G: Commit and push G->>P: Trigger rebuild P-->>W: Updated site in 2-3 minutes

To convert the files:

BASH 
python3 scripts/convert_dita_to_md.py

4.3 Testing Locally

You need Ruby (for Jekyll), Python 3.x, and Bundler.

BASH 
# Clone the repository
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z-doc

# Install dependencies
pip3 install pyyaml
bundle install  # For local Jekyll testing

# Convert DITA to Markdown
python3 scripts/convert_dita_to_md.py

# Test locally (optional)
bundle exec jekyll serve
# Visit http://localhost:4000/Bank-of-Z-doc/

4.4 Optional Automation

A GitHub Actions workflow can convert DITA files automatically.

Property Value
File .github/workflows/convert-docs.yml
Trigger Manual, or on push to Docs/**/*.dita
Action Runs the conversion script and commits the changes

To enable it, make sure GitHub Actions has write permissions in your repository settings.

4.5 Quick Troubleshooting for the Documentation Site

Issue Solution
TOC not updating Run python3 scripts/convert_dita_to_md.py and commit the changes
Missing dependencies Run pip3 install pyyaml and bundle install
Links not working Check that baseurl in _config.yml matches your GitHub Pages URL
