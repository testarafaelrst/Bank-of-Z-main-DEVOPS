1. Installation Verification

The installation verification process provides a structured approach to confirm that the Bank of Z application and its supporting runtime infrastructure have been installed, configured, and deployed correctly. Completing these verification steps ensures that all local development prerequisites, network connections, host middleware subsystems, and application artifacts are operational prior to starting development or testing activities.

2. System Architecture and Component Verification

Before running functional tests, verify that all layers of the Bank of Z platform architecture are connected and active. The architecture consists of the local developer workstation tooling, z/OS management endpoints, API mediation layers, and core IBM Z transaction and database subsystems.

4. Verification Flow and Sequence

The verification lifecycle follows a tiered sequence: validating the client workstation, checking host connectivity, confirming subsystem health, verifying deployment artifacts, and executing functional end-to-end tests.

sequenceDiagram autonumber actor Admin as Developer / Administrator participant WS as Local Workstation (CLI/Tools) participant ZOSMF as z/OSMF Endpoint participant ZCEE as z/OS Connect EE participant Core as Core Subsystems (CICS/IMS/Db2/MQ) Admin->>WS: Verify local tools (Java, Git, Zowe CLI) WS-->>Admin: Tool versions confirmed Admin->>WS: Execute `zowe zosmf check status` WS->>ZOSMF: Ping z/OSMF service ZOSMF-->>WS: Status response (OK) WS-->>Admin: Target z/OS connection confirmed Admin->>ZOSMF: Verify z/OS 3.1+, CICS, IMS, Db2, MQ ZOSMF-->>Admin: Subsystems available and active Admin->>ZCEE: Validate deployed API artifacts Admin->>Core: Validate load modules, tables, plans, and resources Core-->>Admin: Deployment confirmed Admin->>WS: Launch UI & execute transactions WS->>ZCEE: Invoke API requests ZCEE->>Core: Process business logic (CICS / IMS / Db2) Core-->>ZCEE: Return response data ZCEE-->>WS: Deliver payload to UI WS-->>Admin: User info, account details, and transactions verified

The sequence above outlines the full validation path from initial environment checks to executing end-to-end transactions against backend z/OS resources.

5. Verify Development Environment

Confirm that the required development toolchains are installed, configured, and accessible on your local path.

5.1. Verify Java

Validate that the Java runtime is installed and accessible:

BASH 
java --version

5.2. Verify Git

Check that Git version control is available:

BASH 
git --version

5.3. Verify Zowe CLI

Ensure that the Zowe command-line interface is installed:

BASH 
zowe --version

5.4. Verify Connectivity

Test workstation connectivity to the target z/OS system via the z/OSMF profile:

BASH 
zowe zosmf check status

A successful response validates that the local workstation can communicate with the target z/OS host environment.

6. Verify Target Environment

Confirm that the target IBM Z platform environment has the necessary operating system and middleware subsystems online and available:

  • z/OS 3.1 or later
  • CICS
  • IMS Transaction Manager (IMS TM)
  • IMS DB
  • Db2 for z/OS
  • z/OS Connect Enterprise Edition
  • IBM MQ

Note: If any required subsystem is offline or unavailable, contact your z/OS system administrator before proceeding with application verification.

7. Verify Application Deployment

Verify that all Bank of Z application-level components and middleware resources are installed and properly configured:

  • Application Load Modules: Confirm all required load modules are available in the target runtime libraries.
  • Db2 Tables and Plans: Ensure application databases, tables, and execution plans have been created and bound.
  • IMS Application Resources: Verify that IMS transactions, programs, and database descriptors are installed.
  • CICS Resources: Validate that target CICS programs, transactions, and definitions are installed and active.
  • z/OS Connect API Artifacts: Ensure that the Bank of Z API packages are deployed to the z/OS Connect runtime.
  • Configuration Resources: Confirm all required configuration files and environment definitions are available.

8. Verify Application Access and Operations

Perform end-to-end operational checks to confirm that the Bank of Z application processes requests correctly across the full software stack.

Execute the following validation activities:

  1. Access the User Interface: Launch and sign in to the Bank of Z web interface.
  2. Retrieve User Information: Query and display customer profile details.
  3. View Account Details: Access account balances, transaction histories, and related summaries.
  4. Execute Account Transactions: Perform account operations (such as transfers or updates) and ensure data is committed correctly.
  5. Invoke z/OS Connect APIs: Send direct API requests to the deployed z/OS Connect endpoints and verify valid responses.

Successful execution of these tasks confirms that all deployed components, API definitions, and backend subsystems are communicating correctly.

9. Verification Results Summary

Upon completing the verification procedure, the Bank of Z deployment should provide:

  • A fully configured and tested local development environment.
  • Verified connectivity to the target z/OS host.
  • Correctly deployed application artifacts, databases, and load modules.
  • Active and accessible middleware subsystems (CICS, IMS, Db2, IBM MQ, z/OS Connect).
  • Operational REST APIs and services.
  • A functioning, end-to-end operational Bank of Z application environment.
