Tutorial: Debug a CICS Transaction

This tutorial walks you through debugging the Bank of Z INQCUST COBOL program — the CICS customer inquiry transaction — using IBM Z Open Debug in Visual Studio Code. It covers tooling setup, debug profile configuration, breakpoint management, and how to interpret diagnostic output during a live CICS debug session.

1. Overview

The Bank of Z application exposes a customer inquiry feature through the INQCUST COBOL program, which runs as a CICS transaction. When a user looks up a customer from the web UI, the request travels from the browser through z/OS Connect into CICS, where INQCUST is executed.

Debugging this transaction requires intercepting a live CICS task and attaching a source-level debugger to it — without disrupting other users sharing the same CICS region. This is achieved through two server-side daemons:

  • Debug Profile Service (DPS): Manages debug profiles that identify which transactions and which user IDs to intercept.
  • Remote Debug Service (RDS): Acts as a protocol bridge that routes an intercepted CICS task to a specific VS Code instance using the Debug Adapter Protocol (DAP).

Together, they allow a developer to step through COBOL source, inspect working-storage variables, and diagnose issues in a running CICS environment safely.

2. System Architecture

The following diagram illustrates how VS Code, the debug daemons, and the CICS region interact during a debug session.

graph TD A[Browser / Bank of Z Web UI] -->|HTTP Request| B[z/OS Connect] B -->|IPIC Connection| C[CICS Region] C -->|Executes| D[INQCUST COBOL Program] D -->|Task Intercepted| E[Debug Profile Service DPS :8192] E -->|Parks Session| F[Remote Debug Service RDS :8194] F -->|DAP Protocol| G[VS Code - IBM Z Open Debug] G -->|Breakpoints / Step Commands| F

When a matching transaction is triggered under the profiled user ID, CICS suspends the task and notifies the DPS. The RDS then bridges that parked session to VS Code over the Debug Adapter Protocol, making source-level debugging possible in real time.

2.1 Component Reference Table

Component Role Default Port
Debug Profile Service (DPS) Stores and serves debug profiles; identifies which transactions to intercept 8192
Remote Debug Service (RDS) Protocol bridge between DPS and VS Code DAP 8194
IBM Z Open Debug (VS Code) DAP client; renders source, breakpoints, and variables —
z/OS Connect REST-to-CICS gateway for the Bank of Z web UI —
CICS Region Hosts and executes the INQCUST program —

3. Prerequisites

Before starting this tutorial, ensure the following are in place:

  • The Quick Start has been completed and Bank of Z is successfully built and deployed.
  • VS Code is installed with the IBM Developer for z/OS Enterprise Edition (IDzEE) extension pack, which includes IBM Z Open Debug.
  • The Bank of Z CICS region is running and the OMEN transaction is reachable.
  • The INQCUST load module was compiled with the TEST or TEST(SOURCE) compiler option so that a side-file listing (.dbg) exists on USS.

4. How the Debug Flow Works

The sequence below shows the full lifecycle of a debug session — from triggering the transaction to stepping through COBOL source in VS Code.

sequenceDiagram participant Dev as Developer (VS Code) participant DPS as Debug Profile Service (DPS :8192) participant RDS as Remote Debug Service (RDS :8194) participant CICS as CICS Region participant App as INQCUST Program Dev->>DPS: Create & Activate Debug Profile (INQCUST / CICSUSER) Dev->>App: Trigger transaction via Bank of Z Web UI CICS->>DPS: Transaction intercepted — park session DPS-->>CICS: Session parked, waiting for debugger Dev->>RDS: Press F5 — Connect to parked session RDS->>DPS: Retrieve parked session DPS-->>RDS: Session details returned RDS-->>Dev: DAP session established, source loaded Dev->>CICS: Step Over / Step Into / Inspect Variables CICS-->>Dev: Variable values, program counter updates Dev->>RDS: Disconnect (let task complete normally) RDS-->>CICS: Task resumes and completes

5. Step 1 — Configure the Zowe zOpenDebug Profile

The Bank of Z repository ships a pre-configured zOpenDebug profile block in zowe.config.json with DPS port 8192 and RDS port 8194. You need to supply your host name and credentials in zowe.config.user.json.

5.1 Set the Host in zowe.config.user.json

Copy zowe.config.user.json.template to zowe.config.user.json (if not already done), then open it and set the host and credentials for the bank-of-z profile:

JSON 
{
  "profiles": {
    "bank-of-z": {
      "properties": {
        "host": "192.168.1.10"
      },
      "secure": ["user", "password"]
    }
  }
}

Replace 192.168.1.10 with the IP address or hostname of your z/OS system.

5.2 Store Credentials in the Secure Credential Store

BASH 
zowe config secure

Enter your TSO user ID and password when prompted. Zowe stores these securely so they are never written in plaintext to the config file.

5.3 Verify the Debug Profile Resolves Correctly

BASH 
zowe config list --root

Confirm that bank-of-z.zOpenDebug appears under defaults with:

  • dpsPort: 8192
  • rdsPort: 8194

6. Step 2 — Verify the Launch Configuration

The repository includes a ready-to-use debug launch configuration in .vscode/launch.json. Open it and confirm it contains the following entry:

JSON 
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "zOpenDebug",
      "request": "launch",
      "name": "Z Open Debug: Connect to a parked debug session",
      "connection": {
        "type": "zowe",
        "name": "bank-of-z.zOpenDebug"
      }
    }
  ]
}

Key points:

  • type: "zOpenDebug" activates the IBM Z Open Debug adapter.
  • request: "launch" instructs Z Open Debug to connect to a session that is already parked on the DPS — i.e., a CICS task that has been intercepted and is waiting for a debugger to attach.
  • The connection.name references the Zowe profile (bank-of-z.zOpenDebug), which supplies the DPS/RDS host and port details automatically. No extra configuration is required.

7. Step 3 — Create a Debug Profile Service Profile

The DPS profile tells CICS which programs to intercept and for which user ID. This ensures only your transactions are affected — other users on the same CICS region continue uninterrupted.

7.1 Open the Z/OS Debugger Profiles View

In the VS Code Activity Bar, open the Zowe Explorer panel.

7.2 Create a New CICS Debug Profile

In the Z/OS DEBUGGER PROFILES section, expand the Debug Profiles tree node. Right-click on CICS and select Create.

7.3 Fill In the Profile Details

Field Value
Profile name INQCUST-debug (any descriptive name)
CICS system Your CICS region name, e.g. CICSBOZ
Load module / program INQCUST
Qualified user ID Your TSO user ID, e.g. CICSUSER

Select Save. The profile is registered with the DPS on z/OS.

7.4 Activate the Profile

Right-click the newly created profile and select Activate for Debug. A bug icon with a green dot appears next to the profile to confirm it is active.

With the profile active, any invocation of INQCUST under the specified TSO user ID (CICSUSER) is intercepted by CICS and parked until VS Code attaches. Transactions belonging to other user IDs are unaffected.

8. Step 4 — Trigger the CICS Transaction

Open the Bank of Z web application and look up a customer whose ID starts with C (for example, C0001). The UI sends the request through the following path:

graph LR A[Bank of Z Web UI] -->|REST API Call| B[z/OS Connect] B -->|IPIC| C[CICS Transaction] C -->|Intercept by DPS| D[Session Parked] D -->|Waiting for Debugger| E[VS Code Attach]

⚠️ Note on Timeout: For transactions coming from the web interface, a timeout is configured in the cics.xml file for z/OS Connect. In this project it is set to 5 minutes. If you need longer debug sessions, edit the requestTimeout attribute of the zosconnect_cicsIpicConnection tag in cics.xml.

The cics.xml file is generated by .setup/setup/setup-zosconnect-server.sh.

9. Step 5 — Attach the Debug Session in VS Code

9.1 Open the Run and Debug View

In VS Code, open the Run and Debug view using:

  • Windows/Linux: Ctrl+Shift+D
  • macOS: ⇧⌘D

9.2 Select the Launch Configuration

From the configuration dropdown at the top of the panel, select:

CODE 
Z Open Debug: Connect to a parked debug session

This corresponds to the entry defined in .vscode/launch.json.

9.3 Start the Debug Session

Press F5 or click the green Start Debugging arrow.

Z Open Debug contacts the RDS at port 8194, which retrieves the parked session from the DPS at port 8192. VS Code opens the INQCUST COBOL source file and the program counter stops at the first intercepted statement — ready for inspection.

10. Step 6 — Inspect Variables and Step Through Code

Once attached, use the standard VS Code debug toolbar and panels to navigate through the COBOL program.

10.1 Debug Toolbar Actions

Action Shortcut What It Does
Continue F5 Run to next breakpoint or program end
Step Over F10 Execute current statement; stay at the same call level
Step Into F11 Step into a called sub-program or paragraph
Step Out ⇧F11 Run to end of current program or paragraph
Stop ⇧F5 Terminate the debug session; CICS task abends (ADBS)

10.2 Inspecting Variables

  • Open the Variables panel on the left side of the debug view to inspect Working Storage and Linkage Section fields.
  • Hover over a variable name in the source editor to see its current value inline.
  • Use the Watch panel to track specific fields as you step through the program.

10.3 Setting Breakpoints

Click in the gutter (left margin) next to any source line in the INQCUST COBOL file to set a breakpoint. A solid red circle confirms the breakpoint is verified against the loaded listing. A hollow circle indicates an unverified breakpoint — see the Troubleshooting section for resolution steps.

11. Troubleshooting

The table below covers the most common issues encountered during CICS debug sessions with IBM Z Open Debug.

Symptom Likely Cause Resolution
VS Code cannot connect to a parked session Transaction ran and completed before F5 was pressed; profile was not active Ensure the DPS profile is activated before triggering the transaction, then trigger it again
Source not shown — only assembler disassembly Listing file not found or .zdx.json path is incorrect Verify the USS listing path in .zdx.json; confirm the build produced a .dbg side file
CICS transaction abends with ADBS Debug session was stopped (terminated) rather than disconnected Use Disconnect instead of Stop to let the CICS task complete normally
Other users’ transactions are being intercepted DPS profile userId field was left blank or wildcarded Edit the profile and set userId to your specific TSO user ID
RDS connection refused Port 8194 is blocked or the RDS started task is not running Check network access to the z/OS host on port 8194; verify the RDS started task is active
Breakpoints shown as unverified (hollow circles) Source file in VS Code does not match the listing file on z/OS Ensure you are viewing the same source version that was compiled; rebuild and redeploy if necessary
