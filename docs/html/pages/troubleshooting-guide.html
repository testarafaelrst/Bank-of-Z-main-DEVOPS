Troubleshooting Guide

This guide covers common problems and their resolutions when you install, configure, build, deploy, and develop Bank of Z. It is organized by problem area: Zowe CLI connectivity, configuration files, Git and repository access, USS permissions, and build and setup validation. Each entry follows the same pattern of Symptom, Possible cause, and Resolution.

1. Overview

Bank of Z uses a setup process that runs on z/OS Unix System Services (USS) and on a developer workstation. The process depends on these components:

  • Zowe CLI, which connects the workstation to z/OS through z/OSMF.
  • config.yaml, the central configuration file at .setup/config/config.yaml.
  • Git, which clones and synchronizes repositories on USS.
  • IBM Dependency Based Build (DBB) and Java, which run the builds.
  • zBuilder, the build framework that the setup deploys.
  • A writable sandbox directory on USS.

Most failures come from one of these prerequisites being missing, misconfigured, or inaccessible. The recommended approach is:

  1. Identify the stage that failed from the setup output.
  2. Find the matching problem area in this guide.
  3. Apply the resolution and rerun the setup or build.

1.1 Problem Categories

Category Typical problems
Zowe CLI CLI not found, profile not found, unable to connect to z/OS
Configuration Missing config.yaml, unresolved variables, relative paths
Git and repository Git missing on USS, clone failures
USS permissions Permission denied on the sandbox directory
Build and setup Setup completes with errors, DBB validation, Java validation

3. Zowe CLI Issues

3.1 Zowe CLI Not Found

Symptom

Commands such as the following return a command not found error:

BASH 
zowe --version

Possible cause

Zowe CLI is not installed, or it is not on your system path.

Resolution

Verify the installation:

BASH 
zowe --version

If Zowe CLI is not installed, install it with npm:

BASH 
npm install -g @zowe/cli

Make sure the npm global installation directory is included in your system path.

3.2 Zowe Profile Not Found

Symptom

Zowe commands fail because a profile cannot be located.

Possible cause

A z/OSMF profile has not been created or configured correctly.

Resolution

List the available profiles:

BASH 
zowe profiles list zosmf

Create or update the required profile, then verify connectivity:

BASH 
zowe zosmf check status

3.3 Unable to Connect to z/OS

Symptom

Connection validation commands fail.

Possible cause

The host information is incorrect, the credentials are invalid, the network is unavailable, or a firewall blocks the connection.

Resolution

Verify the configured profile settings and test connectivity:

BASH 
zowe zosmf check status

Confirm that the host, port, and credentials are correct. Also confirm that the target system is reachable from your workstation.

The following sequence shows what a successful connectivity check involves.

sequenceDiagram participant User participant CLI as Zowe CLI participant Profile as z/OSMF Profile participant ZOSMF as z/OSMF Server User->>CLI: zowe zosmf check status CLI->>Profile: Read host, port, credentials Profile-->>CLI: Connection settings CLI->>ZOSMF: Status request ZOSMF-->>CLI: Status response CLI-->>User: Connection result

If the check fails, the problem is in one of three places: the profile settings, the credentials, or the network path between the workstation and the server.

4. Configuration Issues

4.1 Configuration File Not Found

Symptom

Setup or build processes fail because the configuration file cannot be located.

Possible cause

The config.yaml file is missing, or it is stored in an unexpected location.

Resolution

Verify that the file exists:

BASH 
ls -la .setup/config/config.yaml

Make sure you run commands from the correct repository location.

4.2 Variable Reference Cannot Be Resolved

Symptom

Setup validation reports unresolved variables.

Possible cause

A referenced configuration value or environment variable does not exist.

Resolution

Verify all variable references. For example:

YAML 
dbb:
  build_dir: ${sandbox.path}/build

Make sure the referenced sections and keys, such as sandbox.path in this example, are defined in the configuration file.

4.3 Invalid Path Format

Symptom

Setup validation fails when it processes directory paths.

Possible cause

A required path is specified as a relative path.

Resolution

Use absolute paths for configuration values that reference USS directories.

YAML 
sandbox:
  path: /usr/local/sandboxes/bank-of-z

4.4 Configuration Dependencies

Several settings depend on each other. Because dbb.build_dir references sandbox.path, an error in the sandbox path can show up as a variable or path error in other sections.

graph TD SP[sandbox.path - absolute USS path] --> BD[dbb.build_dir] DH[dbb_home] --> DV[DBB validation] JH[java_home] --> JV[Java validation] BD --> SETUP[Setup validation] DV --> SETUP JV --> SETUP

5. Git and Repository Issues

5.1 Git Not Available on USS

Symptom

Repository cloning or synchronization fails on USS.

Possible cause

Git is not installed, or it is not on the USS path.

Resolution

Verify the installation:

BASH 
which git
git --version

If Git is not available, contact your z/OS administrator.

5.2 Unable to Clone Repositories

Symptom

Repository clone operations fail during setup.

Possible cause

Network restrictions, repository access problems, or authentication problems.

Resolution

Verify repository access, network connectivity, and authentication settings. Confirm that the target z/OS environment can reach the repository hosting service.

6. USS Permission Issues

6.1 Permission Denied When Creating Workspace

Symptom

Setup scripts fail when they create directories or deploy artifacts.

Possible cause

You do not have sufficient USS permissions.

Resolution

Verify that you have write access to the configured sandbox directory. Review the configured sandbox.path value. If you need more permissions, contact your z/OS administrator.

7. Build and Setup Issues

7.1 Setup Completes with Errors

Symptom

The setup process completes, but some stages report failures or warnings.

Possible cause

A prerequisite component is unavailable or incorrectly configured.

Resolution

Review the setup output and identify the stage that failed. Then verify each of these:

  • DBB installation
  • Java configuration
  • Git availability
  • zBuilder deployment
  • Repository access
  • Configuration settings

Correct the reported issue and rerun the setup process.

7.2 DBB Validation Fails

Symptom

Build processes cannot locate DBB components.

Possible cause

The configured DBB installation path is incorrect.

Resolution

Verify the configured location:

BASH 
ls $DBB_HOME/lib

Update the dbb_home setting if necessary.

7.3 Java Validation Fails

Symptom

Build or setup scripts fail when they invoke Java.

Possible cause

The configured Java runtime is unavailable or incorrectly configured.

Resolution

Verify the Java installation:

BASH 
$JAVA_HOME/bin/java -version

Confirm that the java_home value points to a supported Java installation.

7.4 Setup Stage Validation Sequence

This sequence shows how the setup process validates prerequisites and where each failure type surfaces.

sequenceDiagram participant User participant Setup as Setup Process participant Cfg as config.yaml participant Git participant DBB participant Java User->>Setup: Run setup Setup->>Cfg: Load and resolve variables Cfg-->>Setup: Validated settings Setup->>Git: Check availability and clone Git-->>Setup: Result Setup->>DBB: Validate dbb_home DBB-->>Setup: Result Setup->>Java: Validate java_home Java-->>Setup: Result Setup-->>User: Completed, or completed with errors

9. Getting Additional Help

If this guide does not resolve the issue:

  • Review the setup output and error messages.
  • Verify the configuration settings in config.yaml.
  • Confirm that all prerequisites are installed and accessible.
  • Consult your z/OS administrator for environment-specific issues.
  • Review the workflow documentation for more setup and configuration details.
