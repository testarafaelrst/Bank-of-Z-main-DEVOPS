Tutorial: Debug a CICS Transaction

This tutorial shows how to debug the Bank of Z INQCUST COBOL program, the CICS customer inquiry transaction. You use IBM Z Open Debug in Visual Studio Code with the Debug Profile Service (DPS) and the Remote Debug Service (RDS).

1. Overview

1.1 Purpose

The tutorial walks through attaching VS Code to a live CICS task running INQCUST. The two services have different jobs:

  • The Debug Profile Service (DPS) manages debug profiles. A profile identifies the transaction to debug, so other transactions on the same CICS region are not affected.
  • The Remote Debug Service (RDS) routes the debug session to your specific VS Code instance.

1.2 What You Will Do

Step Activity
1 Configure the Zowe zOpenDebug profile
2 Verify the VS Code launch configuration
3 Create and activate a DPS profile
4 Trigger the CICS transaction from the Bank of Z web app
5 Attach the debug session in VS Code
6 Inspect variables and step through code

1.3 Prerequisites

Before starting, make sure that:

  • You completed the Quick Start and successfully built and deployed Bank of Z.
  • VS Code has the IBM Developer for z/OS Enterprise Edition (IDzEE) extension pack installed. The pack includes IBM Z Open Debug.
  • The Bank of Z CICS region is running and you can reach the OMEN transaction.
  • The INQCUST load module was compiled with the TEST or TEST(SOURCE) compiler option, so a side-file listing exists.

2. System Architecture

2.1 Component Overview

Z Open Debug uses two server-side daemons and a CICS-side intercept to connect VS Code to a running CICS task.

CODE 
VS Code  ⟷  Remote Debug Server (RDS, port 8194)  ⟷  Debug Profile Service (DPS, port 8192)  ⟷  CICS region

The diagram shows two paths:

  • Debug path: VS Code connects through RDS and DPS to the CICS region.
  • Transaction path: the web application reaches INQCUST through z/OS Connect.

2.2 Component Roles

Component Role Port (Bank of Z default)
Debug Profile Service (DPS) Stores and serves debug profiles 8192
Remote Debug Service (RDS) Protocol bridge between DPS and VS Code DAP (Debug Adapter Protocol) 8194
IBM Z Open Debug (VS Code extension) DAP client; renders source, breakpoints, variables —

2.3 How Interception Works

The DPS holds named profiles. When a CICS transaction runs under a user ID that matches a profile, CICS suspends the task and notifies the RDS. The RDS connects the task to the VS Code debug session. Only transactions that belong to the TSO user ID specified in the profile are intercepted. Other users are unaffected.

sequenceDiagram participant Web as Bank of Z Web App participant ZC as z/OS Connect participant CICS as CICS Region participant DPS as Debug Profile Service participant RDS as Remote Debug Service participant VS as VS Code Web->>ZC: Customer lookup (e.g. C0001) ZC->>CICS: Invoke INQCUST CICS->>DPS: Check profiles for program and user ID DPS-->>CICS: Matching active profile CICS->>CICS: Suspend task (parked session) CICS->>RDS: Notify of parked session VS->>RDS: Start Debugging (F5) RDS->>DPS: Retrieve parked session RDS-->>VS: Connect session, stop at first line

3. Step 1 — Configure the Zowe zOpenDebug Profile

The Bank of Z repository ships a pre-configured zOpenDebug profile block in zowe.config.json, with DPS port 8192 and RDS port 8194. You supply the host name and credentials in zowe.config.user.json, which you copy from zowe.config.user.json.template.

3.1 Set the Host

Open zowe.config.user.json and set the host and credentials for the bank-of-z profile:

JSON 
{
  "profiles": {
    "bank-of-z": {
      "properties": {
        "host": "192.168.1.10"
      },
      "secure": ["user", "password"]
    }
  }
}

3.2 Store Credentials

Store credentials in the Zowe secure credential store:

BASH 
zowe config secure

Enter your TSO user ID and password when prompted.

3.3 Verify the Profile

Check that the debug profile resolves correctly:

BASH 
zowe config list --root

Confirm that bank-of-z.zOpenDebug appears under defaults with dpsPort: 8192 and rdsPort: 8194.

4. Step 2 — Verify the Launch Configuration

The repository includes a ready-to-use debug launch configuration in .vscode/launch.json:

JSON 
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "zOpenDebug",
      "request": "launch",
      "name": "Z Open Debug: Connect to a parked debug session",
      "connection": {
        "type": "zowe",
        "name": "bank-of-z.zOpenDebug"
      }
    }
  ]
}

The type: "zOpenDebug" and request: "launch" combination tells Z Open Debug to connect to a session that is already parked on the DPS. That session is a CICS task that was intercepted and is waiting for a debugger to attach. No extra configuration is needed, because the Zowe profile supplies all connection details.

graph LR A[launch.json] -->|connection.name| B[bank-of-z.zOpenDebug] B --> C[zowe.config.json: dpsPort 8192, rdsPort 8194] B --> D[zowe.config.user.json: host and credentials]

5. Step 3 — Create a Debug Profile Service Profile

The DPS profile tells CICS which programs to intercept and for whom. You can create it from the IBM Z Open Debug view in VS Code.

5.1 Create the Profile

  1. In the VS Code Activity Bar, open the Zowe Explorer panel.
  2. In the Z/OS DEBUGGER PROFILES section, expand the Debug Profiles tree node. Right-click CICS and select Create.
  3. Fill in the profile details:
Field Value
Profile name INQCUST-debug (any name)
CICS system Your CICS region name, for example CICSBOZ
Load module / program INQCUST
Qualified user ID Your TSO user ID, for example CICSUSER
  1. Select Save. The profile is registered with the DPS on z/OS.

5.2 Activate the Profile

Right-click the profile and select Activate for Debug. A bug icon with a green dot appears next to the profile when it is active.

With the profile active, any invocation of INQCUST under CICSUSER (the ID used by z/OS Connect) is intercepted by CICS and parked until VS Code attaches.

stateDiagram-v2 [*] --> Created: Create profile Created --> Active: Activate for Debug Active --> Parked: Matching INQCUST task intercepted Parked --> Attached: VS Code starts debugging Attached --> [*]: Disconnect

6. Step 4 — Trigger the CICS Transaction

Open the Bank of Z web application and look up a customer whose ID starts with C (for example, C0001). The UI sends the request through z/OS Connect → CICS → INQCUST.

NOTE: A transaction that comes from the web interface has a timeout, configured in the cics.xml file for z/OS Connect. For this project it is set to 5 minutes. If you need longer sessions, edit the requestTimeout attribute of the zosconnect_cicsIpicConnection tag in cics.xml. The XML file is generated by .setup/setup/setup-zosconnect-server.sh.

graph LR A[Web UI: lookup C0001] --> B[z/OS Connect] B -->|IPIC connection, requestTimeout 5 min| C[CICS] C --> D[INQCUST parked by DPS profile]

7. Step 5 — Attach the Debug Session in VS Code

7.1 Start the Session

  1. In VS Code, open the Run and Debug view (Ctrl+Shift+D / ⇧⌘D).
  2. From the configuration dropdown at the top, select Z Open Debug: Connect to a parked debug session. This is the entry from .vscode/launch.json.
  3. Press F5 or click the green Start Debugging arrow.

7.2 What Happens

Z Open Debug contacts the RDS at port 8194, which retrieves the parked session from the DPS at port 8192. VS Code opens the INQCUST source file and the program counter stops at the first intercepted line.

8. Step 6 — Inspect Variables and Step Through Code

Once attached, use the standard VS Code debug toolbar and panels:

Action Shortcut What it does
Continue F5 Run to next breakpoint or program end
Step Over F10 Execute current statement; stay at same level
Step Into F11 Step into a called sub-program
Step Out ⇧F11 Run to end of current program or paragraph
Stop ⇧F5 Terminate the debug session; CICS task abends (ADBS)
graph TD A[Stopped at first line] --> B{Choose action} B -->|F10| C[Step Over] B -->|F11| D[Step Into] B -->|⇧F11| E[Step Out] B -->|F5| F[Continue] C --> A D --> A E --> A F --> G{Breakpoint hit?} G -->|Yes| A G -->|No| H[Program ends, task completes]

Use Disconnect rather than Stop to end the session. Stop terminates the debug session and causes the CICS task to abend with ADBS.

9. Troubleshooting

Symptom Likely cause Resolution
VS Code cannot connect to a parked session Transaction ran and completed before F5 was pressed; profile was not active Ensure the DPS profile is activated before triggering the transaction, then trigger again
Source not shown — only assembler disassembly Listing file not found or .zdx.json path is wrong Verify the USS listing path in .zdx.json; confirm the build produced a .dbg side file
CICS transaction abends with ADBS Debug session was terminated rather than disconnected Use Disconnect instead of Stop to let the task complete normally
Other users’ transactions are being intercepted DPS profile userId field was left blank or wildcarded Edit the profile and set userId to your specific TSO user ID
RDS connection refused Port 8194 blocked or RDS started task is not running Check network access to the z/OS host on port 8194; verify the RDS started task
Breakpoints shown as unverified (hollow circles) Source file in VS Code does not match the listing file on z/OS Ensure you are viewing the same source version that was compiled; rebuild if necessary
