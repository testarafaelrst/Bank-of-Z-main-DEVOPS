Prerequisites & Environment Configuration

Bank of Z is a self-contained sample hybrid banking application built on IBM Z. Before you can install, build, and run it, your environment — both the target z/OS system and your local workstation — must satisfy a set of platform, tooling, access, and configuration requirements. This page consolidates all prerequisite checks and environment configuration steps into a single reference so that administrators and developers can prepare a complete, validated environment before starting any deployment workflow.

1. Overview

Bank of Z integrates multiple IBM Z middleware technologies — CICS, IMS Transaction Manager (IMS TM), IMS Database (IMS DB), Db2 for z/OS, z/OS Connect Enterprise Edition, and IBM MQ — into a single realistic hybrid banking application. Because the application spans all of these subsystems, preparing the environment involves:

  • Confirming that the z/OS platform and its middleware components are at supported release levels.
  • Installing and registering the z/OS USS build and deploy tooling (DBB, ZOAU, zconfig, Wazi Deploy, and others).
  • Ensuring the developer’s workstation runs a supported desktop platform.
  • Granting the correct access and security permissions (TSO, USS, datasets, RACF).
  • Installing external language-level dependencies (Python libraries, Gradle).
  • Editing the central config.yaml file to reflect your specific environment.
  • Setting required environment variables for middleware credentials.

The sections that follow address each of these areas in order.

The workstation is used exclusively for authoring code and triggering automation. All compilation, linking, static analysis, and deployment activity runs on z/OS USS, where the build and deploy toolchain is installed. Middleware instances (CICS, IMS, Db2, MQ, z/OS Connect) are provisioned automatically by the setup scripts — except for the Db2 subsystem (DBD1), which must pre-exist.

4. z/OS Platform Requirements

4.1 Middleware Component Versions

All components listed below must be installed on the target z/OS system. Contact your system administrator if any component is missing or at an unsupported release level.

Component Minimum Version
z/OS 3.1
CICS TS 6.3
Db2 for z/OS V13
IMS Transaction Manager (IMS TM) V15
IMS Database V15
z/OS Connect Enterprise Edition 3.0.101
IBM MQ Supported release

Important: A pre-existing Db2 subsystem with subsystem ID DBD1 is required. The setup scripts create all required Db2 database objects within this subsystem but do not create the subsystem itself. CICS, IMS, and z/OS Connect runtime instances are provisioned automatically during deployment by the zconfig tool.

6. Access and Security Requirements

Ensure that all of the following access rights are in place before running the setup scripts. If you are unsure about any item, contact your system administrator.

Access Requirement Description
TSO user ID and password Required for authentication and system access
USS access Required to access z/OS UNIX System Services resources
Dataset creation permissions Permission to create and modify datasets
Deployment permissions Permission to deploy application resources
Middleware access Access to CICS, IMS, Db2, IBM MQ, and z/OS Connect, as applicable

Appropriate security definitions must also be configured in RACF or an equivalent security manager before deployment. The exact definitions required depend on your target environment.

Note: Access to z/OS environments, middleware, USS directories, and dataset resources is typically provisioned by your system administrator. If you do not have the required access, contact your administrator before proceeding.

7. External Tool Requirements

7.1 Python Libraries

Two Python libraries are required by the setup and deployment automation. Install them from USS using pip:

BASH 
pip install pyyaml
pip install jinja2

7.2 Gradle

Download the latest supported Gradle binary distribution from the Gradle releases page. After downloading, install it on z/OS USS with the following commands:

BASH 
jar xf gradle-9.5.1-bin.zip
chmod +x gradle-9.5.1/bin/gradle
chtag -tc UTF-8 gradle-9.5.1/bin/gradle

Note: Update the version number in each command to match the release you downloaded. The configured Gradle home must match the gradle_home path set in config.yaml.

8. Verifying Prerequisites

After your system administrator has confirmed all of the above components are in place, run the built-in prerequisite validation script from USS:

BASH 
.setup/setup-common.sh validate-prereqs

This script checks:

  • Version levels of DBB, ZOAU, zconfig, and Wazi Deploy
  • Availability of Git on the USS PATH
  • Network connectivity to GitHub

Resolve any failures reported before proceeding to environment configuration.

9. Environment Configuration

9.1 Configure config.yaml

Edit .setup/config/config.yaml in your local clone of the repository. This single file controls all paths, environment settings, and middleware configuration used during setup, build, and deployment.

Update the values in the global section to match your environment. Template references (e.g., {{ global.sandbox_root }}) resolve automatically and do not need to be edited unless your environment uses non-default paths.

YAML 
# Global properties
# - Shared by middleware/tools
# - Subject to change with middleware/tools updates
global:

  # Sandbox
  sandbox_root: "/usr/local/sandboxes"

  # Application
  app_base_name: "BANKZ"
  app_hlq: "{{ global.app_base_name }}"
  app_short_name: "BOZ"       # Maximum 3 characters
  app_version: "0"
  app_release: "1"
  app_modification: "0"

  # Tools
  java_home:        "{{ sandbox.root }}/tools/J21.0_64"
  python_home:      "/usr/lpp/IBM/cyp/v3r14/pyz"
  zoau_home:        "/usr/lpp/IBM/zoau"
  zconfig_home:     "{{ global.sandbox_root }}/tools/zconfig"
  zcb_home:         "{{ global.sandbox_root }}/tools/zrb/cics-resource-builder-1.0.6"
  dbb_home:         "{{ global.sandbox_root }}/tools/dbb"
  gradle_home:      "{{ global.sandbox_root }}/tools/gradle-9.5.1"
  zcodescan_home:   "/global/opt/pyenv/akf"
  wazideploy_home:  "/global/opt/pyenv/gdp"
  zosconnect_home:  "/usr/lpp/IBM/zosconnect"
  liberty_home:     "/usr/lpp/liberty_zos/25.0.0.9"

  # z/OS System
  zos_admin_user:   "IBMUSER"
  zos_current_user: "${ZOS_CURRENT_USER}"
  zos_ca_label:     "VSICA"
  zos_keyring:      "BOZRING"
  sys_proclib:      "SYS1.PROCLIB"
  tcpip_hlq:        "TCPIP"
  asm_hlq:          "ASM"
  igzxjni2:         "/usr/lpp/IBM/cobol/igyv6r5/lib/igzxjni2.x"
  igy_hlq:          "IGY.V6R5M0"
  fel_hlq:          "FEL"
  ipv_hlq:          "IPV"
  pli_hlq:          "PLI.V6R2M0"
  debug_hlq:        "EQAW"

  # GUI
  zosconnect_http_port:  9080
  zosconnect_https_port: 9444
  zosconnect_task_user:  "{{ global.zos_admin_user }}"

  # Frontend
  frontend_http_port:  9081
  frontend_https_port: 9445
  frontend_task_user:  "{{ global.zos_admin_user }}"

  # CICS
  cics_hlq:     "CICSTS63"
  cics_uss_dir: "/usr/lpp/cicsts/cicsts63"
  cics_sec:     "YES"

  # IMS
  ims_disabled:  "false"
  ims_sys_hlq:   "IMSV15"
  ims_java_dir:  "/usr/lpp/ims/imsjava"
  ims_datastore: "IMS2"
  ims_dfsplex:   "PLEX2"

  # DB2
  db2_hlq:      "DB2V13"
  db2_dsntep:   "DSNTEP13"
  db2_ssid:     "DBD1"
  db2_runlib:   "{{ global.db2_ssid }}.RUNLIB.LOAD"
  db2_sqlid:    "{{ global.zos_current_user }}"
  db2_java_dir: "/usr/lpp/db2d10"
  db2_grants:
    - "CICSUSER"

9.2 Grant Permissions (Non-IBMUSER Accounts Only)

If you are not using the IBMUSER user ID, grant your user ID permission to create Db2 database objects before running the environment setup phase. Run the following command as an administrator, replacing MYUSER with your actual user ID:

BASH 
.setup/setup/grant-perm-user.sh MYUSER

9.3 Set IMS and CICS Credentials

Before running the setup scripts, export the following environment variables in your USS session:

Variable Description
IMS_USER IMS user ID
IMS_PASSWORD IMS password
CICS_USER CICS user ID
CICS_PASSWORD CICS password
BASH 
export IMS_USER=<your_ims_user>
export IMS_PASSWORD=<your_ims_password>

export CICS_USER=<your_cics_user>
export CICS_PASSWORD=<your_cics_password>

9.4 Create the ZCodeScan Configuration File

The static scan stage requires a dedicated ZCodeScan configuration file. This file must be encoded in ISO8859-1 — ZCodeScan cannot read files saved in IBM-1047 or UTF-8.

Create ~/zcs_config_file.yml (or the path specified by zcodescan.config_file in config.yaml):

YAML 
license_server:
  url: https://127.0.0.1:8195
  user: MYUSER
  password: MY_PASSWORD
  verify: false

Note: The password field is automatically encrypted after the first successful scan. You only need to provide it in plain text on first use.
