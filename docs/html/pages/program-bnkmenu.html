BNKMENU – Main Menu Program

BNKMENU is the primary navigation hub of the Bank of Z online banking application. Written in CICS COBOL, it runs under transaction ID OMEN and presents a BMS-driven menu screen to 3270 terminal operators. On each invocation it reads the operator’s single-character selection, validates it, and immediately routes the terminal session to one of eight downstream banking transactions — or re-displays the menu with an error message and audible alarm if the input is invalid. The program is fully pseudo-conversational: it releases CICS resources between every user interaction and re-arms itself via EXEC CICS RETURN TRANSID('OMEN'). All unrecoverable CICS failures are captured, timestamped, and forwarded to the centralised abend handler ABNDPROC before the task is terminated with abend code HBNK.

BNKMENU does not access any database (DB2, VSAM, or IMS). All state is carried purely through the CICS pseudo-conversational mechanism — a 1-byte COMMAREA whose presence (non-zero EIBCALEN) signals a returning session rather than a first-time entry.

BNKMENU is the “front door” of the Bank of Z application. When an operator types OMEN on a 3270 terminal, CICS loads this program. On the very first call (EIBCALEN = 0) the program clears the screen and paints the full menu. On every subsequent call it inspects the AID key and, when ENTER is pressed, reads and validates the single-character action field from the BMS map. A valid selection causes an immediate transfer to the corresponding banking transaction; an invalid selection re-displays the menu with an error message and an audible alarm. PF3 / PF12 displays Session Ended and closes the session cleanly. Any CICS command that does not return DFHRESP(NORMAL) triggers a structured abend sequence that logs diagnostic data via ABNDPROC and terminates the task with code HBNK.

3. Inputs

3.1 Terminal Input — BMS Map Field

The sole data field received from the terminal is ACTIONI, part of the symbolic map BNK1MEI (mapset BNK1MAI, map BNK1ME). It carries the single character the operator typed at the menu prompt:

Value Routed Transaction Banking Function
1 ODCS Display Customer Details
2 ODAC Display Account Details
3 OCCS Create a Customer
4 OCAC Create an Account
5 OUAC Update an Account
6 OCRA Credit / Debit Funds
7 OTFN Transfer Funds
A OCCA Look Up Customer Accounts

3.2 CICS Execute Interface Block (EIB) Fields

These values are injected automatically by CICS at every program entry:

EIB Field Purpose
EIBCALEN 0 on first entry (no prior COMMAREA) → triggers full-screen ERASE
EIBAID AID key pressed — drives the main EVALUATE TRUE dispatch
EIBRESP / EIBRESP2 Response codes from every CICS command; checked after each call
EIBTASKN Current task number — stored in ABND-TASKNO-KEY for diagnostics
EIBTRNID Current transaction ID — stored in ABND-TRANID for diagnostics

3.3 CICS ASSIGN Values

  • ABND-APPLID — populated via EXEC CICS ASSIGN APPLID; identifies the running CICS region in every abend record.
  • ABND-PROGRAM — populated via EXEC CICS ASSIGN PROGRAM; records the executing program name in every abend record.

3.4 CICS Runtime Services

  • EXEC CICS ASKTIME → WS-U-TIME — absolute timestamp used as a unique abend-record key.
  • EXEC CICS FORMATTIME → WS-ORIG-DATE, WS-TIME-NOW — human-readable date (DD/MM/YYYY) and time (HHMMSS) stored in the abend record.

3.5 COMMAREA (Linkage Section)

COBOL 
LINKAGE SECTION.
01  DFHCOMMAREA           PIC X.

A single-byte area passed by CICS on every pseudo-conversational re-entry. Its content is never read; only its existence (EIBCALEN > ZERO) matters — it tells the program this is a returning session, not a first-time entry.

4. Outputs

4.1 Terminal Screen Outputs

The program writes to the terminal exclusively through BMS map BNK1ME (mapset BNK1MAI). Three send modes are used:

Send Mode Flag Value CICS Options When Used
ERASE SEND-ERASE = '1' ERASE FREEKB First entry; MAPFAIL recovery
DATAONLY SEND-DATAONLY = '2' DATAONLY FREEKB Refresh variable fields only
DATAONLY + ALARM SEND-DATAONLY-ALARM = '3' DATAONLY ALARM FREEKB Invalid key / validation error

Key output fields within BNK1MEO:

  • MESSAGEO — feedback line visible to the operator ('Invalid key pressed.' or 'You must enter a valid value (1-7 or A).')
  • ACTIONL — set to -1 to position the cursor on the action input field

A session-end text message is also sent when the operator presses PF3 or PF12:

COBOL 
EXEC CICS SEND TEXT
    FROM(END-OF-SESSION-MESSAGE)
    ERASE
    FREEKB
END-EXEC

END-OF-SESSION-MESSAGE contains the literal 'Session Ended'.

4.2 CICS Transaction Control Outputs

  • Pseudo-conversational re-arm:

    COBOL 
    EXEC CICS RETURN
      TRANSID('OMEN')
      COMMAREA(COMMUNICATION-AREA)
      LENGTH(1)
  END-EXEC

    Re-queues the menu transaction for the next terminal input event.

  • Immediate routing to a banking transaction (example — option 1):

    COBOL 
    EXEC CICS RETURN
      TRANSID('ODCS')
      IMMEDIATE
  END-EXEC

  • Screen clear (CLEAR key):

    COBOL 
    EXEC CICS SEND CONTROL
      ERASE
      FREEKB
  END-EXEC

4.3 Error and Abend Outputs

When any CICS command returns a non-normal response, the program:

  1. Populates ABNDINFO-REC with full diagnostic context.
  2. Links to ABNDPROC to log the record.
  3. Displays WS-FAIL-INFO to the CICS job log.
  4. Issues EXEC CICS ABEND ABCODE('HBNK') NODUMP.

5.2 Pseudo-Conversational Cycle

BNKMENU follows the classic CICS pseudo-conversational pattern. Rather than holding a long-running conversational task open, the program releases all CICS resources after every user interaction and instructs CICS to re-invoke the same transaction (OMEN) the next time the operator presses a key.

sequenceDiagram participant Op as Operator (3270) participant CICS participant BNKMENU participant BankTxn as Banking Transaction Op->>CICS: Type OMEN + ENTER (first time) CICS->>BNKMENU: Invoke (EIBCALEN = 0) BNKMENU->>CICS: SEND MAP BNK1ME (ERASE) CICS-->>Op: Display blank menu BNKMENU->>CICS: RETURN TRANSID(OMEN) COMMAREA(1 byte) note over CICS: Task ends – resources released Op->>CICS: Type '3' + ENTER CICS->>BNKMENU: Invoke (EIBCALEN = 1) BNKMENU->>CICS: RECEIVE MAP BNK1ME → ACTIONI='3' BNKMENU->>BNKMENU: EDIT-MENU-DATA → VALID-DATA = Y BNKMENU->>CICS: RETURN TRANSID(OCCS) IMMEDIATE CICS->>BankTxn: Start OCCS (Create Customer) BankTxn-->>Op: Display Create Customer screen

The key characteristic is the RETURN TRANSID('OMEN') COMMAREA(COMMUNICATION-AREA) LENGTH(1) statement that closes every cycle. The one-byte COMMAREA ensures EIBCALEN is non-zero on re-entry, distinguishing a returning session from a brand-new one.

5.3 Step-by-Step Execution

Step 1 — Entry and first-time detection (PREMIERE / A010)

The program opens with an EVALUATE TRUE block that inspects EIBCALEN and EIBAID:

COBOL 
EVALUATE TRUE
    WHEN EIBCALEN = ZERO
        INITIALIZE BNK1MEO
        MOVE -1       TO ACTIONL
        SET SEND-ERASE TO TRUE
        PERFORM SEND-MAP

    WHEN EIBAID = DFHPA1 OR DFHPA2 OR DFHPA3
        CONTINUE

    WHEN EIBAID = DFHPF3 OR DFHPF12
        PERFORM SEND-TERMINATION-MSG
        EXEC CICS RETURN END-EXEC

    WHEN EIBAID = DFHCLEAR
        EXEC CICS SEND CONTROL ERASE FREEKB END-EXEC
        EXEC CICS RETURN END-EXEC

    WHEN EIBAID = DFHENTER
        PERFORM PROCESS-MENU-MAP

    WHEN OTHER
        MOVE 'Invalid key pressed.' TO MESSAGEO
        SET SEND-DATAONLY-ALARM TO TRUE
        PERFORM SEND-MAP
END-EVALUATE

Step 2 — Pseudo-conversational re-arm

After the EVALUATE, the program always reaches:

COBOL 
EXEC CICS RETURN
    TRANSID('OMEN')
    COMMAREA(COMMUNICATION-AREA)
    LENGTH(1)
    RESP(WS-CICS-RESP)
    RESP2(WS-CICS-RESP2)
END-EXEC

If this command itself fails, the full abend diagnostic sequence is triggered.

Step 3 — Map receive and validation (RECEIVE-MENU-MAP / EDIT-MENU-DATA)

COBOL 
EXEC CICS RECEIVE MAP('BNK1ME')
    MAPSET('BNK1MAI')
    INTO(BNK1MEI)
    RESP(WS-CICS-RESP)
    RESP2(WS-CICS-RESP2)
END-EXEC

EDIT-MENU-DATA then validates ACTIONI:

COBOL 
IF ACTIONI NOT = '1' AND
   ACTIONI NOT = '2' AND
   ACTIONI NOT = '3' AND
   ACTIONI NOT = '4' AND
   ACTIONI NOT = '5' AND
   ACTIONI NOT = '6' AND
   ACTIONI NOT = '7' AND
   ACTIONI NOT = 'A'
    MOVE 'You must enter a valid value (1-7 or A).'
        TO MESSAGEO
    MOVE 'N' TO VALID-DATA-SW
ELSE
    MOVE ACTIONI TO ACTION-ALPHA
END-IF

Step 4 — Transaction routing (INVOKE-OTHER-TXNS / IOT010)

For each valid selection, an immediate CICS RETURN transfers the terminal to the corresponding transaction:

COBOL 
IF ACTIONI = '1'
    EXEC CICS RETURN
        TRANSID('ODCS')
        IMMEDIATE
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
    *> error handling follows ...
END-IF

IF ACTIONI = '2'
    EXEC CICS RETURN
        TRANSID('ODAC')
        IMMEDIATE
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
END-IF
*> ... and so on for options 3–7 and A

Step 5 — Map send (SEND-MAP / SMM010)

COBOL 
IF SEND-ERASE
    EXEC CICS SEND MAP('BNK1ME')
        MAPSET('BNK1MAI')
        FROM(BNK1MEO)
        ERASE
        FREEKB
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
    GO TO SMM999
END-IF

IF SEND-DATAONLY
    EXEC CICS SEND MAP('BNK1ME')
        MAPSET('BNK1MAI')
        FROM(BNK1MEO)
        DATAONLY
        FREEKB
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
    GO TO SMM999
END-IF

IF SEND-DATAONLY-ALARM
    EXEC CICS SEND MAP('BNK1ME')
        MAPSET('BNK1MAI')
        FROM(BNK1MEO)
        DATAONLY
        ALARM
        FREEKB
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
END-IF

Step 6 — Time/date population for diagnostics (POPULATE-TIME-DATE / PTD010)

Called exclusively from error paths to stamp the abend record:

COBOL 
EXEC CICS ASKTIME
    ABSTIME(WS-U-TIME)
END-EXEC

EXEC CICS FORMATTIME
    ABSTIME(WS-U-TIME)
    DDMMYYYY(WS-ORIG-DATE)
    TIME(WS-TIME-NOW)
    DATESEP
END-EXEC

8. Constraints

8.1 Input Validation Constraints

  • ACTIONI must be exactly one character from the set { '1', '2', '3', '4', '5', '6', '7', 'A' }. Any other value sets VALID-DATA-SW = 'N' and blocks transaction dispatch.
  • The EXEC CICS RECEIVE MAP must succeed before validation can proceed. A MAPFAIL response causes an ERASE re-send; any other non-normal response causes an immediate abend.
  • Validation (EDIT-MENU-DATA) must complete before INVOKE-OTHER-TXNS is ever reached — enforced by the IF VALID-DATA guard in PMM010.

8.2 AID Key Constraints

  • Only DFHENTER triggers map processing.
  • DFHPF3 / DFHPF12 unconditionally end the session.
  • DFHCLEAR clears the screen and ends the task without re-arming OMEN.
  • PA keys (DFHPA1–PA3) are silently ignored (CONTINUE).
  • Any unrecognised AID key produces an 'Invalid key pressed.' alarm message.

8.3 Flow Sequencing Constraints

  • The three steps in PROCESS-MENU-MAP (RECEIVE → EDIT → INVOKE) are fixed in order and cannot be rearranged.
  • A SEND-MAP call must always execute at the end of PROCESS-MENU-MAP, regardless of validation outcome, to guarantee the terminal always receives a response.
  • EXEC CICS RETURN TRANSID('OMEN') is always the final statement of the main flow path.
  • Each EXEC CICS RETURN TRANSID(...) IMMEDIATE in INVOKE-OTHER-TXNS transfers control out of the task immediately, so only one downstream transaction can be started per cycle.

8.4 COMMAREA Constraints

  • The COMMAREA passed on the pseudo-conversational return is exactly 1 byte (LENGTH(1) is hard-coded).
  • Its content is never read; only its presence (non-zero EIBCALEN) is tested.

8.5 Screen Send Mode Constraints

  • Exactly one of SEND-ERASE, SEND-DATAONLY, or SEND-DATAONLY-ALARM must be set before SEND-MAP is called. If none is set, SEND-MAP exits silently without sending anything.
  • GO TO SMM999 ensures that once the ERASE or DATAONLY branch executes, the remaining branches are skipped.

8.6 Error and Abend Constraints

  • Every CICS command is individually guarded by a RESP/RESP2 check. Any non-normal response is fatal, with the single exception of MAPFAIL on RECEIVE MAP.
  • The abend code is always 'HBNK'; NODUMP suppresses a storage dump.
  • ABNDINFO-REC must be fully populated (including POPULATE-TIME-DATE) before EXEC CICS LINK to ABNDPROC is issued.
  • ABND-FREEFORM is capped at 600 characters; overflow is silently truncated.

8.7 Known Coding Anomaly

The STRING statement that builds ABND-TIME references WS-TIME-NOW-GRP-MM (minutes) twice instead of using WS-TIME-NOW-GRP-SS (seconds) in the seconds slot. As a result, all abend timestamps are recorded as HH:MM:MM rather than HH:MM:SS. This is a defect that reduces diagnostic timestamp precision but does not affect program operation.

9. Error Handling

9.1 Input Validation Errors

Two classes of user-input error are handled gracefully (no abend):

Invalid menu selection:

CODE 
ACTIONI = 'X'  →  VALID-DATA-SW = 'N'
                   MESSAGEO = 'You must enter a valid value (1-7 or A).'
                   SEND-DATAONLY-ALARM → audible alarm + data refresh

Unrecognised AID key:

CODE 
EIBAID ≠ any handled key  →  MESSAGEO = 'Invalid key pressed.'
                               SEND-DATAONLY-ALARM → audible alarm + data refresh

In both cases the menu remains on screen, the cursor returns to the ACTION field, and the operator can correct their input.

9.2 Terminal I/O Errors

Failing Command RESP Condition Action
EXEC CICS RECEIVE MAP MAPFAIL Recoverable — re-send map with ERASE; no abend
EXEC CICS RECEIVE MAP Any other non-normal Fatal — full abend sequence ('RMM010 - RECEIVE MAP FAIL')
EXEC CICS SEND MAP (ERASE) Non-normal Fatal — 'SMM010 - SEND MAP ERASE FAIL'
EXEC CICS SEND MAP (DATAONLY) Non-normal Fatal — 'SMM010 - SEND MAP DATAONLY FAIL'
EXEC CICS SEND MAP (DATAONLY ALARM) Non-normal Fatal — 'SMM010 - SEND MAP DATAONLY ALARM FAIL'
EXEC CICS SEND TEXT Non-normal Fatal — 'STM010 - SEND TEXT FAIL'

9.3 Transaction Dispatch Errors

Each of the eight EXEC CICS RETURN TRANSID(...) IMMEDIATE commands is individually guarded. A failure on, for example, routing to ODCS produces a free-form diagnostic string:

CODE 
'IOT010 - RETURN TRANSID(ODCS) FAIL. EIBRESP=nnn RESP2=nnn'

The same pattern applies to all eight routing options.

9.4 Pseudo-Conversational Return Error

If the EXEC CICS RETURN TRANSID('OMEN') at the end of the main flow fails:

CODE 
'A010 - RETURN TRANSID(MENU) FAIL. EIBRESP=nnn RESP2=nnn'

10. Worked Examples

10.1 Example 1 — First Entry (No COMMAREA): Menu Displayed for the First Time

Input state:

  • EIBCALEN = 0 (no prior session)
  • No key pressed yet

Expected output:

  • Map BNK1ME sent with ERASE — full blank menu drawn on terminal
  • Cursor positioned on the ACTION field (ACTIONL = -1)
  • EXEC CICS RETURN TRANSID('OMEN') COMMAREA(...) LENGTH(1) re-arms the session

How it works: EIBCALEN = ZERO matches the first WHEN clause. BNK1MEO is initialised with LOW-VALUE, SEND-ERASE is set to TRUE, and SEND-MAP issues EXEC CICS SEND MAP … ERASE FREEKB. The terminal receives a completely cleared screen with the menu layout. CICS is then instructed to re-invoke OMEN on the next keypress.

10.2 Example 2 — Valid Selection '1' (Display Customer Details)

Input state:

  • EIBCALEN = 1 (returning pseudo-conversational cycle)
  • EIBAID = DFHENTER
  • ACTIONI = '1'

Expected output:

  • CICS immediately routes the terminal session to transaction ODCS
  • OMEN is no longer active; ODCS takes over the terminal

How it works: DFHENTER routes execution into PROCESS-MENU-MAP. After a successful RECEIVE MAP, EDIT-MENU-DATA confirms '1' is valid, sets VALID-DATA-SW = 'Y', and INVOKE-OTHER-TXNS fires EXEC CICS RETURN TRANSID('ODCS') IMMEDIATE.

10.3 Example 3 — Invalid Selection (Validation Failure)

Input state:

  • EIBCALEN = 1
  • EIBAID = DFHENTER
  • ACTIONI = 'X'

Expected output:

  • Screen updated with: You must enter a valid value (1-7 or A).
  • Audible alarm triggered at the terminal
  • Cursor repositioned on the ACTION field
  • EXEC CICS RETURN TRANSID('OMEN') re-arms — operator must try again

How it works: In EDIT-MENU-DATA, 'X' matches none of the accepted values, so VALID-DATA-SW = 'N' and the error message is placed in MESSAGEO. IF VALID-DATA is false so INVOKE-OTHER-TXNS is skipped. Back in PMM010, SEND-DATAONLY-ALARM is set and SEND-MAP issues EXEC CICS SEND MAP … DATAONLY ALARM FREEKB.

10.4 Example 4 — Operator Presses PF3 (Session Termination)

Input state:

  • EIBCALEN = 1
  • EIBAID = DFHPF3

Expected output:

  • Terminal displays Session Ended on a cleared screen
  • CICS task ends unconditionally (EXEC CICS RETURN with no TRANSID)

How it works: The WHEN EIBAID = DFHPF3 OR DFHPF12 branch calls SEND-TERMINATION-MSG, which issues EXEC CICS SEND TEXT FROM(END-OF-SESSION-MESSAGE) ERASE FREEKB. The literal 'Session Ended' is written to the cleared terminal screen. A bare EXEC CICS RETURN (no TRANSID) then terminates the task — no further transaction is queued.
