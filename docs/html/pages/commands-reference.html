Commands Reference

A comprehensive reference of all CLI commands, scripts, and automation utilities available in Bank of Z. This document covers the syntax, options, and usage examples for every command used when setting up, configuring, developing, and automating the Bank of Z application on z/OS.

Whether you are a new developer onboarding to the project or an experienced mainframe engineer, this reference provides a single point of truth for all command-line interactions across the Bank of Z ecosystem — from local workstation tooling to z/OS USS environment verification and CI/CD automation scripts.

1. System Architecture

The Bank of Z command and automation landscape spans multiple layers: the developer’s local workstation, the Zowe CLI middleware layer, and the z/OS USS remote environment. Understanding how these layers interact is essential for effective use of the commands documented below.

graph TD subgraph Local Workstation A[Developer Machine] B[VS Code / IDE] C[Git CLI] D[Node.js / npm] E[Java Runtime] F[Zowe CLI] end subgraph Middleware G[z/OSMF] H[RSE API Plugin] end subgraph "z/OS USS Environment" I[USS Shell] J[DBB - Dependency Based Build] K[Java on z/OS] L[Git on USS] end B --> F F --> H H --> G G --> I A --> C C -->|push/pull| L I --> J I --> K I --> L

How the layers connect:

  • The local workstation hosts the developer’s IDE (VS Code), Git client, Node.js/npm, Java, and Zowe CLI.
  • Zowe CLI communicates with z/OS through z/OSMF and the RSE API Plugin, bridging the gap between local development and the mainframe.
  • On the z/OS USS environment, build and deployment activities are executed using DBB, Java, and Git, orchestrated by automation workflow scripts.

3. Zowe CLI Commands

Use Zowe CLI to connect to z/OS systems and support the Zowe CLI workflow. Zowe CLI is the primary interface between the developer workstation and the mainframe.

3.1 Verify Installation

Displays the installed Zowe CLI version. Run this first to confirm Zowe CLI is properly installed.

BASH 
zowe --version

3.2 Install the RSE API Plug-in

Installs the RSE API plugin required by the Bank of Z setup workflow. This plugin provides additional capabilities for interacting with z/OS resources.

BASH 
zowe plugins install @zowe/rse-api-for-zowe-cli

3.3 Create a z/OSMF Profile

Creates a z/OSMF connection profile that stores your host, port, and user credentials for repeated use.

BASH 
zowe profiles create zosmf-profile myprofile \
  --host your-zos-host \
  --port 443 \
  --user your-userid
Option Description
--host The hostname or IP address of your z/OS system
--port The z/OSMF port (typically 443)
--user Your z/OS user ID

3.4 Verify Connectivity

Verifies connectivity to the configured z/OSMF instance. Use this after creating a profile to confirm the connection is working.

BASH 
zowe zosmf check status

3.5 List Available Profiles

Displays all configured z/OSMF profiles.

BASH 
zowe profiles list zosmf

3.6 Set a Default Profile

Sets the default z/OSMF profile so that subsequent commands use it automatically.

BASH 
zowe profiles set-default zosmf myprofile

4. Git Commands

Use Git to manage source code changes and collaborate with other contributors on the Bank of Z project.

4.1 Clone a Repository

Creates a local copy of a remote repository.

BASH 
git clone <repository-url>

4.2 Create a Branch

Creates and switches to a new feature branch. Follow the naming convention feature/<description>.

BASH 
git checkout -b feature/my-change

4.3 View Status

Displays modified, staged, and untracked files in the working directory.

BASH 
git status

4.4 Commit Changes

Stages all changes and commits them with a descriptive message.

BASH 
git add .
git commit -m "Describe your change"

4.5 Push Changes

Pushes committed changes from your local branch to the remote repository.

BASH 
git push origin <branch-name>

5. Setup Verification Commands

Use these commands on the local developer workstation to verify that all required tools are installed and available before beginning Bank of Z development.

5.1 Node.js

BASH 
node -v

Displays the installed Node.js version.

5.2 npm

BASH 
npm -v

Displays the installed npm version.

5.3 Git

BASH 
git --version

Displays the installed Git version.

5.4 Java

BASH 
java -version

Displays the installed Java version.

Tip: Ensure all tool versions meet the minimum requirements documented in the Bank of Z setup guide before proceeding with environment configuration.

6. USS Verification Commands

Use these commands when validating the z/OS Unix System Services (USS) environment. These checks confirm that the remote z/OS system has the necessary tooling for builds and deployments.

6.1 Verify Git Availability

Verifies that Git is installed and accessible in the USS environment.

BASH 
which git
git --version

6.2 Verify DBB Installation

Verifies that the Dependency Based Build (DBB) installation path is accessible.

BASH 
ls $DBB_HOME/lib

6.3 Verify Java Configuration

Verifies that the configured Java runtime is available on USS.

BASH 
$JAVA_HOME/bin/java -version

The following scripts are used by the Bank of Z automation workflows to orchestrate setup, build, and deployment activities across local and remote environments.

7.1 Script Reference

Script Purpose Runs On
setup-local.sh Initiates setup activities from the developer workstation Local
setup-common.sh Performs environment setup on z/OS USS z/OS USS
pipeline-local.sh Initiates build and deployment processing Local
pipeline-remote.sh Runs build and deployment activities on z/OS USS z/OS USS

7.2 Zowe CLI Workflow

The Zowe CLI workflow can be completed through a VS Code task or by running setup-local.sh directly.

Running via VS Code:

  1. Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P).
  2. Run Tasks: Run Task.
  3. Select Setup Bank of Z Environment.

Running directly:

BASH 
./setup-local.sh

7.3 GRUB Workflow

The GRUB workflow synchronizes local changes to USS and runs the Bank of Z setup process. Refer to the GRUB Workflow documentation for environment-specific configuration and run procedures.

8. Documentation Scripts

Scripts for managing and converting Bank of Z project documentation.

8.1 convert_dita_to_md.py

Converts DITA XML files to Markdown format and generates a dynamic Table of Contents.

Prerequisites:

BASH 
pip3 install pyyaml

Usage:

BASH 
python3 scripts/convert_dita_to_md.py

What it does:

  1. Scans the Docs/ folder for DITA files.
  2. Converts DITA XML to Markdown format.
  3. Creates an organized folder structure in docs/.
  4. Generates _data/toc.yml automatically.
  5. Creates index pages for each section.

Example — before and after:

BASH 
# Before running
Docs/com.ibm.tutorials.doc/getting-started.dita

# After running
docs/tutorials/getting-started.md
docs/tutorials/index.md
_data/toc.yml (updated)

8.2 Adding New Documentation Scripts

When adding new scripts to the documentation toolchain, follow these conventions:

Convention Example
Use descriptive names convert_dita_to_md.py
Use underscores for spaces generate_pdf_docs.py
Include .py extension validate_links.py

Each script should include:

  • A docstring explaining its purpose
  • Usage instructions
  • Requirements and dependencies
  • Example output
