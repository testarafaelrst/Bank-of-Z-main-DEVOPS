Deployment Methods

1. Overview

Deploying Bank of Z provisions a complete application environment on z/OS. The environment includes CICS, IMS, z/OS Connect, a Liberty frontend server, and all application data. Once you have cloned the repository and configured it for your environment, the process is fully automated.

Bank of Z supports three deployment workflows. All three run the same deployment stages and produce the same deployed environment. They differ in how the source code reaches z/OS USS and how the setup scripts are started.

Workflow How code reaches z/OS USS SSH to USS required Push to remote required Best suited for
Direct USS Cloned on USS by the user Yes Not applicable (cloned from GitHub) The most transparent option, with each stage run manually
Zowe CLI The script clones your pushed branch from GitHub onto USS No Yes Local development without SSH access
GRUB GRUB syncs local files to USS No No Fast iteration on uncommitted changes

1.1 Key Characteristics

  • Same stages everywhere. Each workflow runs validate-prereqs, environment, and install-bank-of-z. Each stage is a subcommand of .setup/setup-common.sh.
  • Same configuration file. You edit .setup/config/config.yaml for your environment.
  • Same duration. The initial build and deployment typically take about 15 to 20 minutes.
  • Same prerequisite. A pre-existing Db2 subsystem (DBD1) is required. All other middleware is provisioned automatically.

2. System Architecture

The deployment architecture has two sides: your local machine (or an SSH session) and z/OS USS. Tooling on the local side (Zowe CLI or GRUB) moves the source to USS and starts setup-remote.sh. That script drives setup-common.sh through the three stages. The stages provision the runtime and deploy the application artifacts.

2.1 Component Architecture

2.2 Components and Responsibilities

Component Responsibility
.setup/config/config.yaml Environment-specific configuration, including required tool versions
.setup/setup-local.sh Zowe CLI entry point that runs from the local machine
.setup/setup-remote.sh Runs on USS and invokes the three setup stages (Zowe CLI and GRUB)
.setup/setup-common.sh Stage dispatcher with the subcommands validate-prereqs, environment, install-bank-of-z, and verify-installation
Zowe RSE API Creates the USS workspace directory (Zowe CLI workflow)

Wazi Deploy Deploys the packaged archive to the CICS and IMS environments

3. Deployment Stages

All three workflows run the same three stages.

graph LR A[Stage 1: Validate prerequisites] --> B[Stage 2: Provision middleware] B --> C[Stage 3: Build and deploy] C --> D[Verify deployment]

3.1 Stage 1: Validate Prerequisites

BASH 
.setup/setup-common.sh validate-prereqs

This stage verifies that all required tools are installed on z/OS USS at the versions specified in config.yaml. The tools checked are:

  • DBB
  • ZOAU
  • zconfig
  • Wazi Deploy
  • Java
  • Git
  • Network connectivity to GitHub

3.2 Stage 2: Provision Middleware

BASH 
.setup/setup-common.sh environment

This stage provisions the complete application runtime from scratch. It is fully automated and performs these steps in sequence:

  1. Stops any existing Bank of Z tasks (CICS, IMS, z/OS Connect, frontend).
  2. Cleans up existing application datasets.
  3. Clones the IBM DBB accelerators repository from GitHub.
  4. Copies the zBuilder build framework.
  5. Creates Db2 database tables.
  6. Provisions a CICS region using zconfig.
  7. Provisions an IMS region using zconfig.
  8. Creates IMS database objects.
  9. Starts the IMS Bank of Z message processing regions.
  10. Creates and starts a z/OS Connect server.
  11. Creates and starts a frontend Liberty server.

Note: This stage requires a pre-existing Db2 subsystem (DBD1). All other middleware is provisioned automatically.

3.3 Stage 3: Build and Deploy

BASH 
.setup/setup-common.sh install-bank-of-z

This stage builds the application from source and deploys the generated artifacts to the provisioned runtime:

  1. Runs a full DBB build for all application sources: COBOL, PL/I, Assembler, BMS, Java, and z/OS Connect APIs.
  2. Packages the build outputs into a deployment archive.
  3. Runs Wazi Deploy to deploy the archive to the CICS and IMS environments.
  4. Populates Db2 with application test data.
  5. Populates the IMS database with application test data.

The initial build and deployment typically take about 15 to 20 minutes.

3.4 Stage Data Flow

graph TD Src[Application Sources] --> Build[Full DBB Build] Build --> Out[Build Outputs] Out --> Archive[Deployment Archive] Archive --> Wazi[Wazi Deploy] Wazi --> CICSEnv[CICS Environment] Wazi --> IMSEnv[IMS Environment] Test[Test Data] --> Db2Data[(Db2 Tables)] Test --> IMSData[(IMS Database)]

4. Direct USS Deployment

Direct USS deployment is the most transparent option. You connect to z/OS over SSH and run each command yourself, so you can observe every stage.

4.1 Prerequisites

  • SSH access to your z/OS system
  • Git installed on z/OS USS
  • A z/OS environment that meets the documented prerequisites

4.2 Step-by-Step Procedure

Step 1: SSH to z/OS

BASH 
ssh user@your-zos-host

Step 2: Clone the repository

Choose a working directory on USS. You specify this path in the configuration file in the next step.

BASH 
export BANK_OF_Z_WORK_DIR=/usr/local/sandboxes/bank-of-z
mkdir -p $BANK_OF_Z_WORK_DIR
cd $BANK_OF_Z_WORK_DIR
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

Step 3: Edit the configuration file

BASH 
vi .setup/config/config.yaml

Step 4: Validate prerequisites

BASH 
.setup/setup-common.sh validate-prereqs

Resolve any failures before continuing.

Step 5: Provision middleware

BASH 
.setup/setup-common.sh environment

This takes several minutes.

Step 6: Build and deploy

BASH 
.setup/setup-common.sh install-bank-of-z

Note: Warnings related to the YAML scanner and chown failures are expected and do not indicate a problem.

Step 7: Verify the deployment

Open the frontend in a browser.

HTTP:

BASH 
http://<your-zos-host>:9081/admin.html

HTTPS:

BASH 
https://<your-zos-host>:9445/admin.html

Step 8: Run post-install verification tests

BASH 
.setup/setup-common.sh verify-installation

This runs the integration test suite in tests/ against the deployed application. The tests exercise the CICS and IMS API paths and report a pass/fail result for each. All tests must pass before the installation is considered complete.

4.3 Direct USS Sequence

sequenceDiagram participant Dev as Developer participant USS as z/OS USS participant GH as GitHub Dev->>USS: ssh user@your-zos-host Dev->>USS: mkdir and cd BANK_OF_Z_WORK_DIR USS->>GH: git clone Bank-of-Z GH-->>USS: Repository contents Dev->>USS: vi .setup/config/config.yaml Dev->>USS: setup-common.sh validate-prereqs Dev->>USS: setup-common.sh environment Dev->>USS: setup-common.sh install-bank-of-z Dev->>USS: setup-common.sh verify-installation USS-->>Dev: Pass/fail test results

5. Zowe CLI Deployment

With the Zowe CLI workflow, you clone the repository locally. A script then clones your current GitHub branch onto z/OS USS and runs all three setup stages automatically. No SSH access to USS is required.

Note: The script clones your branch from GitHub on USS. Push your branch to the remote before running the script. Local commits that have not been pushed are not included.

5.1 Prerequisites

  • A z/OS environment that meets the documented prerequisites
  • Zowe CLI setup is complete: Zowe CLI is installed, the RSE API plug-in is installed, and your Zowe profile is configured

5.2 Step-by-Step Procedure

Step 1: Clone the repository locally

BASH 
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

Step 2: Edit the configuration file

Open .setup/config/config.yaml in your local editor and update it for your environment.

Step 3: Push your branch

BASH 
git add .setup/config/config.yaml
git commit -m "Configure for my environment"
git push

Step 4: Run the setup script

BASH 
bash .setup/setup-local.sh

Alternatively, in Visual Studio Code, select Command Palette → Tasks: Run Task → Setup Bank of Z Environment.

Step 5: Verify the deployment

CODE 
http://<your-zos-host>:9080/bank-frontend-vanilla

5.3 What Runs Automatically

  1. The script creates the USS workspace directory by using the Zowe RSE API.
  2. It clones your current branch from GitHub to z/OS USS.
  3. It invokes setup-remote.sh on USS, which runs validate-prereqs, environment, and install-bank-of-z.

Logs are written to /tmp/remote-setup.log on your local machine. Warnings related to the YAML scanner and chown failures are expected.

5.4 Zowe CLI Sequence

sequenceDiagram participant Dev as Developer participant Local as setup-local.sh participant RSE as Zowe RSE API participant GH as GitHub participant USS as z/OS USS Dev->>GH: git push (configured branch) Dev->>Local: bash .setup/setup-local.sh Local->>RSE: Create USS workspace directory RSE-->>Local: Directory created Local->>USS: Clone current branch from GitHub USS->>GH: git clone branch GH-->>USS: Branch contents Local->>USS: Invoke setup-remote.sh USS->>USS: validate-prereqs USS->>USS: environment USS->>USS: install-bank-of-z USS-->>Local: Output logged to /tmp/remote-setup.log

6. GRUB Deployment

GRUB syncs your local file changes to z/OS USS and triggers the setup scripts automatically. You do not need to commit or push your changes before deploying.

6.1 Prerequisites

  • A z/OS environment that meets the documented prerequisites
  • GRUB setup is complete: GRUB is installed and configured with the Bank of Z remote path and post-sync hook

6.2 Step-by-Step Procedure

Step 1: Clone the repository locally

BASH 
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

Step 2: Edit the configuration file

Open .setup/config/config.yaml in your local editor. You do not need to commit your changes, because GRUB syncs the file as-is.

Step 3: Trigger a GRUB sync

Trigger a sync from your local machine, using the command or UI action for your GRUB installation. GRUB transfers only the files that changed since the previous sync.

Step 4: Verify the deployment

CODE 
http://<your-zos-host>:9080/bank-frontend-vanilla

6.3 What Runs Automatically

After the sync completes, the configured post-sync hook runs setup-remote.sh on z/OS USS. The script runs these stages:

  • validate-prereqs: verifies that all required tools are installed.
  • environment: provisions Db2, CICS, IMS, z/OS Connect, and the frontend server.
  • install-bank-of-z: builds the application, deploys it with Wazi Deploy, and populates the test data.

The initial deployment typically takes 15 to 20 minutes. Later syncs are typically faster because only changed files are transferred.

6.4 GRUB Sequence

sequenceDiagram participant Dev as Developer participant GRUB as GRUB participant USS as z/OS USS Dev->>Dev: Edit .setup/config/config.yaml Dev->>GRUB: Trigger sync GRUB->>USS: Transfer changed files USS-->>GRUB: Sync complete GRUB->>USS: Post-sync hook runs setup-remote.sh USS->>USS: validate-prereqs USS->>USS: environment USS->>USS: install-bank-of-z USS-->>Dev: Deployed environment ready

8. Incremental Builds

After the initial deployment, most day-to-day development can use an incremental build and deploy instead of rebuilding the entire environment.

The incremental workflow rebuilds and deploys only the application components affected by your source code changes. This reduces build time and preserves the existing runtime environment.

For the incremental workflows, see the Zowe CLI Workflow and GRUB Workflow pages.

9. Notes and Troubleshooting

  • Warnings related to the YAML scanner and chown failures are expected and do not indicate a problem.
  • If validate-prereqs reports failures, resolve them before running later stages.
  • For the Zowe CLI workflow, make sure your branch is pushed. Unpushed local commits are not deployed.
  • For the Zowe CLI workflow, check /tmp/remote-setup.log on your local machine for the run output.
  • For HTTPS access and certificate configuration, see the “Accessing Bank of Z over HTTPS” section of the project README.
