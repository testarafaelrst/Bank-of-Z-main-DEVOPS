Commands & Scripts Reference

This reference guide documents the commands, command-line interfaces (CLIs), verification procedures, automation workflows, and helper scripts used to configure, build, deploy, and maintain the Bank of Z project across local developer workstations and z/OS UNIX System Services (USS) environments.

1. Overview

Bank of Z relies on a hybrid tooling model combining local developer tools (Node.js, Git, Zowe CLI, VS Code) and mainframe-side components (z/OSMF, RSE API, z/OS UNIX System Services, IBM Dependency Based Build, and Java).

This guide provides command-level references for:

  • Local environment verification (Node.js, npm, Git, Java)
  • Zowe CLI configuration and profile management
  • Git version control operations
  • z/OS USS environment verification (DBB, Java, Git)
  • Core workflow scripts for environment setup and CI/CD pipelines
  • Documentation build and migration utilities

2. System Architecture and Tooling

The Bank of Z automation architecture links local developer workstations to remote z/OS systems using RESTful APIs, CLI tools, and automation scripts.

Architecture Description

  1. Workstation Layer: Developers interact with source code and automation tasks through VS Code or terminal shells, executing local shell scripts (setup-local.sh, pipeline-local.sh) and documentation tools (convert_dita_to_md.py).
  2. Connection Layer: Zowe CLI interfaces with z/OSMF and IBM RSE API endpoints over secure HTTPS connections, passing commands, credentials, and triggering USS actions.
  3. z/OS USS Execution Layer: Automated scripts (setup-common.sh, pipeline-remote.sh) run within z/OS USS, invoking IBM Dependency Based Build (DBB) and Java runtimes to compile and deploy mainframe artifacts.

3. Workstation Prerequisites & Verification Commands

Before executing Bank of Z workflows, verify that all workstation prerequisites are properly installed.

3.1. Node.js Verification

Verify the Node.js runtime environment version:

BASH 
node -v

3.2. npm Verification

Verify the Node Package Manager (npm) version:

BASH 
npm -v

3.3. Git CLI Verification

Check the installed Git version on your workstation:

BASH 
git --version

3.4. Java Runtime Verification

Verify the local Java runtime version:

BASH 
java -version

4. Zowe CLI Commands

Zowe CLI manages remote connectivity and operational interaction with z/OS host systems.

4.1. Verify Installation

Display the installed Zowe CLI core version:

BASH 
zowe --version

4.2. Install the RSE API Plug-in

Install the IBM Remote System Explorer (RSE) API plug-in required by Bank of Z setup workflows:

BASH 
zowe plugins install @zowe/rse-api-for-zowe-cli

4.3. Create a z/OSMF Profile

Create a profile containing host, port, and authentication credentials for z/OSMF:

BASH 
zowe profiles create zosmf-profile myprofile \
  --host your-zos-host \
  --port 443 \
  --user your-userid

4.4. Verify Connectivity

Test the network and authentication path to the target z/OSMF instance:

BASH 
zowe zosmf check status

4.5. List Available Profiles

List all configured z/OSMF connection profiles:

BASH 
zowe profiles list zosmf

4.6. Set a Default Profile

Assign a specific profile as the default for CLI execution:

BASH 
zowe profiles set-default zosmf myprofile

5. Git Version Control Commands

Standard Git operations manage source changes across local and remote repositories.

5.1. Clone a Repository

Clone the Bank of Z repository to your local workstation:

BASH 
git clone <repository-url>

5.2. Create and Switch Branches

Create a feature branch for isolated changes:

BASH 
git checkout -b feature/my-change

5.3. View Working Tree Status

Inspect modified, staged, and untracked files:

BASH 
git status

5.4. Stage and Commit Changes

Stage tracked modifications and record them to local history:

BASH 
git add .
git commit -m "Describe your change"

5.5. Push Changes to Remote

Publish local branch commits to the remote repository:

BASH 
git push origin <branch-name>

6. z/OS UNIX System Services (USS) Verification

Verify the availability of key utilities directly inside the z/OS USS environment.

6.1. Verify Git Availability in USS

Ensure the Git binary is configured in the USS path:

BASH 
which git
git --version

6.2. Verify IBM Dependency Based Build (DBB)

Verify that the DBB installation directory and libraries are accessible:

BASH 
ls $DBB_HOME/lib

6.3. Verify z/OS Java Configuration

Verify the active Java runtime environment configured under $JAVA_HOME:

BASH 
$JAVA_HOME/bin/java -version

7. Workflow & Automation Scripts

7.1. Workflow Scripts Inventory

Bank of Z utilizes paired local and remote scripts to automate setup, build, and deployment processes:

Script Execution Target Purpose
setup-local.sh Local Workstation Initiates setup activities from the developer workstation via Zowe CLI
setup-common.sh z/OS USS Performs environment setup and configuration directly on z/OS USS
pipeline-local.sh Local Workstation Initiates build and deployment processing pipelines from the client
pipeline-remote.sh z/OS USS Runs build, compilation, and deployment activities on z/OS USS

7.3. Zowe CLI Workflow Execution

The Zowe CLI workflow configures and validates the environment from the developer workstation. It can be triggered in two ways:

  1. Via VS Code Tasks:

    • Open the Command Palette (Ctrl+Shift+P or Cmd+Shift+P).
    • Run Tasks: Run Task.
    • Select Setup Bank of Z Environment.

  2. Via Command Line:

    BASH 
    ./setup-local.sh

7.4. GRUB Workflow Execution

The GRUB workflow synchronizes local code changes to z/OS USS and executes the Bank of Z setup and build cycle. Refer to the GRUB workflow guides for specific target environment parameters and runtime procedures.

8. Documentation Utility Scripts

Documentation maintenance utilities support automated conversion and navigation generation.

8.1. DITA to Markdown Conversion (convert_dita_to_md.py)

The scripts/convert_dita_to_md.py script transforms legacy DITA XML documentation into Markdown and auto-generates dynamic table-of-contents files.

Purpose & Operation

  1. Scans the Docs/ directory for .dita source files.
  2. Converts DITA XML content to standard Markdown formatting.
  3. Creates an organized target directory structure under docs/.
  4. Generates _data/toc.yml automatically for site navigation.
  5. Generates section index pages (index.md) for each topic folder.

Requirements

Install required Python dependencies:

BASH 
pip3 install pyyaml

Usage

Execute the script from the repository root:

BASH 
python3 scripts/convert_dita_to_md.py

Transformation Example

  • Source input: Docs/com.ibm.tutorials.doc/getting-started.dita
  • Generated output:
    • docs/tutorials/getting-started.md
    • docs/tutorials/index.md
    • _data/toc.yml (updated)

8.2. Guidelines for Adding New Documentation Scripts

When adding documentation helper scripts to the scripts/ directory:

  • Naming Conventions: Use lowercase descriptive names with underscores (e.g., convert_dita_to_md.py, generate_pdf_docs.py) and a .py extension.
  • Documentation Standards: Include docstrings explaining the script’s purpose, usage syntax, required dependencies, and expected outputs.
