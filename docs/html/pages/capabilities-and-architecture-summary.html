Key Capabilities & Architecture Summary

Bank of Z is an enterprise sample application that demonstrates core retail banking capabilities integrated with modern IBM Z development practices, hybrid transaction processing, and contemporary DevOps toolchains.

1. Overview

Bank of Z showcases how modern web-based frontends connect seamlessly to robust IBM Z backend systems. The application allows users to perform standard retail banking transactions through a unified interface while routing workloads dynamically across diverse mainframe transaction managers and databases.

Key business and technical capabilities highlighted include:

  • Banking operations: Core workflows including account management, customer profile management, deposits, withdrawals, fund transfers, and historical transaction processing.
  • Hybrid transaction processing: Dynamic routing of transactions across both Customer Information Control System (CICS) and IMS Transaction Manager (IMS TM) backends without impacting the end-user experience.
  • Modern development workflows: End-to-end modern developer workflows utilizing Git, IBM Dependency Based Build (DBB), build tools such as Bob and zBuilder, automated CI/CD pipelines, VS Code integration, and GRUB development practices.
  • Enterprise integration: Cohesive integration bridging RESTful APIs via z/OS Connect, messaging via IBM MQ, and data storage across Db2 for z/OS and IMS DB.

2. System Architecture

The Bank of Z architecture adopts a hybrid multi-tier structure where browser-based clients interact with z/OS backend services via REST APIs managed by z/OS Connect. Workloads are delegated to either CICS or IMS TM for core business logic execution, persisting records in Db2 or IMS DB, and publishing integration events to external systems using IBM MQ.

2.1. Architectural Layers

The architecture spans several integrated layers:

  1. Presentation Layer: Browser-based user interface providing a unified customer experience for all banking workflows.
  2. API & Integration Layer: z/OS Connect transforms RESTful HTTP/JSON requests from the web interface into optimized mainframe service calls.
  3. Transaction Processing Layer: Dual transaction processing environments (CICS and IMS TM) host backend business logic and process operations based on the configured path.
  4. Data Persistence Layer: Shared enterprise data stores combining relational storage (Db2 for z/OS) and hierarchical databases (IMS DB).
  5. Asynchronous Integration Layer: IBM MQ provides reliable message-oriented middleware for event streaming and communication with external downstream systems.

3. Transaction Flow and Hybrid Processing

The application demonstrates hybrid routing where transaction requests are routed either to CICS or IMS TM based on user context or transaction configuration.

3.1. Hybrid Path Execution Details

  • Request Ingress: Client actions (such as account lookups, deposits, or fund transfers) initiate standard JSON REST calls to z/OS Connect.
  • Dynamic Routing: z/OS Connect delegates execution to the selected transaction engine (CICS or IMS TM).
  • Data Access & State Management: Business programs access relational data in Db2 for z/OS or hierarchical records in IMS DB.
  • Asynchronous Messaging: Upon transaction commitment, operational records and notifications are posted to IBM MQ queues for consumption by downstream and external services.

4.1. DevOps Components

  • Source Control Management: Git-based repository management enabling standard branching, pull requests, and distributed version control.
  • IDE Integration: Developer workstations equipped with VS Code and standard plugins for code editing, linting, and local testing.
  • Build Automation: IBM Dependency Based Build (DBB) combined with build frameworks such as Bob and zBuilder to analyze source dependencies and compile changed artifacts.
  • Deployment Pipelines: Automated deployment pipelines managing target environments across CICS, IMS, and z/OS Connect artifacts.
