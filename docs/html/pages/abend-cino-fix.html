Fixing the CINO Abend

This page documents the diagnosis and remediation of abend code 4038 (IOERR). It occurred in transaction OMEN (program BNKMENU) in CICS region CICSAOR1. The cause was a closed Transient Data queue (TDQUEUE) named CINO.

1. Overview

1.1 Incident Summary

Field Value
JOBID STC02872
CICS Region CICSAOR1
Transaction OMEN
Program BNKMENU
Abend Code 4038 (IOERR)
Date/Time 24/10/2026 17:14:56 and 17:15:33
User RAFAELT (terminals 0189/0190)

1.2 Root Cause

The TDQUEUE CINO is a CICS Transient Data output queue. It was closed in region CICSAOR1. Program BNKMENU tried to open it with SET TDQUEUE(CINO) OPENSTATUS(OPEN) and received:

CODE 
RESP(IOERR) RESP2(14)

The source analysis interprets RESP2(14) as SYSIDERR. It reads this as meaning the VSAM dataset associated with the TDQUEUE was not found in the catalog. The failed open caused CICS to abend the transaction with code 4038 and issue message DFHAC2236.

1.3 Resolution at a Glance

  • The debug sessions were cleaned up. The terminals were terminated by the system and no pending profiles remain for RAFAELT.
  • The TDQUEUE must be reopened by a CICS administrator. RAFAELT lacks RACF UPDATE authority on the required OPERCMDS resource.
  • After the reopen, verify the queue state and have the user re-run OMEN.

2. System Architecture

2.1 Components Involved

The failing path involves the user terminal, the CICS region, the program and transaction, the TD queue, and its backing VSAM dataset. The RACF OPERCMDS check governs who may fix the problem from the MVS console.

graph TD U[User RAFAELT - Terminals 0189/0190] --> T[Transaction OMEN] T --> P[Program BNKMENU] P --> R[CICS Region CICSAOR1] R --> Q[TDQUEUE CINO] Q --> V[VSAM Dataset associated with CINO] V --> C[System Catalog] R --> L[MSGUSR DD 106 - Message Log] A[CICS Administrator] --> M[MVS Console / CEMT] M --> RACF[RACF OPERCMDS - MVS.MODIFY.STC.CICSAOR1.CICSAOR1] RACF --> R

The components are:

Component Role
OMEN CICS transaction started by the user from the terminal
BNKMENU Program that issues SET TDQUEUE(CINO) OPENSTATUS(OPEN)
CINO Transient Data output queue that was found closed
VSAM dataset Backing storage for the TDQUEUE, expected to be resolvable via the catalog
MSGUSR (DD 106) Log where DFHAP1900 and DFHAC2236 were recorded
RACF OPERCMDS Controls who may issue MODIFY commands against the CICS STC

2.2 Failure Sequence

The sequence below shows how the closed queue led to the abend.

sequenceDiagram participant User as RAFAELT participant CICS as CICSAOR1 participant Pgm as BNKMENU participant TDQ as TDQUEUE CINO participant Log as MSGUSR User->>CICS: Start transaction OMEN CICS->>Pgm: Invoke BNKMENU Pgm->>TDQ: SET TDQUEUE(CINO) OPENSTATUS(OPEN) TDQ-->>Pgm: RESP(IOERR) RESP2(14) Pgm-->>CICS: Unhandled error CICS->>Log: DFHAP1900 (SET TDQUEUE failed) CICS->>Log: DFHAC2236 (abend 4038) CICS-->>User: Transaction abended

          SET TDQUEUE(CINO) OPENSTATUS(OPEN) RESP(IOERR) RESP2(14).

3.2 Interpretation

Message Meaning in this incident
DFHAP1900 Records the failing command, SET TDQUEUE(CINO) OPENSTATUS(OPEN), with RESP(IOERR) and RESP2(14)
DFHAC2236 Confirms transaction OMEN (number 69904) abended with 4038 in BNKMENU on terminal 0189

The failure occurred twice, at 17:14:56 and 17:15:33. The two occurrences correspond to terminals 0189 and 0190.

4. Actions Performed

4.1 Debug Sessions (Completed)

  • The terminals 0189 and 0190 for user RAFAELT were terminated by the system. The relevant messages are DFHZC3462 and DFHZC6966.
  • The EQADPFMB file holds only one active profile, JCMARCA. No profiles are pending for RAFAELT.

4.2 TDQUEUE CINO (Requires CICS Administrator Action)

RAFAELT does not have RACF UPDATE authority on the following resource:

CODE 
MVS.MODIFY.STC.CICSAOR1.CICSAOR1  CL(OPERCMDS)
ACCESS INTENT(UPDATE)  ACCESS ALLOWED(READ)

Because of this, RAFAELT cannot issue the MODIFY command that reopens the queue. The access check works as follows:

graph TD A[Issue F CICSAOR1,CEMT S TDQUEUE - CINO - OPEN] --> B{RACF OPERCMDS check} B -- UPDATE authority --> C[Command accepted by CICSAOR1] B -- READ only --> D[Command rejected] C --> E[TDQUEUE CINO opened] D --> F[Escalate to CICS Administrator] F --> C

5. Remediation Procedure

5.1 Reopen the Queue from the Console

The CICS administrator runs the following command at the MVS console, or uses CEMT directly:

CODE 
F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN

5.2 Reopen the Queue via JCL

Alternatively, submit the JCL below under a user ID that has UPDATE authority on OPERCMDS:

JCL 
//FIXCINO  JOB (ACCT),'FIX CINO TDQUEUE',CLASS=A,MSGCLASS=H,
//         MSGLEVEL=(1,1),NOTIFY=&SYSUID
//*---------------------------------------------------------*
//* CORRECAO: ABRIR TDQUEUE CINO NA REGIAO CICSAOR1         *
//* ABEND 4038 TRANSACAO OMEN / PROGRAMA BNKMENU            *
//*---------------------------------------------------------*
//STEP1    EXEC PGM=IKJEFT01,REGION=0M
//SYSTSPRT DD SYSOUT=*
//SYSTSIN  DD *
  CONSOLE
  F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN
  F CICSAOR1,CEMT I TDQUEUE(CINO)
  END
/*

The job runs IKJEFT01 (the TSO terminal monitor program) and activates a console session. It then issues two commands:

  1. CEMT S TDQUEUE(CINO) OPEN sets the queue open.
  2. CEMT I TDQUEUE(CINO) inquires on the queue to show its resulting status.

5.3 Remediation Flow

sequenceDiagram participant Admin as CICS Administrator participant Con as MVS Console / JCL participant CICS as CICSAOR1 participant TDQ as TDQUEUE CINO participant User as RAFAELT Admin->>Con: F CICSAOR1,CEMT S TDQUEUE(CINO) OPEN Con->>CICS: Pass CEMT command CICS->>TDQ: Open queue TDQ-->>CICS: STATUS OPEN Admin->>Con: F CICSAOR1,CEMT I TDQUEUE(CINO) Con-->>Admin: STATUS( OPEN ) ... Admin->>User: Request re-run of OMEN User->>CICS: Execute OMEN CICS-->>User: Menu displayed, no abend 4038

6. Post-Fix Verification

  1. Confirm that the TDQUEUE is open:

    CODE 
    F CICSAOR1,CEMT I TDQUEUE(CINO)

    The expected output is:

    CODE 
    STATUS(  OPEN ) ...

  2. Ask RAFAELT to re-execute transaction OMEN.

  3. Check MSGUSR and confirm that no new DFHAC2236 message with abend 4038 appears.

Check Expected result
CEMT I TDQUEUE(CINO) STATUS( OPEN )
Re-run of OMEN Transaction completes normally
MSGUSR review No DFHAC2236 with abend 4038

7. Prevention

7.1 Recommendations

  1. Find out why CINO was closed. Check for a failure in the associated VSAM dataset. Also check whether someone intentionally ran CEMT S TDQUEUE(CINO) CLOSE.
  2. Review DEBUGTOOL=NO in the SIT of CICSAOR1. With this parameter in effect, z/OS Debugger sessions that end abruptly can leave the enclave in an inconsistent state (CEE2529S). This can cause cascading failures.
  3. Consider defining the CINO VSAM dataset as RECOVERABLE in the CSD. This helps the queue reopen automatically after a failure.

7.2 Prevention Overview

graph TD A[Closed TDQUEUE CINO] --> B[Investigate cause] B --> B1[VSAM dataset failure] B --> B2[Manual CEMT CLOSE] A --> C[Review SIT DEBUGTOOL=NO] C --> C1[Abrupt Debugger termination can leave enclave inconsistent - CEE2529S] A --> D[Define CINO VSAM as RECOVERABLE in CSD] D --> D1[Queue reopened automatically after failure]
