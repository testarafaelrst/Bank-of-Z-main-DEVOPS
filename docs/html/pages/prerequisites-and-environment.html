Prerequisites & Environment Configuration

This page is the installation landing page for Bank of Z. It lists the software and access you need on z/OS and on your workstation, and the environment settings to configure before you deploy. Complete these steps before you start any of the getting-started tutorials.

1. Overview

Bank of Z is a self-contained sample hybrid banking application. It demonstrates modern IBM Z development, deployment, and DevSecOps practices. The repository contains everything needed to install and configure the full environment:

  • Application source code
  • Infrastructure configuration
  • Automation scripts
  • Build tooling
  • Deployment assets
  • Supporting documentation

The application integrates these technologies:

  • CICS
  • IMS Transaction Manager (IMS TM)
  • IMS DB
  • Db2 for z/OS
  • z/OS Connect
  • IBM MQ

Together they give you a realistic environment for learning, testing, and workflow validation.

1.1 Installation Workflow

Installation has six stages. This page covers stages 1 and 2. It also covers part of stage 3, the external tools that must be installed on USS.

  1. Verify software and system prerequisites.
  2. Configure the target environment.
  3. Install and configure the required development tools.
  4. Build the application.
  5. Deploy application resources and services.
  6. Verify the installation.

2. System Architecture

Bank of Z runs on a z/OS target system. A developer works from a desktop or cloud workspace and uses USS-based tooling to build and deploy. Setup scripts read .setup/config/config.yaml and use that configuration to drive the tools and provision the middleware.

2.1 Component Relationships

  • Configuration lives in config.yaml, and USS tools read it.
  • zconfig provisions the CICS resources, IMS resources, and the z/OS Connect runtime during the environment phase.
  • The Db2 subsystem DBD1 must already exist. The setup scripts create only the database objects inside it.
  • Security definitions in RACF (or an equivalent security manager) must be in place before deployment.

3. Prerequisites

Before you deploy Bank of Z, make sure your z/OS environment meets the requirements below. These are platform components and tools that a system administrator usually provisions.

For local workstation requirements (IDE, Zowe CLI, and GRUB), see Local Tools Setup. The tools you need depend on the deployment workflow you choose.

3.1 Supported Desktop Platforms

Platform Minimum Version
Windows Windows 11
macOS macOS 26
OpenShift Dev Spaces 3.20 or later
GitHub Codespaces Supported

If you use IBM Premium Bob for Z (Bob IDE), make sure your workstation meets the operating system and system requirements in the IBM Premium Bob for Z documentation.

3.2 z/OS Platform Requirements

The target z/OS environment must include these components. Contact your system administrator if any are missing.

Component Minimum Version
z/OS 3.1
CICS TS 6.3
Db2 for z/OS V13
IMS Transaction Manager (IMS TM) V15
IMS Database V15
z/OS Connect Enterprise Edition 3.0.101
IBM MQ Supported release

Note: A pre-existing Db2 subsystem with subsystem ID DBD1 is required. The setup scripts create the Db2 database objects within this subsystem but do not create the subsystem. IMS, CICS, and z/OS Connect runtime instances are provisioned automatically during deployment.

3.4 Access and Security Requirements

Make sure you have the following access before you continue.

Access Requirement Description
TSO user ID and password Required for authentication and system access
USS access Required to access z/OS UNIX System Services resources
Dataset creation permissions Permission to create and modify datasets
Deployment permissions Permission to deploy application resources
Middleware access Access to CICS, IMS, Db2, IBM MQ, and z/OS Connect, as applicable

Security definitions must also be configured in RACF or an equivalent security manager before deployment. The required definitions depend on your target environment. Contact your system administrator if you are unsure what is required.

Note: A system administrator typically provisions access to z/OS environments, middleware, USS directories, and dataset resources. If you do not have the required access, contact your administrator before you continue.

3.5 External Tools Requirements

Building and deploying Bank of Z requires the external tools and libraries below.

3.5.1 Python Libraries

Install the required Python libraries:

BASH 
pip install pyyaml
pip install jinja2

3.5.2 Gradle

Download the latest supported Gradle binary distribution from the Gradle releases page (https://gradle.org/releases/). Then install it on z/OS USS:

BASH 
jar xf gradle-9.5.1-bin.zip
chmod +x gradle-9.5.1/bin/gradle
chtag -tc UTF-8 gradle-9.5.1/bin/gradle

Note: If you download a different Gradle release, update the version number in the commands.

3.6 Verify Prerequisites

After your system administrator confirms the items above are in place, run the prerequisite validation from USS:

BASH 
.setup/setup-common.sh validate-prereqs

This check does the following:

  • Verifies the versions of DBB, ZOAU, zconfig, and Wazi Deploy.
  • Verifies that Git is available.
  • Verifies network connectivity to GitHub.

For a full description of each check, see Deploy Using Direct USS Access.

4. Environment Configuration

This section covers the configuration to complete before you deploy Bank of Z. Before you begin, make sure your z/OS environment meets every requirement in section 3. The Db2 subsystem DBD1 and the required RACF definitions must exist before you run the setup scripts.

4.1 Configuration Flow

graph TD A[Edit config.yaml global section] --> B{Using IBMUSER?} B -- Yes --> D[Set IMS and CICS credentials] B -- No --> C[Run grant-perm-user.sh as administrator] C --> D D --> E[Create ZCodeScan config file] E --> F[Choose a deployment tutorial]

4.2 Configure the Application

Edit .setup/config/config.yaml in your local clone of the repository. This file controls the paths, environment settings, and middleware configuration used during setup, build, and deployment.

Update the values in the global section to match your environment. Unless noted otherwise, the remaining values use template references and need no changes.

YAML 
# Global properties
# - Shared by middleware/tools 
# - Subject to change with middleware/tools updates
global:

  # Sandbox
  sandbox_root: "/usr/local/sandboxes"

  # Application
  app_base_name: "BANKZ"
  app_hlq: "{{ global.app_base_name }}"
  app_short_name: "BOZ" # Maximum 3 characters
  app_version: "0"
  app_release: "1"
  app_modification: "0"

  # Tools
  java_home: "{{ sandbox.root }}/tools/J21.0_64"
  python_home: "/usr/lpp/IBM/cyp/v3r14/pyz"
  zoau_home: "/usr/lpp/IBM/zoau"
  zconfig_home: "{{ global.sandbox_root }}/tools/zconfig"
  zcb_home: "{{ global.sandbox_root }}/tools/zrb/cics-resource-builder-1.0.6"
  dbb_home: "{{ global.sandbox_root }}/tools/dbb"
  gradle_home:  "{{ global.sandbox_root }}/tools/gradle-9.5.1"
  zcodescan_home: "/global/opt/pyenv/akf"
  wazideploy_home: "/global/opt/pyenv/gdp"
  zosconnect_home: "/usr/lpp/IBM/zosconnect"
  liberty_home: "/usr/lpp/liberty_zos/25.0.0.9"

  # z/OS System
  zos_admin_user: "IBMUSER"
  zos_current_user: "${ZOS_CURRENT_USER}"
  zos_ca_label: "VSICA"
  zos_keyring: "BOZRING"
  sys_proclib: "SYS1.PROCLIB"
  tcpip_hlq: "TCPIP"
  asm_hlq: "ASM"
  igzxjni2: "/usr/lpp/IBM/cobol/igyv6r5/lib/igzxjni2.x"
  igy_hlq: "IGY.V6R5M0"
  fel_hlq: "FEL"
  ipv_hlq: "IPV"
  pli_hlq: "PLI.V6R2M0"
  debug_hlq: "EQAW"
  
  # GUI
  zosconnect_http_port: 9080
  zosconnect_https_port: 9444
  zosconnect_task_user: "{{ global.zos_admin_user }}"

  # Frontend
  frontend_http_port: 9081
  frontend_https_port: 9445
  frontend_task_user: "{{ global.zos_admin_user}}"

  # CICS
  cics_hlq: "CICSTS63"
  cics_uss_dir: "/usr/lpp/cicsts/cicsts63"
  cics_sec: "YES"
  
  # IMS
  ims_disabled: "false"
  ims_sys_hlq: "IMSV15"
  ims_java_dir: "/usr/lpp/ims/imsjava"
  ims_datastore: "IMS2"
  ims_dfsplex: "PLEX2"
  
  # DB2
  db2_hlq: "DB2V13"
  db2_dsntep: "DSNTEP13"
  db2_ssid: "DBD1"
  db2_runlib: "{{ global.db2_ssid }}.RUNLIB.LOAD"
  db2_sqlid: "{{ global.zos_current_user }}"
  db2_java_dir: "/usr/lpp/db2d10"
  db2_grants:
  - "CICSUSER"

All other configuration values use template references ({{section.field}}). They need no changes unless your environment uses non-default values. For a description of every configuration property, see the Configuration Reference.

4.3 Grant Permissions (Non-IBMUSER Accounts Only)

If you do not use the IBMUSER user ID, grant your user ID permission to create Db2 database objects before you run the environment setup.

Run this command as an administrator, and replace MYUSER with your user ID:

BASH 
.setup/setup/grant-perm-user.sh MYUSER

4.4 Set the IMS and CICS Credentials

Set these environment variables before you run the setup scripts:

Variable Description
IMS_USER IMS user ID
IMS_PASSWORD IMS password
CICS_USER CICS user ID
CICS_PASSWORD CICS password

Example:

BASH 
export IMS_USER=<your_ims_user>
export IMS_PASSWORD=<your_ims_password>

export CICS_USER=<your_cics_user>
export CICS_PASSWORD=<your_cics_password>

4.5 Create the ZCodeScan Configuration File

The static scan stage needs a ZCodeScan configuration file. You must create it manually and encode it in ISO8859-1, because ZCodeScan cannot read files saved in IBM-1047 or UTF-8.

Create ~/zcs_config_file.yml, or the file named by zcodescan.config_file in config.yaml:

YAML 
license_server:
  url: https://127.0.0.1:8195
  user: MYUSER
  password: MY_PASSWORD
  verify: false

Note: ZCodeScan encrypts the password automatically after the first scan. You only need to enter it in plain text the first time.
