Configuration Reference

Bank of Z centralizes all environment-specific settings in a single YAML configuration file located at .setup/config/config.yaml. This file governs every aspect of the application lifecycle — from sandbox directory layout and dataset naming through middleware connectivity and deployment automation. Understanding its structure and rules is essential for successfully setting up, building, and deploying Bank of Z across any z/OS environment.

1. Overview

The .setup/config/config.yaml file is the single source of truth for all Bank of Z environment configuration. It is consumed by setup scripts, build pipelines, and deployment automation tools. The file is organized into named sections, each targeting a specific subsystem or tool. Values defined in one section can be referenced from another using a lightweight variable-expansion syntax, which eliminates duplication and ensures consistency across the configuration.

Key capabilities of the configuration file:

  • Hierarchical organization — settings are grouped into logical YAML sections (e.g., sandbox, app, dbb, cics)
  • Variable expansion — values can reference other configuration entries using {{section.key}} or ${section.key} syntax
  • Environment variable injection — sensitive values such as credentials are read from shell environment variables using ${ENV_VAR} syntax
  • Comment support — inline documentation using the # prefix
  • Validation — the setup process validates required fields, path formats, character limits, and variable resolution before any build or deployment action is taken

3. Configuration File Structure

The file is organized as a flat set of top-level YAML sections. The global section holds the primary shared values; all other sections can reference those values via variable expansion.

YAML 
# .setup/config/config.yaml

global:
  app_base_name: BANKZ
  app_hlq: "{{ global.app_base_name }}"
  app_short_name: BOZ
  sandbox_root: /usr/local/sandboxes
  zos_admin_user: IBMUSER
  zos_current_user: ${ZOS_CURRENT_USER}

sandbox:
  path: /usr/local/sandboxes/bank-of-z

app:
  base_name: BANKZ
  short_name: BOZ
  zos_version: V0R1M0

dbb:
  dbb_home: /usr/lpp/IBM/dbb
  java_home: /usr/lpp/java/java21/current_64

cics:
  user: ${CICS_USER}
  password: ${CICS_PASSWORD}
  cmci_port: 27100
  ipic_port: 27114

4. Variable Expansion

Configuration values can reference other configuration entries, eliminating repetition and making multi-environment management straightforward.

4.1 Section References

Use ${section.key} or {{section.key}} to reference a value defined elsewhere in the file:

YAML 
sandbox:
  path: /usr/local/sandboxes/bank-of-z

dbb:
  dbb_build: ${sandbox.path}/Bank-of-Z/.setup/build
  dbb_cwd:   ${sandbox.path}/Bank-of-Z/

Resolution is recursive — a variable may itself reference another variable — but circular references are not permitted and are caught during validation.

4.2 Environment Variable References

Use ${ENV_VAR} to inject values from the shell environment at runtime:

YAML 
cics:
  user:     ${CICS_USER}
  password: ${CICS_PASSWORD}

zcodescan:
  rseapi_user:     ${RESAPI_USER}
  rseapi_password: ${RESAPI_PASSWORD}

Security best practice: Always use environment variable references for credentials, API keys, and any other sensitive values. Never hardcode secrets in config.yaml.

The diagram below shows how variable expansion is resolved at setup time:

sequenceDiagram participant CF as config.yaml participant VP as Variable Processor participant ENV as Shell Environment participant SC as Setup Script SC->>CF: Load configuration file CF-->>VP: Raw YAML with variable tokens VP->>VP: Resolve {{section.key}} references VP->>ENV: Look up ${ENV_VAR} tokens ENV-->>VP: Environment variable values VP->>VP: Validate resolved values VP-->>SC: Fully resolved configuration map SC->>SC: Execute setup / build / deploy

5. Required Settings

The global section contains the primary configuration values required for every Bank of Z environment. These settings are consumed by setup scripts, middleware, and supporting tools.

5.1 Sandbox

Variable Default Value Description
sandbox_root /usr/local/sandboxes Root directory of the sandbox on z/OS USS

Requirements:

  • Must be an absolute path (starts with /)
  • No trailing slashes
  • The user executing setup must have write permissions
  • Parent directory must already exist
YAML 
# Development environment
sandbox:
  path: /usr/local/sandboxes/dev/bank-of-z

# Personal sandbox
sandbox:
  path: /u/userid/sandboxes/bank-of-z

5.2 Application Identity

Variable Default Value Description
app_base_name BANKZ Application base name; used as dataset HLQ
app_hlq {{ global.app_base_name }} Application high-level qualifier
app_short_name BOZ Short identifier (max 3 characters)
app_version 0 Application version number
app_release 1 Application release number
app_modification 0 Application modification level

app_base_name drives dataset naming throughout the system:

CODE 
BANKZ.V0R1M0.LOAD
BANKZ.V0R1M0.COBCOPY
BANKZ.V0R1M0.OBJ

app_short_name is used in CICS region names and transaction IDs:

CODE

BOZ1       ← transaction prefix

6. Section Settings

6.1 Sandbox Configuration

The sandbox section defines the root directory on z/OS UNIX System Services (USS) where all Bank of Z components are installed. All other path-based settings derive from this value.

6.2 Application Configuration

The app section defines the naming conventions used for z/OS datasets, CICS resources, and deployment artifacts. The zos_version field is formatted as V#R#M# and is embedded in dataset names to support multiple concurrent versions.

6.3 DBB Configuration

The dbb section identifies the IBM Dependency Based Build (DBB) installation and its Java runtime. DBB drives the compilation and linking of all COBOL, PL/I, and Assembler source members.

YAML 
dbb:
  dbb_home:  /usr/lpp/IBM/dbb
  java_home: /usr/lpp/java/java21/current_64

6.4 Repository Configuration

Defines the Git repositories cloned during environment setup. Each entry specifies the repository name, clone URL, and local target directory.

YAML 
repositories:
  - name:       dbb
    url:        https://github.com/IBM/dbb.git
    target_dir: dbb
  - name:       custom-tools
    url:        https://github.com/company/tools.git
    target_dir: tools

6.5 zBuilder Configuration

Defines where the zBuilder build framework source and deployment artifacts are located. java_home for zBuilder requires Java 17 or higher.

YAML 
zbuilder:
  source_dir: build
  target_dir: ${sandbox.path}/zBuilder
  java_home:  /usr/lpp/java/java21/current_64

6.6 zconfig Configuration

Defines settings for z/OS configuration tooling, including the CICS Resource Builder (CRB).

YAML 
zconfig:
  zconfig_home: /usr/local/sandboxes/tools/zconfig
  zcb_home:     /usr/local/sandboxes/tools/zrb/cics-resource-builder-1.0.6
  java_home:    /usr/lpp/java/java21/current_64

6.7 ZCodeScan Configuration

Defines settings used for static code analysis against the Bank of Z source base.

YAML 
zcodescan:
  zcodescan_home: /global/opt/pyenv/akf
  java_home:      /usr/lpp/java/java21/current_64
  src_folder:     ${sandbox.path}/Bank-of-Z/src/base
  output_folder:  ${sandbox.path}/Bank-of-Z/zcodescan
  src_encoding:   IBM-1047
  rseapi_user:    ${RESAPI_USER}
  rseapi_password: ${RESAPI_PASSWORD}

6.8 Wazi Deploy Configuration

Defines deployment automation settings consumed by Wazi Deploy during the CD pipeline.

YAML 
wazideploy:
  wazideploy_home:    /global/opt/pyenv/gdp
  deployment_method:  ${sandbox.path}/dbb/WaziDeploy/zDeploy/deployment-configuration/deployment-method.yml
  deployment_envfile: ${sandbox.path}/Bank-of-Z/.setup/deploy/Development.yml

6.9 TAZ Configuration

7. Environment-Specific Configurations

Bank of Z supports multiple concurrent environments — development, test, and production — each with its own config.yaml. The key differentiators per environment are the sandbox.path, app.base_name, app.short_name, and app.zos_version values.

8. Validation Rules

Before executing any setup, build, or deployment step, the setup process validates the loaded configuration. The validation sequence is shown below:

sequenceDiagram participant U as User / Pipeline participant V as Validator participant CF as config.yaml U->>V: Invoke setup script V->>CF: Parse YAML CF-->>V: Configuration tree V->>V: Check required fields present V->>V: Validate absolute path formats V->>V: Enforce character limits V->>V: Resolve all variable references V->>V: Detect circular references alt Validation passes V-->>U: Configuration accepted — proceed else Validation fails V-->>U: Error report with failing field(s) end

Validation checks include:

  1. Required fields present

    • sandbox.path
    • app.base_name
    • app.short_name
    • dbb.dbb_home
    • dbb.java_home

  2. Path formats

    • All paths must be absolute (begin with /)
    • No trailing slashes

  3. Variable resolution

    • All ${section.key} and {{section.key}} tokens must resolve to a defined value
    • No circular references permitted

  4. Character limits

    • app.base_name — maximum 8 characters, alphanumeric only
    • app.short_name — maximum 4 characters

  5. Tool locations defined

    • All referenced tool _home paths must be set

Note: Correcting configuration issues before running setup prevents downstream build and deployment failures.

9. Troubleshooting

9.1 Configuration File Not Found

Symptom: Configuration file not found error during setup.

Cause: config.yaml is missing or the script is run from the wrong directory.

Solution:

BASH 
# Verify the file exists
ls -la .setup/config/config.yaml

# Confirm you are in the repository root
pwd

9.2 Variable Reference Cannot Be Resolved

Symptom: Variable reference cannot be resolved error.

Cause: A ${section.key} token references a section or key that does not exist.

YAML 
# Bad — references a non-existent section
dbb:
  build_dir: ${workspace.path}/build   # 'workspace' is not a defined section

# Good — correct section name
dbb:
  build_dir: ${sandbox.path}/build

9.3 Invalid Path Format

Symptom: Invalid path format validation error.

Cause: A path value is relative rather than absolute.

YAML 
# Bad — relative path
sandbox:
  path: sandboxes/bank-of-z

# Good — absolute path
sandbox:
  path: /usr/local/sandboxes/bank-of-z

9.4 Application Name Too Long

Symptom: Character limit exceeded validation error on app.base_name or app.short_name.

Cause: The value exceeds the z/OS dataset naming or CICS resource naming limits.

YAML 
# Bad — exceeds 8-character limit
app:
  base_name: BANKOFZDEV   # 10 characters

# Good — within limit
app:
  base_name: BANKZDEV     # 8 characters
