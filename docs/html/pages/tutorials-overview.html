Tutorials Overview & Deployment Walkthrough

1. Overview

The Bank of Z tutorials are for developers who have already installed and verified Bank of Z. They cover common development, deployment, and modernization workflows. The tutorials build on one another. Together they show how an application change moves from source code to a running deployment in a hybrid IBM Z environment.

By completing the tutorials, you learn how to:

  • Build and deploy Bank of Z application components
  • Modify and validate application code
  • Deploy changes to CICS and IMS environments
  • Use modern IBM Z development workflows and tooling
  • Verify application behavior after deployment

This page does two things:

  1. It indexes the available tutorials.
  2. It describes the end-to-end first-time deployment shown in the Deploy Bank of Z tutorial.

1.1 Available Tutorials

2. System Architecture

The Deploy Bank of Z tutorial uses the Direct USS deployment method. It starts from a z/OS environment where all prerequisites are already in place. The setup stages provision a full application stack automatically. The stack has these components:

  • CICS: hosts the transactional application components.
  • IMS: hosts the IMS-based application components.
  • z/OS Connect: exposes the services of the application stack.
  • Liberty frontend server: provides the user-facing frontend.

2.1 Component View

graph TD U[Developer] --> USS[z/OS USS Environment] USS --> REPO[Cloned Bank of Z Repository] REPO --> SETUP[Three Setup Stages] SETUP --> CICS[CICS] SETUP --> IMS[IMS] SETUP --> ZCON[z/OS Connect] SETUP --> LIB[Liberty Frontend Server] SETUP --> BUILD[Build and Deploy from Source] BUILD --> CICS BUILD --> IMS LIB --> ZCON ZCON --> CICS ZCON --> IMS

The diagram shows the following relationships:

  • The developer works in the z/OS USS environment.
  • The cloned repository drives the three setup stages.
  • The setup stages provision the runtime components and build and deploy the application from source.
  • The Liberty frontend reaches the CICS and IMS back ends through z/OS Connect. This is the typical layering for a hybrid application. The source material does not give the exact wiring, so treat the connections from z/OS Connect to CICS and IMS as illustrative.

3. Deployment Walkthrough

3.1 What the Walkthrough Demonstrates

The walkthrough is a video of a complete first-time deployment. It shows:

  1. Starting from a z/OS environment with all prerequisites in place.
  2. Cloning the repository to USS.
  3. Running the three setup stages.
  4. Automatic provisioning of the full application stack: CICS, IMS, z/OS Connect, and the Liberty frontend server.
  5. Building and deploying the application from source.

3.2 Deployment Sequence

The source material does not name the individual setup stages. The sequence therefore shows them in order as stages 1 to 3.

4. Day-to-Day Development Workflow

A full deployment is only needed the first time. After Bank of Z is deployed, use the incremental build and deploy workflow instead of repeating the full deployment after every code change. The script for this is pipeline-remote.sh.

Tip: Once Bank of Z has been deployed successfully, use the incremental build and deploy workflow (pipeline-remote.sh) during day-to-day development instead of performing a full deployment after every code change.

graph TD A[First-time setup] --> B[Full deployment: three setup stages] B --> C{Code change?} C -->|Yes| D[Run pipeline-remote.sh] D --> E[Incremental build and deploy] E --> F[Verify behavior] F --> C C -->|No| G[Done]

4.1 Full vs. Incremental Deployment

Aspect Full Deployment Incremental Workflow
When to use First-time setup Day-to-day development
Mechanism Three setup stages from the cloned repository pipeline-remote.sh
Scope Provisions the whole stack, then builds and deploys from source Builds and deploys changes
Frequency Once After each code change
