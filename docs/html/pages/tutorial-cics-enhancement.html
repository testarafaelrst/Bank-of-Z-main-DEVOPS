Tutorial: CICS Enhancement Scenario

1. Overview

This tutorial walks you through a complete, end-to-end enhancement to the CICS-based implementation of Bank of Z — a realistic mainframe banking application. The enhancement being added is a new customer email field, which touches multiple layers of the application stack: the Db2 database schema, COBOL copybooks, CICS programs, and the front-end web interface.

The scenario mirrors a real-world IBM Z development workflow:

  • Understand the existing application using Z Understand and Bob AI
  • Plan the changes through impact analysis and an implementation checklist
  • Implement the enhancement using IBM Z Open Editor and COBOL modifications
  • Build and deploy the updated components through the Bank of Z pipeline
  • Validate the results via the Bank of Z web application

By the end of this tutorial, you will have hands-on experience with the complete IBM Z development lifecycle, from codebase exploration to production-ready deployment.

2. System Architecture

The Bank of Z CICS application follows a classic multi-tier IBM Z architecture. User requests flow from a web front end through a CICS transaction gateway into COBOL application programs, which interact with a Db2 database for persistent storage.

graph TD A[Bank of Z Web Application] -->|HTTP Request| B[CICS Transaction Gateway] B -->|EXEC CICS| C[CICS Region] C -->|Invoke| D[COBOL Application Programs] D -->|EXEC SQL| E[Db2 Database] D -->|Copybook Definitions| F[COBOL Copybooks] E -->|Customer Data| D D -->|Response Data| C C -->|Response| B B -->|HTTP Response| A subgraph IBM Z Mainframe C D E F end

This architecture means that adding a new field — such as a customer email address — requires coordinated changes across several components simultaneously: the Db2 table definition, the COBOL copybooks that map the data layout, the CICS programs that process and return the data, and the web front end that displays it.

The diagram below illustrates the component ownership relevant to this specific enhancement:

graph LR subgraph Database Layer DB[(Db2 Customer Table)] end subgraph Application Layer CPY[COBOL Copybook\nCUSTOMER Data Structure] PGM1[CICS COBOL Program\nCustomer Inquiry] PGM2[CICS COBOL Program\nCustomer Update] end subgraph Presentation Layer WEB[Bank of Z\nWeb Application] end DB -- "EMAIL column added" --> CPY CPY -- "EMAIL field mapped" --> PGM1 CPY -- "EMAIL field mapped" --> PGM2 PGM1 -- "Email returned in response" --> WEB PGM2 -- "Email accepted in request" --> WEB

4. What You Will Learn

By completing this tutorial, you will gain practical skills in the following areas:

  • Application understanding — Explore the Bank of Z codebase with Z Understand, trace the CICS request flow, and map component dependencies
  • Impact analysis — Identify all artifacts affected by a given enhancement before writing a single line of code
  • Implementation planning — Use Bob AI to generate an ordered implementation checklist
  • COBOL modification — Update copybooks, working storage, and procedure division logic in IBM Z Open Editor
  • Build and deployment — Run the Bank of Z build pipeline and deploy updated CICS program definitions
  • Validation — Confirm the enhancement is live through the Bank of Z web application

5. Part 1 — Understand and Plan the Enhancement

5.1 Goals of Part 1

Before making any code changes, it is essential to fully understand what the application does today and which components will be affected by the email field addition. Skipping this step in a real-world engagement risks missed dependencies, broken transactions, and regressions.

Part 1 covers:

  • Exploring the Bank of Z codebase using Z Understand
  • Understanding the CICS application architecture
  • Performing impact analysis on the customer data structure
  • Tracing the end-to-end application data flow
  • Generating an implementation plan with Bob AI
  • Producing a prioritized implementation checklist

5.3 Key Concepts: CICS Request Flow

Understanding how a CICS transaction processes a customer inquiry is essential before modifying it. The flow below represents a typical customer data retrieval transaction in Bank of Z:

sequenceDiagram actor User participant Web as Web Application participant GW as CICS Gateway participant TXN as CICS Transaction participant PGM as COBOL Program participant DB2 as Db2 Database User->>Web: Request customer details Web->>GW: HTTP POST with customer ID GW->>TXN: START transaction (e.g., BKZC) TXN->>PGM: EXEC CICS LINK to inquiry program PGM->>DB2: EXEC SQL SELECT from CUSTOMER table DB2-->>PGM: Customer row (including new EMAIL column) PGM-->>TXN: Populate COMMAREA with customer data TXN-->>GW: Return COMMAREA GW-->>Web: JSON response Web-->>User: Display customer details (with email)

6. Part 2 — Implement and Validate the Enhancement

6.1 Goals of Part 2

With a clear implementation plan in hand from Part 1, Part 2 moves into active development. All changes are made inside IBM Z Open Editor, with Bob AI available for code generation assistance.

Part 2 covers:

  • Updating Db2 table definitions to add the EMAIL column
  • Modifying COBOL copybooks to include the new EMAIL field
  • Updating CICS COBOL programs to handle the new field in both inquiry and update flows
  • Running the Bank of Z build and deployment pipeline
  • Validating the Db2 schema changes post-deployment
  • Verifying the enhancement through the Bank of Z web application

6.2 End-to-End Implementation Flow

The diagram below captures the full sequence of changes and their dependencies. Each step must be completed in order, because downstream artifacts depend on upstream definitions.

graph TD A[1. Alter Db2 CUSTOMER Table\nADD EMAIL VARCHAR 100] --> B[2. Update COBOL Copybook\nAdd EMAIL PIC X 100 field] B --> C[3. Update Customer Inquiry Program\nMap EMAIL from Db2 result set to COMMAREA] B --> D[4. Update Customer Update Program\nAccept and persist EMAIL from COMMAREA] C --> E[5. Run Bank of Z Build Pipeline\nCompile, link-edit, bind] D --> E E --> F[6. Deploy to CICS Region\nNEWCOPY / PHASEIN updated programs] F --> G[7. Validate Db2 Schema\nVerify EMAIL column in SYSIBM.SYSCOLUMNS] F --> H[8. Verify via Web Application\nEmail field visible and editable] G --> I{Enhancement\nSuccessful?} H --> I I -- Yes --> J[Merge and Promote Changes] I -- No --> K[Diagnose and Remediate] K --> E

6.3 Artifact Changes in Detail

The following table summarises every artifact touched during the enhancement and the nature of the change:

Artifact Type Artifact Name Change Description
Db2 DDL CUSTOMER table ALTER TABLE to add EMAIL VARCHAR(100) column
COBOL Copybook CUSTCPY (or equivalent) Add 05 CUST-EMAIL PIC X(100) to customer group item
COBOL Program Customer Inquiry Add EMAIL to SELECT column list; move to COMMAREA
COBOL Program Customer Update Add EMAIL to UPDATE SET clause; accept from COMMAREA
CICS COMMAREA Communication area layout Extend to include email field
Web Application Customer detail page Render and bind the new email field

6.4 Example Artifact Changes

6.4.1 Db2 DDL — Adding the EMAIL Column

SQL 
ALTER TABLE BANKOFZ.CUSTOMER
    ADD COLUMN EMAIL VARCHAR(100);

6.4.2 COBOL Copybook — Adding the EMAIL Field

COBOL 
01 CUSTOMER-RECORD.
           05 CUST-ID          PIC 9(10).
           05 CUST-FIRST-NAME  PIC X(30).
           05 CUST-LAST-NAME   PIC X(30).
           05 CUST-PHONE       PIC X(15).
           05 CUST-EMAIL       PIC X(100).    *> NEW FIELD
           05 CUST-BALANCE     PIC S9(13)V99 COMP-3.

6.4.3 COBOL Program — Reading EMAIL in an Inquiry

COBOL 
EXEC SQL
           SELECT CUST_ID,
                  CUST_FIRST_NAME,
                  CUST_LAST_NAME,
                  CUST_PHONE,
                  EMAIL                          *> NEW COLUMN
           INTO  :CUST-ID,
                 :CUST-FIRST-NAME,
                 :CUST-LAST-NAME,
                 :CUST-PHONE,
                 :CUST-EMAIL                     *> NEW HOST VARIABLE
           FROM  BANKOFZ.CUSTOMER
           WHERE CUST_ID = :WS-INPUT-CUST-ID
       END-EXEC.

6.4.4 COBOL Program — Persisting EMAIL in an Update

COBOL 
EXEC SQL
           UPDATE BANKOFZ.CUSTOMER
           SET    CUST_FIRST_NAME = :CUST-FIRST-NAME,
                  CUST_LAST_NAME  = :CUST-LAST-NAME,
                  CUST_PHONE      = :CUST-PHONE,
                  EMAIL           = :CUST-EMAIL       *> NEW COLUMN
           WHERE  CUST_ID         = :CUST-ID
       END-EXEC.

6.4.5 CICS NEWCOPY — Refreshing the Updated Program

After deployment, the updated COBOL program load module must be refreshed in the CICS region so that the new copy is used for all subsequent transactions:

CODE 
CEMT SET PROGRAM(BKZCUST) NEWCOPY

6.5 Build and Deployment Pipeline

The Bank of Z pipeline automates the steps from source compilation through CICS deployment:

graph LR A[Source Changes\ncommitted to SCM] --> B[IBM Dependency Based Build\nDBB Compile + Link-edit] B --> C[Db2 Bind\nPrecompile + Bind Package] C --> D[Packaging\nUCD Artifact Bundle] D --> E[Deploy to CICS\nUCD Deploy + NEWCOPY] E --> F[Smoke Test\nAutomated transaction check] F --> G{Pass?} G -- Yes --> H[Deployment Complete] G -- No --> I[Rollback and Alert]
