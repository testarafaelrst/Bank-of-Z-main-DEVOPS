Zowe CLI Workflow

The Zowe CLI workflow facilitates Git-based development by coordinating build and deployment activities between a local development environment and z/OS UNIX System Services (USS) using setup-local.sh and pipeline-local.sh. This workflow eliminates the need for direct SSH access to USS.

1. Overview

The Zowe CLI workflow is designed for day-to-day application development on the mainframe. Instead of requiring direct interactive SSH sessions into z/OS USS, developers interact through local automation scripts and Zowe CLI commands. Changes committed and pushed to a remote Git repository are cloned onto z/OS USS workspaces, where native build and deployment utilities (such as IBM Dependency Based Build and Wazi Deploy) execute automatically.

2. System Architecture

The workflow establishes communication between three primary environments: the local developer machine, the remote Git repository (GitHub), and the target z/OS system hosting USS.

2.1. Architectural Components

  • Local Machine: Runs your IDE (such as VS Code), local Git client, Zowe CLI, and coordinator scripts (setup-local.sh, pipeline-local.sh).
  • Remote Git Repository: Stores source assets and feature branches on GitHub.
  • z/OS USS Environment: Receives remote command triggers from Zowe CLI, clones the active branch, and runs build tools (DBB) and deployment orchestration (Wazi Deploy) without manual SSH logon.

3. Full and Incremental Build and Deploy

Bank of Z supports two distinct build and deploy patterns depending on the scope of changes:

  • Full Build and Deploy: Recommended when provisioning a new environment or when underlying infrastructure configurations require a complete redeployment.
  • Incremental Build and Deploy: Optimized for standard day-to-day development. It rebuilds and deploys only the components impacted by recent code modifications.

On USS, the incremental workflow can also be executed via:

BASH 
pipeline-remote.sh

4. Daily Development Cycle

The standard development lifecycle consists of five sequential steps:

sequenceDiagram autonumber actor Dev as Developer participant Local as Local Machine (Zowe CLI) participant Git as GitHub participant USS as z/OS USS Dev->>Local: Modify application source files Dev->>Git: Commit and push changes (`git push origin `) Dev->>Local: Run setup-local.sh or pipeline-local.sh Local->>USS: Create USS workspace directory Local->>USS: Trigger remote clone from GitHub USS->>Git: Clone branch contents Local->>USS: Invoke setup-remote.sh or pipeline-remote.sh USS->>USS: Execute DBB build & Wazi Deploy Local-->>Dev: Execution completed Dev->>USS: Validate application via Web UI

4.1. Step 1: Make Changes

Modify source code within your local repository workspace. Common components modified during day-to-day development include:

  • COBOL programs and copybooks
  • BMS maps
  • z/OS Connect API assets
  • Web application components
  • Configuration files

4.2. Step 2: Commit and Push

All modifications must be pushed to the remote repository prior to triggering the build. Because USS scripts clone your active branch directly from GitHub, unpushed local commits will not be included in the build.

BASH 
git add .
git commit -m "Your change description"
git push origin your-branch

4.3. Step 3: Run the Setup or Pipeline Task

Execution can be triggered from the terminal or using VS Code tasks.

4.3.1. Command Line Execution

BASH 
# Full environment setup (first time or after infrastructure changes)
bash .setup/setup-local.sh

# Incremental build and deploy only
bash .setup/pipeline-local.sh

4.3.2. VS Code Task Execution

Open the Command Palette (Ctrl+Shift+P or Cmd+Shift+P), navigate to Tasks: Run Task, and select the desired task.

The VS Code task definition is managed in .vscode/tasks.json:

JSON 
{
  \"version\": \"2.0.0\",
  \"tasks\": [
    {
      \"label\": \"Setup Bank of Z Environment\",
      \"type\": \"shell\",\n      \"command\": \"bash .setup/setup-local.sh\",
      \"problemMatcher\": [],
      \"presentation\": {
        \"reveal\": \"always\",
        \"panel\": \"new\"
      }
    }
  ]
}

4.4. Step 4: Automated Script Execution

When running the setup script, operations are coordinated across environments:

CODE 
Local Machine                         z/OS USS
─────────────                         ────────
setup-local.sh executes
│
├─ Creates USS workspace  ──────────→ Directory created
├─ Clones your branch     ──────────→ git clone from GitHub
└─ Invokes setup-remote.sh ─────────→ Runs on USS natively
                                        ├─ validate-prereqs
                                        ├─ environment
                                        └─ install-bank-of-z

For incremental builds, pipeline-local.sh uploads pipeline assets and triggers pipeline-remote.sh on USS. This runs the DBB build and executes Wazi Deploy without re-provisioning middleware components.

4.5. Step 5: Validate Changes

Verify that the updated application code and APIs are operational by opening the Bank of Z web frontend:

CODE 
http://<your-zos-host>:9080/bank-frontend-vanilla

5. Working with Branches and Workspaces

The automation scripts automatically detect your active local Git branch:

BASH 
# Switch to your feature branch before running
git checkout feature/my-change
git push origin feature/my-change
bash .setup/setup-local.sh

To avoid file conflicts when multiple developers deploy to the same z/OS host, configure unique workspace paths in config.yaml.

6. Performance Comparison

The following table compares the operational performance of the Zowe CLI workflow against the GRUB workflow:

Operation Zowe CLI GRUB
Initial setup ~5–8 minutes ~3–6 minutes
Incremental update ~5–8 minutes ~5–10 seconds
Requires push to remote Yes No
