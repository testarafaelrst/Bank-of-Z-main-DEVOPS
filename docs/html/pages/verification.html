Verification & Smoke Testing

1. Overview

The Bank of Z application runs on IBM Z infrastructure and integrates multiple enterprise middleware platforms — CICS, IMS, Db2, MQ, and z/OS Connect EE — to deliver a fully functional core banking system. Before development or operational activities can begin, every layer of this stack must be confirmed as correctly installed, configured, and reachable.

This page guides platform engineers and developers through a structured verification and smoke-testing workflow. It covers:

  • Validating the local development toolchain (Java, Git, Zowe CLI)
  • Confirming connectivity to the target z/OS environment
  • Checking that all required middleware subsystems are active
  • Verifying that application artifacts (load modules, Db2 plans, IMS resources, CICS definitions) have been deployed
  • Running end-to-end smoke tests against live transactions and APIs to confirm the system is fully operational

A clean pass through all checks means the Bank of Z environment is ready for development, testing, or production use.

2. System Architecture

The diagram below illustrates the major components of the Bank of Z platform and the relationships between them. Verification activities target each layer in turn — from the developer workstation down through the z/OS runtime and its middleware subsystems.

graph TD WS["👩‍💻 Developer Workstation\n(Java · Git · Zowe CLI)"] ZOSMF["z/OSMF\n(REST Gateway)"] ZCONN["z/OS Connect EE\n(API Layer)"] CICS["CICS Region\n(Transaction Manager)"] IMS["IMS TM / IMS DB\n(Transaction & Hierarchical DB)"] DB2["Db2 for z/OS\n(Relational Database)"] MQ["IBM MQ\n(Messaging)"] ZOS["z/OS 3.1+\n(Operating System)"] UI["Bank of Z\nUser Interface"] WS -->|"zowe zosmf check status"| ZOSMF UI -->|HTTP/S API calls| ZCONN ZCONN --> CICS ZCONN --> IMS CICS --> DB2 CICS --> MQ IMS --> DB2 ZOSMF --> ZOS ZOS --> CICS ZOS --> IMS ZOS --> DB2 ZOS --> MQ

The workstation communicates with z/OS through z/OSMF. The Bank of Z UI drives business transactions through z/OS Connect EE, which fans out to CICS and IMS. Both CICS and IMS persist data in Db2, while IBM MQ handles asynchronous messaging between components.

4. Verify Development Environment

The development toolchain must be installed and accessible on the engineer’s workstation before any remote interaction with z/OS can take place.

4.1 Verify Java

Bank of Z build tooling and Zowe CLI require a Java runtime. Confirm availability with:

BASH 
java --version

Expected output (exact version may vary):

CODE 
openjdk 17.0.x 2024-xx-xx
OpenJDK Runtime Environment ...

4.2 Verify Git

Source control operations depend on Git. Confirm availability with:

BASH 
git --version

Expected output:

CODE 
git version 2.x.x

4.3 Verify Zowe CLI

Zowe CLI is the primary command-line interface for interacting with z/OS services from the workstation. Confirm availability with:

BASH 
zowe --version

Expected output:

CODE 
X.X.X

4.4 Verify z/OSMF Connectivity

With the toolchain confirmed, test end-to-end network connectivity to the z/OS environment:

BASH 
zowe zosmf check status

A successful response returns the z/OSMF server details and confirms the workstation can reach the target z/OS system. Any connection error at this stage indicates a network, firewall, or profile configuration issue that must be resolved before proceeding.

The sequence below illustrates the connectivity check flow:

sequenceDiagram participant DEV as Developer Workstation participant CLI as Zowe CLI participant ZOSMF as z/OSMF (z/OS) DEV->>CLI: zowe zosmf check status CLI->>ZOSMF: HTTPS GET /zosmf/info ZOSMF-->>CLI: 200 OK + server metadata CLI-->>DEV: ✅ Connection successful

5. Verify Target z/OS Environment

With workstation tooling confirmed, validate that the required IBM Z platform components are present and active on the target system.

5.1 Required Platform Components

The following subsystems must be available before Bank of Z artifacts can function:

Component Minimum Level Role
z/OS 3.1 Base operating system
CICS Current supported release Online transaction processing
IMS Transaction Manager Current supported release IMS transaction routing
IMS DB Current supported release Hierarchical database
Db2 for z/OS Current supported release Relational database
z/OS Connect Enterprise Edition Current supported release RESTful API gateway
IBM MQ Current supported release Asynchronous messaging

Note: If any required subsystem is unavailable, contact your system administrator before proceeding with application deployment or smoke testing.

5.2 Middleware Status Checks

Use the Zowe CLI to interrogate subsystem status remotely from the workstation, or use the native operator console commands directly on z/OS.

Check CICS region status via Zowe:

BASH 
zowe zos-console issue command "CEMT INQ TASK" --sysplex-system <LPAR>

Check Db2 subsystem status via operator console:

BASH 
zowe zos-console issue command "DISPLAY DB2,TYPE=ACTIVE"

Check IMS control region via operator console:

BASH 
zowe zos-console issue command "/DIS ACT"

Check IBM MQ queue manager:

BASH 
zowe zos-console issue command "DISPLAY QMGR"

6. Verify Application Deployment

Once the platform is confirmed healthy, verify that the Bank of Z application artifacts have been deployed correctly to each middleware layer.

6.2 Verify Load Modules

Confirm that the application load modules have been placed in the target partitioned data set (PDS/E):

BASH 
zowe zos-files list ds-members "BANKOFZ.LOADLIB"

Expected: a list of member names corresponding to the deployed Bank of Z programs.

6.3 Verify Db2 Tables and Plans

Confirm that tables exist and the application plan has been bound successfully:

BASH 
zowe zos-console issue command "DISPLAY DDF"

To check bound plans directly, issue the following from a Db2 command prompt or SPUFI:

SQL 
SELECT NAME, OWNER, VALID, OPERATIVE
FROM SYSIBM.SYSPLAN
WHERE NAME LIKE 'BANKOFZ%';

Expected: rows returned with VALID = 'Y' and OPERATIVE = 'Y'.

6.4 Verify IMS Application Resources

Confirm that the Bank of Z PSBs and DBDs have been loaded into the IMS subsystem:

BASH 
zowe zos-console issue command "/DIS PGM NAME=BANKOFZ*"

Expected: program entries listed with a status of NOTINIT or STOSCHD (available for scheduling).

6.5 Verify CICS Resource Definitions

Confirm that CICS resource definitions (transactions, programs, files) are installed and enabled:

BASH 
zowe zos-console issue command "CEMT INQ PROG(BANKOFZ*)"

Expected: program entries returned with Enabled status and a non-zero Length indicating the module is loaded.

6.6 Verify z/OS Connect API Artifacts

Confirm that the Bank of Z APIs are registered and reachable in z/OS Connect EE. Access the health endpoint:

BASH 
curl -k https://<ZCONN_HOST>:<PORT>/zosConnect/apis

Expected: a JSON response listing the deployed Bank of Z APIs with a status of started.

7. Smoke Testing — End-to-End Validation

With all platform and deployment checks passed, run the following smoke tests to confirm that the full application stack is functioning end-to-end. These tests exercise real transactions and data flows through the system.

7.1 Smoke Test Flow

The sequence diagram below illustrates the end-to-end flow exercised during smoke testing:

sequenceDiagram participant Tester participant UI as Bank of Z UI participant ZCONN as z/OS Connect EE participant CICS as CICS Region participant IMS as IMS TM participant DB2 as Db2 for z/OS Tester->>UI: Open Bank of Z UI UI-->>Tester: Login page rendered ✅ Tester->>UI: Authenticate (user credentials) UI->>ZCONN: POST /api/auth ZCONN->>CICS: EXEC CICS LINK PROGRAM(BOZBAUTH) CICS->>DB2: SELECT from USER_ACCOUNT DB2-->>CICS: User record returned CICS-->>ZCONN: Auth token issued ZCONN-->>UI: 200 OK + token UI-->>Tester: Dashboard displayed ✅ Tester->>UI: View account details UI->>ZCONN: GET /api/accounts/{id} ZCONN->>IMS: DL/I GU call (Account segment) IMS-->>ZCONN: Account data ZCONN-->>UI: Account JSON UI-->>Tester: Account details displayed ✅ Tester->>UI: Execute a transaction (transfer) UI->>ZCONN: POST /api/transactions ZCONN->>CICS: EXEC CICS START TRANSID(BOZT) CICS->>DB2: UPDATE ACCOUNT balance DB2-->>CICS: Commit confirmed CICS-->>ZCONN: Transaction ID returned ZCONN-->>UI: 201 Created UI-->>Tester: Transaction confirmation ✅

7.2 Smoke Test 1 — Access the User Interface

  1. Open a browser and navigate to the Bank of Z UI endpoint.
  2. Confirm the login page renders without errors.
  3. Log in with a valid test user account.
  4. Confirm the dashboard is displayed successfully.

Pass criteria: Login completes and the account dashboard is visible.

7.3 Smoke Test 2 — Retrieve User Information

  1. From the dashboard, navigate to the user profile section.
  2. Confirm that user details (name, account number, address) are returned and displayed correctly.

Pass criteria: User data is fetched and rendered without errors or timeouts.

7.4 Smoke Test 3 — View Account Details

  1. Select an account from the account list.
  2. Confirm that the account balance, account type, and transaction history are displayed.

Pass criteria: Account data is retrieved from IMS/Db2 and displayed without errors.

7.5 Smoke Test 4 — Execute an Account Transaction

  1. Initiate a fund transfer or deposit operation from the UI.
  2. Confirm the transaction is submitted and a confirmation number is returned.
  3. Confirm the updated balance reflects the transaction.

Pass criteria: Transaction is processed end-to-end, persisted in Db2, and the UI reflects the updated balance.

7.6 Smoke Test 5 — Invoke z/OS Connect APIs Directly

Invoke a deployed API endpoint directly using curl or a REST client to verify the API layer independently of the UI:

BASH 
# Retrieve account list for a test user
curl -k -X GET \
  https://<ZCONN_HOST>:<PORT>/api/v1/accounts \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json"

Expected response:

JSON 
{
  "accounts": [
    {
      "accountId": "000001234",
      "accountType": "CHECKING",
      "balance": 1500.00,
      "currency": "USD"
    }
  ]
}

Pass criteria: HTTP 200 response with valid account data in the JSON body.

8. Verification Results

A fully successful verification run confirms the following:

Area Expected Outcome
Development environment Java, Git, and Zowe CLI installed; z/OSMF reachable
z/OS platform All required subsystems (CICS, IMS, Db2, MQ, z/OS Connect EE) active
Application artifacts Load modules, Db2 plans, IMS resources, CICS definitions, and APIs deployed
Smoke tests All 5 end-to-end scenarios pass without errors
APIs z/OS Connect EE APIs return valid data with HTTP 200
Overall Bank of Z application environment is fully operational

If any check fails, refer to the relevant middleware or application deployment section of the installation guide and contact your system administrator if a platform-level issue is suspected.
