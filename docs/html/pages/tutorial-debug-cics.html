Tutorial: Debug a CICS Transaction

1. Overview

This tutorial walks you through debugging the Bank of Z INQCUST COBOL program — the CICS customer inquiry transaction — using IBM Z Open Debug in Visual Studio Code. The debug pipeline relies on two server-side daemons running on z/OS:

  • Debug Profile Service (DPS): Manages debug profiles that identify which transactions and user IDs to intercept, without disrupting other users sharing the same CICS region.
  • Remote Debug Service (RDS): Acts as a protocol bridge, routing a parked CICS task to your specific VS Code debug session via the Debug Adapter Protocol (DAP).

By the end of this tutorial you will know how to configure a Zowe debug profile, create a DPS intercept profile, trigger the INQCUST transaction, attach VS Code, set breakpoints, inspect variables, and diagnose common abend conditions.

2. System Architecture

The following diagram shows the high-level components involved in a Z Open Debug session and how they relate to each other.

graph TD A[Developer - VS Code + IBM Z Open Debug] -->|DAP protocol| B[Remote Debug Service - RDS\nPort 8194] B -->|Session handoff| C[Debug Profile Service - DPS\nPort 8192] C -->|Intercept trigger| D[CICS Region - CICSBOZ] D -->|Task parking| E[INQCUST COBOL Program] F[Bank of Z Web UI] -->|HTTP request| G[z/OS Connect EE] G -->|IPIC link| D

When a customer inquiry is submitted from the web UI, the request flows from the browser through z/OS Connect EE into the CICS region. If a matching DPS profile is active for the executing user ID, CICS suspends (parks) the INQCUST task and holds it until VS Code attaches. The RDS mediates between the DPS and the VS Code DAP client, delivering source-level debugging across the network.

The table below summarises each component’s role and its default port in the Bank of Z environment:

Component Role Default Port
Debug Profile Service (DPS) Stores and serves debug profiles; signals CICS to park a task 8192
Remote Debug Service (RDS) Protocol bridge between DPS and VS Code DAP 8194
IBM Z Open Debug (VS Code) DAP client; renders source, breakpoints, and variables —
z/OS Connect EE Exposes CICS services as REST APIs for the web frontend —

3. Prerequisites

Before starting, confirm that all of the following are in place:

  • The Bank of Z Quick Start has been completed and the application is built and deployed.
  • VS Code has the IBM Developer for z/OS Enterprise Edition (IDzEE) extension pack installed (this includes IBM Z Open Debug).
  • The Bank of Z CICS region is running and the OMEN transaction is reachable.
  • The INQCUST load module was compiled with the TEST or TEST(SOURCE) compiler option so that a side-file listing (.dbg) exists on USS.

4. Step 1 — Configure the Zowe zOpenDebug Profile

The Bank of Z repository ships a pre-configured zOpenDebug profile block in zowe.config.json with DPS port 8192 and RDS port 8194. You only need to supply the target host name and your credentials.

4.1 Set the Host in zowe.config.user.json

Copy zowe.config.user.json.template to zowe.config.user.json, then edit it to supply your z/OS host address:

JSON 
{
  "profiles": {
    "bank-of-z": {
      "properties": {
        "host": "192.168.1.10"
      },
      "secure": ["user", "password"]
    }
  }
}

4.2 Store Credentials in the Secure Store

BASH 
zowe config secure

Enter your TSO user ID and password when prompted. Credentials are encrypted and stored in the Zowe secure credential vault — they are never written in plain text to disk.

4.3 Verify the Profile Resolution

BASH 
zowe config list --root

Confirm that bank-of-z.zOpenDebug appears under defaults and that dpsPort: 8192 and rdsPort: 8194 are present.

5. Step 2 — Verify the VS Code Launch Configuration

The repository includes a ready-to-use debug launch configuration at .vscode/launch.json:

JSON 
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "zOpenDebug",
      "request": "launch",
      "name": "Z Open Debug: Connect to a parked debug session",
      "connection": {
        "type": "zowe",
        "name": "bank-of-z.zOpenDebug"
      }
    }
  ]
}

The type: "zOpenDebug" and request: "launch" combination instructs Z Open Debug to connect to a session that is already parked on the DPS — that is, a CICS task that has been intercepted and is waiting for a debugger to attach. All connection details (host, ports, credentials) are sourced automatically from the Zowe profile configured in Step 1.

6. Step 3 — Create a Debug Profile Service Profile

A DPS profile tells CICS which programs to intercept and restricts interception to a specific TSO user ID, so that other users sharing the CICS region are unaffected.

6.1 Open the Z/OS Debugger Profiles View

In the VS Code Activity Bar, open the Zowe Explorer panel. Locate the Z/OS DEBUGGER PROFILES section and expand the Debug Profiles tree node.

6.2 Create a New CICS Profile

Right-click CICS and select Create. Fill in the fields as follows:

Field Example Value
Profile name INQCUST-debug
CICS system CICSBOZ (your region name)
Load module / program INQCUST
Qualified user ID CICSUSER (your TSO user ID)

Click Save. The profile is registered with the DPS daemon on z/OS.

6.3 Activate the Profile

Right-click the newly created profile and select Activate for Debug. A bug icon with a green dot appears next to the profile entry to confirm it is active.

Important: The profile must be active before you trigger the transaction. Any invocation of INQCUST under the specified user ID will now be intercepted and parked until VS Code attaches.

7. Step 4 — Trigger the CICS Transaction

Open the Bank of Z web application and look up a customer whose ID starts with C (for example, C0001). The UI dispatches the request through the following chain:

sequenceDiagram participant UI as Bank of Z Web UI participant ZC as z/OS Connect EE participant CICS as CICS Region participant DPS as Debug Profile Service participant VSC as VS Code / Z Open Debug UI->>ZC: HTTP GET /customers/C0001 ZC->>CICS: IPIC link → INQCUST CICS->>DPS: Check active profiles for CICSUSER DPS-->>CICS: Profile match — park task CICS-->>DPS: Task parked (waiting) VSC->>DPS: Attach to parked session (F5) DPS-->>VSC: Session handed off VSC-->>CICS: Resume execution under debugger control

Note: A 5-minute request timeout is configured in the z/OS Connect cics.xml file (requestTimeout attribute of the zosconnect_cicsIpicConnection tag). If you need longer debug sessions, increase this value before triggering the transaction. The cics.xml file is generated by .setup/setup/setup-zosconnect-server.sh.

8. Step 5 — Attach the Debug Session in VS Code

8.1 Open the Run and Debug View

Press Ctrl+Shift+D (Windows/Linux) or ⇧⌘D (macOS) to open the Run and Debug panel.

8.2 Select the Launch Configuration

From the configuration dropdown at the top of the panel, select Z Open Debug: Connect to a parked debug session.

8.3 Start Debugging

Press F5 or click the green Start Debugging arrow.

Z Open Debug contacts the RDS at port 8194, which retrieves the parked session from the DPS at port 8192. VS Code opens the INQCUST COBOL source file and the program counter stops at the first intercepted line, ready for interactive debugging.

9. Step 6 — Set Breakpoints and Inspect Storage

9.1 Setting Breakpoints

Click in the gutter (left margin) of the INQCUST source file next to any executable statement to set a breakpoint. A solid red circle confirms the breakpoint is verified — meaning the debug runtime has matched it to a statement in the compiled listing.

Tip: If a breakpoint appears as a hollow (unverified) circle, the source file in VS Code does not match the listing file on z/OS. Rebuild the program and ensure you are viewing the same source version that was compiled.

9.2 Stepping Through Code

Use the standard VS Code debug toolbar to control execution:

Action Shortcut Behaviour
Continue F5 Run to the next breakpoint or program end
Step Over F10 Execute the current COBOL statement; stay at the same nesting level
Step Into F11 Step into a called sub-program or PERFORM paragraph
Step Out ⇧F11 Run to the end of the current program or paragraph
Stop ⇧F5 Terminate the session; the CICS task abends with ADBS

9.3 Inspecting Variables and Storage

While stopped at a breakpoint, use the Variables panel (left side of the Debug view) to inspect Working Storage and Linkage Section fields. You can:

  • Hover over a variable name in the source editor to see its current value in a tooltip.
  • Expand group-level items to drill down into nested data structures.
  • Watch specific fields by adding them to the Watch panel for continuous monitoring as you step.

10. Troubleshooting

The table below covers the most common issues encountered when debugging INQCUST and how to resolve them.

Symptom Likely Cause Resolution
VS Code cannot connect to a parked session Transaction ran and completed before F5 was pressed; profile was not active Ensure the DPS profile is activated before triggering the transaction, then trigger again
Source not shown — only assembler disassembly Listing file not found or .zdx.json path is incorrect Verify the USS listing path in .zdx.json; confirm the build produced a .dbg side file
CICS transaction abends with ADBS Debug session was terminated (Stop) rather than disconnected Use Disconnect instead of Stop to allow the CICS task to complete normally
Other users’ transactions are being intercepted DPS profile userId field was left blank or wildcarded Edit the profile and set userId to your specific TSO user ID
RDS connection refused Port 8194 is blocked or the RDS started task is not running Check network access to the z/OS host on port 8194; verify the RDS started task is active
Breakpoints shown as unverified (hollow circles) Source in VS Code does not match the compiled listing on z/OS Ensure you are viewing the same source version that was compiled; rebuild if necessary
