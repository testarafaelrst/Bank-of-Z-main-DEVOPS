Commands Reference

This reference guide documents all CLI commands, workflow scripts, and utility tools used to build, deploy, and manage the Bank of Z application. It covers Zowe CLI commands for z/OS connectivity, Git commands for source control, environment verification utilities, automation scripts, and documentation management tools. Use this page as a single-stop reference when setting up your development environment, running build pipelines, or contributing to the project.

1. System Architecture

The Bank of Z toolchain spans both local developer workstations and the remote z/OS USS (Unix System Services) environment. The diagram below illustrates how the major components and workflows relate to one another.

graph TD DEV[Developer Workstation] VSC[VS Code + Tasks] GIT[Git Repository] ZOWE[Zowe CLI] ZOSMF[z/OSMF on z/OS] USS[z/OS USS Environment] DBB[IBM DBB Build] DEPLOY[Deployment Target] SCRIPTS[Workflow Scripts\nsetup-local.sh / pipeline-local.sh] REMOTE[Remote Scripts\nsetup-common.sh / pipeline-remote.sh] DOCS[Documentation Scripts\nconvert_dita_to_md.py] DEV --> VSC DEV --> GIT DEV --> SCRIPTS VSC --> SCRIPTS SCRIPTS -->|Zowe CLI| ZOSMF SCRIPTS -->|SSH / RSE API| USS ZOSMF --> USS USS --> REMOTE REMOTE --> DBB DBB --> DEPLOY GIT -->|push/pull| DEV DOCS --> GIT

The developer workstation is the entry point for all actions. VS Code tasks and local scripts orchestrate calls to z/OS through Zowe CLI and the RSE API plug-in, while USS-side scripts execute the actual build and deployment steps using IBM Dependency Based Build (DBB).

The Bank of Z command ecosystem is organized into five functional areas:

3. Zowe CLI Commands

Zowe CLI is the primary interface for interacting with z/OS systems from the developer workstation. All Bank of Z automation workflows depend on a correctly configured Zowe CLI installation.

3.1 Verify Installation

BASH 
zowe --version

Displays the installed Zowe CLI version. Run this first to confirm Zowe CLI is available before executing any other commands.

3.2 Install the RSE API Plug-in

BASH 
zowe plugins install @zowe/rse-api-for-zowe-cli

Installs the RSE API plug-in, which is required by the Bank of Z setup workflow to transfer files and execute commands on z/OS USS.

3.3 Create a z/OSMF Profile

BASH 
zowe profiles create zosmf-profile myprofile \
  --host your-zos-host \
  --port 443 \
  --user your-userid

Creates a named z/OSMF connection profile. Replace your-zos-host and your-userid with the values for your environment.

3.4 Verify Connectivity

BASH 
zowe zosmf check status

Validates that the currently active z/OSMF profile can reach the z/OS host. Always run this after creating or modifying a profile.

3.5 List Available Profiles

BASH 
zowe profiles list zosmf

Lists all configured z/OSMF profiles so you can confirm the correct profile exists before setting it as the default.

3.6 Set a Default Profile

BASH 
zowe profiles set-default zosmf myprofile

Sets the named profile as the default for all subsequent Zowe CLI commands, removing the need to specify --profile on every invocation.

4. Git Commands

Git is used to manage all source code changes for Bank of Z and to collaborate with other contributors through a shared remote repository.

4.1 Clone a Repository

BASH 
git clone <repository-url>

Creates a local copy of the Bank of Z repository. Run this once when setting up a new workstation.

4.2 Create a Branch

BASH 
git checkout -b feature/my-change

Creates and immediately switches to a new feature branch. All development work should be done on a dedicated branch rather than directly on main.

4.3 View Status

BASH 
git status

Displays modified, staged, and untracked files, giving a snapshot of the current working-tree state.

4.4 Commit Changes

BASH 
git add .
git commit -m "Describe your change"

Stages all modified files and records them as a commit. Write a clear, concise commit message that describes the intent of the change.

4.5 Push Changes

BASH 
git push origin <branch-name>

Pushes the local commits on the specified branch to the remote repository, making them available for review and integration.

6. USS Verification Commands

These commands validate the z/OS Unix System Services (USS) environment before running build or deployment pipelines.

6.1 Verify Git Availability

BASH 
which git
git --version

Confirms that Git is installed and available on the USS PATH. Both commands should succeed before attempting any source-code operations on USS.

6.2 Verify DBB Installation

BASH 
ls $DBB_HOME/lib

Verifies that the IBM Dependency Based Build (DBB) installation is accessible via the $DBB_HOME environment variable. A successful listing of the lib directory confirms DBB is correctly configured.

6.3 Verify Java Configuration

BASH 
$JAVA_HOME/bin/java -version

Ensures the Java runtime referenced by $JAVA_HOME is available. DBB requires a valid Java installation to execute build scripts.

7. Workflow Scripts

The Bank of Z automation layer is divided into four shell scripts that together cover the full lifecycle from local initiation through remote build and deployment on z/OS USS.

7.1 Script Inventory

Script Execution Context Purpose
setup-local.sh Developer workstation Initiates environment setup activities from the local machine
setup-common.sh z/OS USS Performs environment setup steps on the USS side
pipeline-local.sh Developer workstation Initiates the build and deployment processing sequence
pipeline-remote.sh z/OS USS Runs the actual build and deployment activities on USS

7.2 Script Execution Flow

The diagram below shows the sequence of events when a developer triggers either the setup or pipeline workflow.

sequenceDiagram participant DEV as Developer Workstation participant LOC as setup-local.sh / pipeline-local.sh participant ZOWE as Zowe CLI (RSE API) participant USS as z/OS USS participant REM as setup-common.sh / pipeline-remote.sh participant DBB as IBM DBB DEV->>LOC: Execute local script (or VS Code task) LOC->>ZOWE: Authenticate & transfer files ZOWE->>USS: Upload scripts and source USS->>REM: Invoke remote script REM->>DBB: Trigger build / deployment DBB-->>REM: Build results REM-->>USS: Write logs USS-->>ZOWE: Return output ZOWE-->>LOC: Stream results LOC-->>DEV: Display status

7.3 Zowe CLI Workflow Entry Point

The Zowe CLI workflow can be launched from VS Code without opening a terminal:

  1. Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P).
  2. Run Tasks: Run Task.
  3. Select Setup Bank of Z Environment.

Alternatively, run setup-local.sh directly from a terminal for the same effect. For full configuration details, see the Zowe CLI Workflow guide.

7.4 GRUB Workflow

The GRUB workflow synchronizes local changes to USS and then triggers the Bank of Z setup process. It is an alternative to the Zowe CLI workflow and is suited to environments where direct USS access is available. See the GRUB Workflow guide for environment-specific configuration and run procedures.

8. Documentation Scripts

The scripts/ directory contains Python utilities for managing the Bank of Z documentation site.

8.1 convert_dita_to_md.py

Converts DITA XML source files into Markdown and automatically generates a dynamic Table of Contents.

8.1.1 Usage

BASH 
python3 scripts/convert_dita_to_md.py

8.1.2 Prerequisites

Install the required Python dependency before running the script:

BASH 
pip3 install pyyaml

8.1.3 Processing Steps

The script performs the following steps in sequence:

graph LR A[Scan Docs/ folder\nfor DITA files] --> B[Convert DITA XML\nto Markdown] B --> C[Create organized\nfolder structure in docs/] C --> D[Generate section\nindex pages] D --> E[Write _data/toc.yml]
  1. Scans the Docs/ folder for .dita files.
  2. Converts DITA XML markup to Markdown format.
  3. Creates an organized folder structure under docs/.
  4. Generates _data/toc.yml automatically.
  5. Creates index pages for each documentation section.

8.1.4 Example Transformation

BASH 
# Input — DITA source file
Docs/com.ibm.tutorials.doc/getting-started.dita

# Output — Markdown and navigation artifacts
docs/tutorials/getting-started.md
docs/tutorials/index.md
_data/toc.yml  (updated)

8.2 Adding New Scripts

Place additional documentation management scripts in the scripts/ directory. Follow these conventions:

  • Descriptive names: e.g., convert_dita_to_md.py, generate_pdf_docs.py
  • Underscore word separators: avoid hyphens or spaces in filenames
  • .py extension for all Python scripts

Every script should include:

  • A docstring explaining its purpose
  • Usage instructions
  • A list of dependencies
  • An example showing expected output
