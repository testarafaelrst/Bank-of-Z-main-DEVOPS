CICS COBOL Program Examples

This technical document provides application-level documentation for two core CICS COBOL program patterns within the Bank of Z core banking application:

  1. BNKMENU: An interactive, pseudo-conversational 3270 terminal hub utilizing Basic Mapping Support (BMS) for operator navigation and transaction dispatching.
  2. CRDTAGY2: A non-terminal, asynchronous background task simulating an external credit bureau service utilizing modern CICS Channels and Containers alongside CICS Async API paradigms.

1. Overview

Enterprise mainframe banking architectures combine online interactive screen processing with decoupled, background micro-services. Within the Bank of Z application suite:

  • BNKMENU acts as the primary user-facing front door for terminal operators. Operating under the OMEN transaction identifier, it presents a 3270 terminal menu, parses user Attention Identifier (AID) keys, validates numeric and alphabetic menu choices, and immediately routes execution to targeted business transactions (such as customer inquiry, account creation, or fund transfers) via pseudo-conversational transfers.
  • CRDTAGY2 serves as an asynchronous credit scoring simulator. When banking transactions require a customer credit evaluation, they initiate CRDTAGY2 as an asynchronous child task. The program fetches the customer record from a shared CICS channel, simulates external network latency using EXEC CICS DELAY, computes a randomized credit rating, updates the container payload, and returns the result to allow parent transaction retrieval.

2. System Architecture

The Bank of Z architecture separates synchronous presentation logic from asynchronous background processing. Both program archetypes integrate into the centralized diagnostic subsystem ABNDPROC for structured incident telemetry.

2.1 Architecture and Component Interaction Text Description

  1. Terminal Navigation (BNKMENU): The user interacts with the terminal via BMS mapset BNK1MAI (map BNK1ME). BNKMENU inspects the Execution Interface Block (EIBCALEN and EIBAID). It dynamically selects the map transmission mode (ERASE, DATAONLY, or DATAONLY ALARM) and transfers control immediately to business transactions (ODCS through OCCA) or loops back to itself (OMEN).
  2. Channel-Driven Asynchronous Simulation (CRDTAGY2): Parent transactions instantiate CRDTAGY2 passing the CIPCREDCHANN channel containing the CIPB container with CUSTOMER-RECORD data. CRDTAGY2 executes without terminal dependency, modifying the shared container.
  3. Unified Incident Telemetry: Both programs monitor the EIBRESP and EIBRESP2 status codes for all CICS commands. Any unhandled non-normal response populates an ABNDINFO-REC structure containing task numbers, timestamps, transaction codes, and formatted failure descriptions, delegating logging to ABNDPROC.

3. BNKMENU — Online Banking Navigation Hub

3.1 Purpose and Interaction Model

BNKMENU is an interactive BMS menu router designed using CICS pseudo-conversational standards. To conserve mainframe resources, the program terminates its task after presenting the screen and registers a follow-up transaction (OMEN) with a 1-byte communication area (COMMAREA). When the terminal user responds, CICS initiates a new task instance.

3.3 Transaction Dispatching and Navigation Mapping

When the user enters a valid single-character option in ACTIONI, BNKMENU issues EXEC CICS RETURN TRANSID(...) IMMEDIATE. The IMMEDIATE option bypasses asynchronous transaction queues and directs the terminal directly to the requested application:

Action Code Target Transaction Functional Target
'1' ODCS Display Customer Details
'2' ODAC Display Account Details
'3' OCCS Create New Customer
'4' OCAC Create New Account
'5' OUAC Update Account Details
'6' OCRA Credit / Debit Funds
'7' OTFN Transfer Funds Between Accounts
'A' OCCA Look Up Accounts by Customer

                   TRANSID ('OCCA')
                   IMMEDIATE
                   RESP    (WS-CICS-RESP)
                   RESP2   (WS-CICS-RESP2)
               END-EXEC
           END-IF.

3.4 Error Handling and Abend Diagnostics

BNKMENU handles errors through two distinct recovery mechanisms:

  1. User-Correctable Errors: Input validation failures or unhandled AID keys preserve the session. The program sets SEND-FLAG to SEND-DATAONLY-ALARM, writes the error message to MESSAGEO, positions the cursor via ACTIONL = -1, and updates the screen with a 3270 audible beep.
  2. System/CICS Failures: Any non-normal EIBRESP triggers diagnostic capture in ABNDINFO-REC and invokes ABNDPROC:

4. CRDTAGY2 — Asynchronous Credit Agency Simulator

4.1 Purpose and Execution Model

CRDTAGY2 is a background CICS program running without terminal attachment. Injected as an asynchronous child task by a parent banking transaction, it emulates third-party credit bureau latencies and scoring.

  • Latency Simulation: Uses FUNCTION RANDOM seeded with EIBTASKN (the unique CICS Task Number) to pause the task for 1 to 3 seconds via EXEC CICS DELAY.
  • Score Generation: Uses subsequent calls to FUNCTION RANDOM to compute an integer score between 1 and 999.
  • Parent Timeout Behavior: The parent transaction executes a non-blocking FETCH CHILD with a 3.0-second timeout. Because CRDTAGY2 delays between 1 and 3 seconds, approximately 1 out of 4 executions will exceed the parent timeout window, reproducing realistic external service timeouts.

4.2 Data Structures and Channel/Container Interaction

CRDTAGY2 bypasses legacy COMMAREA size limits (32 KB) by utilizing CICS Channels and Containers. It interacts with channel CIPCREDCHANN and container CIPB, which encapsulates the CUSTOMER-RECORD layout.

4.3 Processing Logic and Sequence

4.4 Error Handling and Diagnostic Telemetry

CRDTAGY2 implements differentiated error response paths:

  • EXEC CICS DELAY Failure: Triggers comprehensive abend handling, linking to ABNDPROC with error payload ABNDINFO-REC and abending with code PLOP.
  • GET CONTAINER / PUT CONTAINER Failure: Writes diagnostic information to the system log using DISPLAY and performs an early exit via EXEC CICS RETURN.

Code Example: Container Operations in CRDTAGY2

COBOL 
MOVE LENGTH OF WS-CONT-IN TO WS-CONTAINER-LEN.
           EXEC CICS GET CONTAINER (WS-CONTAINER-NAME)
                           CHANNEL (WS-CHANNEL-NAME)
                           INTO    (WS-CONT-IN)
                           FLENGTH (WS-CONTAINER-LEN)
                           RESP    (WS-CICS-RESP)
                           RESP2   (WS-CICS-RESP2)
           END-EXEC.

           IF WS-CICS-RESP NOT = DFHRESP(NORMAL)
               DISPLAY 'CRDTAGY2 - UNABLE TO GET CONTAINER. RESP='
                       WS-CICS-RESP ' RESP2=' WS-CICS-RESP2
               PERFORM GMOFH010-GET-ME-OUT-OF-HERE
           END-IF.

      * Calculate credit score between 1 and 999
           COMPUTE WS-NEW-CREDSCORE = ((999 - 1) * FUNCTION RANDOM) + 1.
           MOVE WS-NEW-CREDSCORE TO CUSTOMER-CREDIT-SCORE OF WS-CONT-IN.

           MOVE LENGTH OF WS-CONT-IN TO WS-CONTAINER-LEN.
           EXEC CICS PUT CONTAINER (WS-CONTAINER-NAME)
                           FROM    (WS-CONT-IN)
                           FLENGTH (WS-CONTAINER-LEN)
                           CHANNEL (WS-CHANNEL-NAME)
                           RESP    (WS-CICS-RESP)
                           RESP2   (WS-CICS-RESP2)
           END-EXEC.

           IF WS-CICS-RESP NOT = DFHRESP(NORMAL)
               DISPLAY 'CRDTAGY2 - UNABLE TO PUT CONTAINER. RESP='
                       WS-CICS-RESP ' RESP2=' WS-CICS-RESP2
               PERFORM GMOFH010-GET-ME-OUT-OF-HERE
           END-IF.

       GMOFH010-GET-ME-OUT-OF-HERE.
           EXEC CICS RETURN END-EXEC.

5. Comparative Summary and Integration Patterns

5.1 Interactive BMS vs Asynchronous Channels/Containers

The following matrix compares the architectural patterns implemented across BNKMENU and CRDTAGY2:

Architectural Feature BNKMENU CRDTAGY2
Program Role Interactive Front-End Navigation Hub Asynchronous Background Scoring Engine
Execution Pattern Pseudo-conversational (Session-driven) Asynchronous Child Task (API Async)
User Interface BMS Map (BNK1ME in BNK1MAI) Headless (No Terminal / No Screen)
Data Exchange Medium 1-Byte DFHCOMMAREA + BMS Screen buffer CICS Channel (CIPCREDCHANN) & Container (CIPB)
Primary CICS Commands SEND MAP, RECEIVE MAP, RETURN TRANSID IMMEDIATE DELAY FOR SECONDS, GET CONTAINER, PUT CONTAINER
Randomization / Timing Event-driven by operator keystrokes FUNCTION RANDOM(EIBTASKN) + EXEC CICS DELAY
Abend Code HBNK (with NODUMP) PLOP (with default dump)
Downstream Linkage Immediate transaction routing (RETURN TRANSID) Parent transaction collects data via FETCH CHILD
