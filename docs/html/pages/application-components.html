1. Application Components

The Bank of Z application consists of several application and infrastructure components that work together to provide a unified banking experience. These components enable the application to deliver modern web-based banking services while leveraging proven IBM Z transaction-processing technologies, hybrid data stores, and enterprise messaging infrastructure.

1.1. Overview

Bank of Z is architected as a hybrid enterprise banking solution. It decouples customer-facing interactions from backend transactional workloads through a modern API gateway. Core banking functions—including customer management, account administration, and transaction processing—are distributed across dual transaction processing runtimes (CICS and IMS TM), supported by Db2 for z/OS relational tables and IMS hierarchical databases. Asynchronous inter-bank communications and cross-system fund transfers are facilitated by IBM MQ messaging to external institutions such as Bank of Q.

1.3. Presentation Tier

1.3.1. Bank of Z UI

The Bank of Z user interface provides a responsive, browser-based experience for performing everyday banking operations. Customers and bank personnel can manage customer profiles, open and monitor accounts, and execute fund transfers through a single application interface. The UI abstracts backend processing paths, allowing users to interact with services seamlessly regardless of whether a transaction is handled by CICS or IMS.

1.4. API Integration Layer

1.4.1. z/OS Connect

z/OS Connect acts as the secure, high-performance API abstraction layer between the Bank of Z UI and backend mainframe transaction processors. It exposes RESTful APIs to client applications and converts incoming JSON payloads into binary data structures (such as COBOL copybook layouts) consumed by CICS programs and IMS transactions.

1.5. Transaction Processing Systems

1.5.1. Customer Information Control System (CICS)

CICS delivers high-volume transaction processing for the CICS processing path within Bank of Z. CICS programs handle core business logic, including:

  • Customer record lookups and updates
  • Real-time balance inquiries and debit/credit ledger operations
  • Writing transaction auditing records to relational storage

1.5.2. IMS Transaction Manager (IMS TM)

IMS TM provides transaction-processing services for the IMS processing path. It processes incoming banking requests concurrently with CICS, managing:

  • Customer lifecycle operations
  • Account balance modifications and validations
  • Transaction settlement using DL/I and embedded SQL interfaces

1.6.1. Money and Account Management Db2 Database

The Money and Account Management Db2 database serves as the primary relational data store for the CICS processing path. It stores active customer records, account master data, and pending transactions. It is also accessible by IMS transactions requiring unified relational account verification.

1.6.2. Money and Account Management IMS Database

The Money and Account Management IMS database provides hierarchical data storage tailored for the IMS processing path. It allows IMS applications to retrieve and manipulate customer profiles and segment-based account hierarchies with high throughput and low latency.

1.6.3. Account History Db2 Database

The Account History Db2 database stores historical account activities, past statements, and audit logs. This dedicated repository supports customer inquiry workflows, compliance tracking, and periodic reporting without impacting transaction processing performance in active ledger tables.

1.7. Messaging and Inter-System Integration

1.7.1. IBM MQ

IBM MQ provides enterprise-grade message queuing for asynchronous communication between Bank of Z and external entities. It ensures guaranteed message delivery, transactional message integrity, and decoupling between independent banking platforms.

1.7.2. Bank of Q

Bank of Q represents an external banking institution that integrates with Bank of Z via IBM MQ. This integration facilitates inter-bank scenarios, including external wire transfers and clearinghouse reconciliations.

1.8.2. Asynchronous External Transfer Flow

When a transaction involves external institutions like Bank of Q, Bank of Z coordinates transactional updates and message queues across boundaries.
