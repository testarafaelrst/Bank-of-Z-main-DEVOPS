Tutorial: CICS Enhancement Scenario

This tutorial walks through a typical IBM Z development workflow. You enhance the CICS-based implementation of Bank of Z by adding a new customer email field. You analyze the application, plan the change, implement it, deploy it, and validate it. The tools used are Z Understand, Bob AI, IBM Z Open Editor, and the Bank of Z build and deployment pipeline.

1. Overview

1.1 Purpose

The tutorial shows how to enhance an existing CICS application in a structured way. The enhancement adds an email field to the customer data. It touches several layers of the application: database definitions, COBOL programs, and the web application used for verification.

1.2 Prerequisites

Before you start, make sure that you have:

  • Completed the Quick Start
  • Successfully built and deployed Bank of Z
  • A working Bank of Z development environment

1.3 What You Will Learn

By completing this tutorial, you will learn how to:

  • Understand the CICS application architecture and request flow
  • Analyze the impact of an application enhancement
  • Plan application changes using Bob AI and Z Understand
  • Modify application artifacts, including database definitions and COBOL programs
  • Use IBM Z Open Editor features to navigate and review application code
  • Build and deploy updated CICS application components
  • Verify the enhancement using the Bank of Z web application

1.4 Tutorial Structure

The tutorial has two parts. Each part is a video demonstration.

Part Focus Main Tools
Part 1 Understand and plan the enhancement Z Understand, Bob AI
Part 2 Implement and validate the enhancement IBM Z Open Editor, Bob AI, build and deployment pipeline, Bank of Z web application

2. System Architecture

2.1 Application and Tooling Components

The enhancement affects the CICS application components and uses several development tools. The diagram below shows how they relate.

graph TD Dev[Developer] --> ZU[Z Understand] Dev --> Bob[Bob AI] Dev --> ZOE[IBM Z Open Editor] ZU --> Plan[Impact Analysis and Implementation Plan] Bob --> Plan Plan --> Artifacts[Application Artifacts] ZOE --> Artifacts Artifacts --> DBDef[Database Definitions] Artifacts --> COBOL[COBOL Programs] Artifacts --> Pipeline[Build and Deployment Pipeline] Pipeline --> CICS[CICS Application on z/OS] CICS --> DB[(Customer Data)] Web[Bank of Z Web Application] --> CICS Dev --> Web

The diagram shows these relationships:

  • Z Understand and Bob AI support analysis and planning.
  • IBM Z Open Editor is used to navigate and modify the COBOL programs and other artifacts.
  • The build and deployment pipeline takes the updated artifacts, which include database definitions and COBOL programs, and deploys them to the CICS environment.
  • The Bank of Z web application is the front end used to verify the enhancement.

2.2 Request Flow

Part 1 of the tutorial traces the application data flow. The diagram below gives a generalized view of how a request moves through the system. The exact programs and transactions are shown in the demonstration.

sequenceDiagram participant User participant Web as Bank of Z Web Application participant CICS as CICS Application (COBOL) participant DB as Database User->>Web: Enter or view customer details Web->>CICS: Send request CICS->>DB: Read or write customer record DB-->>CICS: Customer data (including email) CICS-->>Web: Response Web-->>User: Display result

The enhancement adds the email field at the database layer. It also adds it in the COBOL programs that handle customer data, so that the value is stored, retrieved, and returned to the web application.

3. Development Workflow

The tutorial follows a plan, implement, deploy, and verify lifecycle.

graph LR A[Explore Codebase] --> B[Understand Architecture] B --> C[Impact Analysis] C --> D[Trace Data Flow] D --> E[Implementation Plan and Checklist] E --> F[Update Artifacts] F --> G[Implement Code Changes] G --> H[Build and Deploy] H --> I[Validate Database Updates] I --> J[Verify in Web Application]

The first five steps belong to Part 1. The remaining steps belong to Part 2.

4. Part 1: Understand and Plan the Enhancement

4.1 Objective

In this part you analyze the existing application, identify the components that the enhancement affects, and generate an implementation plan.

4.2 Topics Covered

The demonstration covers:

  • Exploring the Bank of Z codebase using Z Understand
  • Understanding the CICS application architecture
  • Performing impact analysis
  • Tracing the application data flow
  • Generating an implementation plan
  • Creating an implementation checklist

4.3 Planning Activities

graph TD Start[Enhancement Request: Add Customer Email] --> Explore[Explore Codebase with Z Understand] Explore --> Arch[Understand CICS Architecture] Arch --> Impact[Perform Impact Analysis] Impact --> Flow[Trace Data Flow] Flow --> PlanGen[Generate Implementation Plan with Bob AI] PlanGen --> Checklist[Create Implementation Checklist]

Each activity builds on the one before it:

  1. Explore: Z Understand shows the structure of the codebase.
  2. Architecture: You learn how CICS components interact.
  3. Impact analysis: You identify which artifacts, such as database definitions and COBOL programs, must change.
  4. Data flow: You trace how customer data moves through the application.
  5. Plan and checklist: You turn the findings into an ordered plan and a checklist for implementation.

5. Part 2: Implement and Validate the Enhancement

5.1 Objective

In this part you implement the planned enhancement, deploy the updated application, and verify the results.

5.2 Topics Covered

The demonstration covers:

  • Updating application artifacts
  • Reviewing and implementing code changes
  • Using IBM Z Open Editor to navigate and modify COBOL programs
  • Using Bob AI to assist with implementation
  • Running the Bank of Z build and deployment pipeline
  • Validating database updates
  • Verifying the enhancement through the Bank of Z web application

5.3 Implementation Sequence

sequenceDiagram participant Dev as Developer participant Bob as Bob AI participant ZOE as IBM Z Open Editor participant Pipe as Build and Deployment Pipeline participant CICS as CICS Environment participant DB as Database participant Web as Bank of Z Web Application Dev->>Bob: Request implementation assistance Bob-->>Dev: Suggested changes Dev->>ZOE: Update database definitions and COBOL programs Dev->>Pipe: Run build and deployment Pipe->>CICS: Deploy updated components Pipe->>DB: Apply database definition changes Dev->>DB: Validate database updates Dev->>Web: Verify email field end to end Web->>CICS: Request customer data CICS->>DB: Access customer record DB-->>CICS: Customer data with email CICS-->>Web: Response Web-->>Dev: Email field displayed

5.4 Key Activities

Activity Tool Result
Update application artifacts IBM Z Open Editor, Bob AI Database definitions and COBOL programs include the email field
Review and implement code changes IBM Z Open Editor Changes are navigated, reviewed, and applied in the COBOL source
Build and deploy Bank of Z pipeline Updated components are deployed to CICS
Validate database updates Database tooling The new field is present and populated as expected
Verify the enhancement Bank of Z web application The email is visible and works through the full request flow

6. Outcome

When you finish this tutorial, you will have planned, implemented, deployed, and verified a CICS application enhancement using the Bank of Z development workflow. You will also have used modern IBM Z development tools to understand an existing codebase, implement changes, and validate the results.

6.1 Summary of Skills Gained

  • Analyzing an existing CICS application with Z Understand
  • Planning changes and building a checklist with Bob AI
  • Modifying database definitions and COBOL programs with IBM Z Open Editor
  • Using the build and deployment pipeline to roll out CICS application changes
  • Verifying changes end to end through the Bank of Z web application
