Zowe CLI & Profile Setup

1. Overview

Zowe CLI is a command-line interface that enables developers to interact with IBM Z systems from a local workstation. For the Bank of Z project, Zowe CLI is a core component of the deployment toolchain — it communicates with z/OS Unix System Services (USS) to create workspace directories, clone the repository remotely, and execute setup commands on the target system.

A Zowe profile (stored in ~/.zowe/zowe.config.json) centralizes all connection details — host, ports, credentials, and service endpoints — into a single configuration file. This profile is shared across tools: both the Zowe CLI deployment scripts and IDE extensions such as Zowe Explorer and IBM Z Open Debug read from the same profile, so you only need to configure it once.

This page covers the full setup lifecycle:

  1. Creating and configuring the Zowe profile
  2. Installing Zowe CLI and required plug-ins
  3. Verifying connectivity to your z/OS system

The shared Zowe profile acts as the single source of truth for all connectivity. Every tool — whether the CLI, the IDE extension, or the debugger — reads from the same zowe.config.json, eliminating configuration drift between tools.

4. Zowe Profile Setup

4.1 What Is a Zowe Profile?

A Zowe profile stores connection details used by both IDE extensions and the Zowe CLI to communicate with a z/OS system. The profile is defined in ~/.zowe/zowe.config.json and contains sub-profiles for each service type:

Profile Type Service Default Port
zosmf z/OS Management Facility 10443
rseapi IBM RSE API 8195
ssh Secure Shell 22
tso TSO/E N/A
zOpenDebug IBM Z Open Debug DPS: 8192, RDS: 8194

4.2 Creating the Profile

Create the file ~/.zowe/zowe.config.json with the content below. You must update the fields marked with <...> for your specific environment:

  • host — Hostname or IP address of your z/OS system
  • account — Your TSO account number
  • logonProcedure — Your TSO logon procedure
  • Ports — Update if your environment uses non-default ports
JSON 
{
  "$schema": "./zowe.schema.json",
  "profiles": {
    "BankOfZDemo": {
      "properties": {
        "host": "<your host>",
        "rejectUnauthorized": false
      },
      "secure": ["user", "password"],
      "profiles": {
        "rseapi": {
          "type": "rse",
          "properties": {
            "port": 8195,
            "basePath": "rseapi",
            "protocol": "https"
          }
        },
        "zosmf": {
          "type": "zosmf",
          "properties": {
            "port": 10443
          }
        },
        "ssh": {
          "type": "ssh",
          "properties": {
            "port": 22
          }
        },
        "tso": {
          "type": "tso",
          "properties": {
            "account": "<account>",
            "codePage": "1047",
            "logonProcedure": "<logon procedure>"
          }
        },
        "zOpenDebug": {
          "type": "zOpenDebug",
          "properties": {
            "dpsPort": 8192,
            "rdsPort": 8194,
            "dpsContextRoot": "api/v1",
            "dpsSecured": true,
            "authenticationType": "basic",
            "uuid": "4267a0f6-b756-4f3c-b900-0b959b4567c3"
          }
        }
      }
    }
  },
  "defaults": {
    "zosmf": "BankOfZDemo.zosmf",
    "tso": "BankOfZDemo.tso",
    "ssh": "BankOfZDemo.ssh",
    "rse": "BankOfZDemo.rseapi",
    "zOpenDebug": "BankOfZDemo.zOpenDebug"
  },
  "autoStore": true
}

📝 The "secure" array means that user and password will be stored in your system’s secure credential store rather than in plain text in the JSON file.

📚 For more information about profile types and configuration options, see the IBM Z Open Editor documentation.

4.3 Profile Structure

The diagram below shows the hierarchical structure of the BankOfZDemo profile and how each sub-profile maps to a z/OS service.

graph TD ROOT["zowe.config.json"] DEMO["BankOfZDemo (root profile)\nhost: your-zos-host\nrejectUnauthorized: false\nsecure: user + password"] RSEAPI["rseapi\ntype: rse\nport: 8195\nprotocol: https"] ZOSMF["zosmf\ntype: zosmf\nport: 10443"] SSH["ssh\ntype: ssh\nport: 22"] TSO["tso\ntype: tso\ncodePage: 1047"] DEBUG["zOpenDebug\ntype: zOpenDebug\ndpsPort: 8192 / rdsPort: 8194"] ROOT --> DEMO DEMO --> RSEAPI DEMO --> ZOSMF DEMO --> SSH DEMO --> TSO DEMO --> DEBUG

The root BankOfZDemo profile defines shared properties (host, credentials) that all sub-profiles inherit, while each sub-profile adds the service-specific port and configuration.

4.4 Verifying Profile Connectivity

After creating the profile, verify that your z/OS system is reachable:

BASH 
zowe zosmf check status
zowe rse check status

If either command fails, check that:

  • The host value is correct and reachable from your workstation
  • The port numbers match the services configured on your z/OS system
  • The services (z/OSMF, RSE API) are running on z/OS
  • Your credentials are correct

5. Zowe CLI Installation

5.1 Installing Zowe CLI

With Node.js and npm verified, install the Zowe CLI globally using npm:

BASH 
npm install -g @zowe/cli@zowe-v3-lts

Verify the installation was successful:

BASH 
zowe --version

5.2 Installing the IBM RSE API Plug-in

The IBM RSE API plug-in is required for the Bank of Z setup-local.sh script to execute USS commands and manage files on the target z/OS system. Install it via the Zowe plug-in manager:

BASH 
zowe plugins install @ibm/rse-api-for-zowe-cli

Verify that the plug-in appears in the installed plug-in list:

BASH 
zowe plugins list

7. Verification Summary

Run the following commands in sequence to confirm your complete setup is working:

BASH 
# 1. Confirm Node.js version
node -v

# 2. Confirm npm version
npm -v

# 3. Confirm Zowe CLI version
zowe --version

# 4. Confirm RSE API plug-in is installed
zowe plugins list

# 5. Verify z/OSMF connectivity using the profile
zowe zosmf check status

# 6. Verify RSE API connectivity using the profile
zowe rse check status

All six commands should complete without errors before proceeding to deployment.
