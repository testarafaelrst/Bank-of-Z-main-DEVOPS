Tutorial: Deploy Bank of Z

This tutorial walks you through a complete, end-to-end first-time deployment of the Bank of Z application onto an IBM Z environment. Using the Direct USS (Unix System Services) method, you will clone the repository, run three automated setup stages, and bring up a full application stack — including CICS, IMS, z/OS Connect, and a Liberty frontend server — entirely from source.

1. Overview

Bank of Z is a full-stack, hybrid IBM Z reference application that demonstrates modern development and deployment practices on z/OS. It integrates multiple IBM Z middleware components — CICS, IMS, z/OS Connect, and WebSphere Liberty — into a unified banking simulation environment.

This tutorial covers the Direct USS deployment path: the fastest way to get Bank of Z up and running from scratch. A guided video walkthrough is embedded below to accompany each step described in this document.

By the end of this tutorial, you will have:

  • A fully provisioned Bank of Z application stack running on IBM Z
  • CICS and IMS environments configured and deployed
  • z/OS Connect APIs exposed and connected
  • A Liberty-hosted frontend accessible via browser
  • A working incremental build/deploy workflow ready for day-to-day development

Tip: Once Bank of Z has been deployed successfully, use the incremental build and deploy workflow (pipeline-remote.sh) during day-to-day development instead of performing a full deployment after every code change.

2. System Architecture

Bank of Z is composed of several interconnected IBM Z middleware layers, each serving a distinct role. The diagram below illustrates the high-level system architecture and how components relate to one another.

The Liberty server acts as the user-facing frontend, routing REST calls through z/OS Connect, which then dispatches transactions to either the CICS or IMS backend. All build and deployment operations originate from USS, directly from the cloned repository.

The sections below mirror the steps shown in the video.

4.1 Stage 1 — Clone the Repository to USS

Open a USS shell session on your z/OS system and clone the Bank of Z repository:

BASH 
git clone https://github.com/IBM/Bank-of-Z.git
cd Bank-of-Z

This places the full application source tree — including COBOL programs, CICS definitions, IMS configurations, z/OS Connect API descriptors, and Liberty server configuration — under a single USS directory.

4.2 Stage 2 — Provision the Application Stack

Run the first setup stage script to automatically provision all required middleware components. This stage configures CICS, IMS, z/OS Connect, and Liberty based on parameters defined in the repository.

BASH 
./setup/stage1-provision.sh

What this stage does:

  • Defines and installs the CICS region and required resource definitions (programs, transactions, files)
  • Provisions the IMS environment and database descriptors
  • Registers z/OS Connect API service definitions
  • Initializes the Liberty server instance and deploys base configuration

4.3 Stage 3 — Build and Deploy from Source

Run the second and third setup stage scripts to build the application from source and deploy all artifacts to the provisioned stack.

BASH 
./setup/stage2-build.sh
./setup/stage3-deploy.sh

Stage 2 — Build:

  • Invokes DBB (Dependency Based Build) to compile COBOL programs
  • Assembles any HLASM modules
  • Packages the Liberty web application (WAR/EAR)
  • Generates z/OS Connect API binding files

Stage 3 — Deploy:

  • Installs compiled load modules into CICS
  • Loads IMS database segments
  • Publishes z/OS Connect API definitions
  • Deploys the Liberty application package to the server

4.4 Deployment Flow

The sequence diagram below illustrates how the three setup stages interact with each middleware component during a full deployment.

5. Post-Deployment Verification

Once all three stages complete successfully, verify the deployment by:

  1. Checking the Liberty server — confirm the frontend is reachable via browser at the configured host and port.
  2. Submitting a CICS transaction — use a 3270 terminal or REST call via z/OS Connect to invoke a Bank of Z transaction.
  3. Querying IMS — verify IMS database segments are populated and accessible.
  4. Testing the REST API — send a sample request through z/OS Connect to confirm end-to-end API routing.

6. Incremental Build and Deploy (Day-to-Day Development)

After the initial full deployment, avoid repeating the full three-stage process for every code change. Instead, use the incremental build and deploy script provided in the repository:

BASH 
./pipeline-remote.sh

This script:

  • Detects only the source files that have changed since the last build
  • Rebuilds only the affected components using DBB
  • Redeploys only the updated artifacts to CICS, IMS, z/OS Connect, or Liberty as needed

This incremental workflow significantly reduces build and deploy cycle times during active development.
