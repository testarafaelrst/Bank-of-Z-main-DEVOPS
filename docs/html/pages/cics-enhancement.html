Tutorial: CICS Enhancement Scenario

1. Overview

The CICS Enhancement Scenario is a hands-on tutorial that walks through a realistic IBM Z application modernization workflow using the Bank of Z sample application. The scenario focuses on adding a new customer email field to the existing CICS-based banking application — a change that touches multiple layers of the system, from database definitions to COBOL programs and the web front end.

The tutorial is structured in two parts:

  • Part 1 covers understanding and planning the enhancement using IBM Z tooling.
  • Part 2 covers implementing, deploying, and validating the changes.

Throughout the tutorial, the following IBM Z development tools are used:

Tool Purpose
Z Understand Explore and analyze the existing codebase
Bob AI Assist with impact analysis and implementation planning
IBM Z Open Editor Navigate and modify COBOL source files
Bank of Z Build & Deploy Pipeline Build and deploy updated components

2. System Architecture

The Bank of Z CICS application follows a layered architecture. A web front end submits requests to a CICS transaction, which drives COBOL business logic programs. Those programs interact with a DB2 database through embedded SQL, and results are returned back to the caller.

The diagram below illustrates the high-level system architecture and how the components interact:

graph TD A[Bank of Z Web Application] -->|HTTP Request| B[CICS Transaction Gateway] B -->|EXEC CICS LINK| C[CICS Region] C --> D[COBOL Business Logic Programs] D -->|EXEC SQL| E[DB2 Database] E -->|Result Set| D D -->|COMMAREA Response| C C -->|Response| B B -->|HTTP Response| A subgraph IBM Z Environment C D E end

The enhancement — adding a customer email field — requires coordinated changes across all layers: the DB2 table definition, the COBOL copybook that maps the customer data structure, the COBOL programs that read and write customer records, and the web application that displays the data.

3. Prerequisites

Before starting this tutorial, ensure that you have:

  • Completed the Quick Start guide
  • Successfully built and deployed Bank of Z
  • A working Bank of Z development environment

4. What You Will Learn

By completing this tutorial, you will learn how to:

  • Understand the CICS application architecture and request flow
  • Analyze the impact of an application enhancement
  • Plan application changes using Bob AI and Z Understand
  • Modify application artifacts, including database definitions and COBOL programs
  • Use IBM Z Open Editor features to navigate and review application code
  • Build and deploy updated CICS application components
  • Verify the enhancement using the Bank of Z web application

5. Part 1 — Understand and Plan the Enhancement

5.1 Goal

Before writing a single line of code, it is essential to understand how the existing application is structured and which components will be affected by the new email field. Part 1 demonstrates how to use IBM Z tooling to explore the codebase, trace data flows, and produce a concrete implementation plan.

5.2 Development Planning Workflow

The diagram below shows the sequential planning activities carried out in Part 1:

5.3 Activities Covered

The following activities are demonstrated in Part 1:

  1. Explore the codebase — Use Z Understand to browse the Bank of Z project, view program hierarchies, and understand the call graph.
  2. Understand the CICS application architecture — Identify CICS transactions, linked COBOL programs, copybooks, and DB2 tables.
  3. Perform impact analysis — Use Bob AI to determine which artifacts need to change when adding the email field.
  4. Trace the application data flow — Follow customer data from the database through the COBOL programs to the web response.
  5. Generate an implementation plan — Ask Bob AI to produce a prioritized list of changes.
  6. Create an implementation checklist — Document each artifact to be modified before touching any code.

5.4 Data Flow for Customer Record Retrieval

The following diagram illustrates how a customer record flows through the system — the data path that the email field enhancement must be threaded through:

graph LR A[DB2 CUSTOMER Table] -->|FETCH cursor| B[COBOL Copybook - CUSTCOPY] B -->|Mapped to COMMAREA| C[CICS COBOL Program] C -->|EXEC CICS RETURN| D[CICS Transaction Gateway] D -->|JSON Serialization| E[Bank of Z Web Application] E -->|Display| F[Browser - Customer Details Screen]

Note: The email field must be added at every layer shown above — starting from the DB2 table definition (CUSTOMER) and propagating through the copybook, COBOL program, and finally the web application display.

6. Part 2 — Implement and Validate the Enhancement

6.1 Goal

With a clear implementation plan in hand, Part 2 demonstrates the actual code changes, the build and deployment pipeline, and the validation steps to confirm the enhancement is working correctly end to end.

6.2 End-to-End Implementation Workflow

sequenceDiagram actor Developer participant Editor as IBM Z Open Editor participant BobAI as Bob AI participant Pipeline as Build & Deploy Pipeline participant DB2 as DB2 Database participant Web as Bank of Z Web App Developer->>DB2: ALTER TABLE CUSTOMER ADD COLUMN EMAIL VARCHAR(100) Developer->>Editor: Open CUSTCOPY copybook Editor-->>Developer: Display current structure Developer->>BobAI: "Generate COBOL field definition for EMAIL" BobAI-->>Developer: 05 CUST-EMAIL PIC X(100). Developer->>Editor: Add CUST-EMAIL to copybook Developer->>Editor: Update COBOL programs to read/write CUST-EMAIL Developer->>Pipeline: Trigger build and deploy Pipeline-->>DB2: Apply schema changes Pipeline-->>Developer: Deployment successful Developer->>Web: Open Customer Details screen Web-->>Developer: Email field displayed correctly

6.3 Activities Covered

The following activities are demonstrated in Part 2:

  1. Update application artifacts — Modify the DB2 table definition to add the EMAIL column.
  2. Review and implement code changes — Use IBM Z Open Editor to update COBOL copybooks and programs.
  3. Navigate COBOL programs — Use IBM Z Open Editor’s outline view and cross-reference features to find all locations that reference the customer record structure.
  4. Use Bob AI for implementation assistance — Generate COBOL field definitions and SQL statement snippets.
  5. Run the build and deployment pipeline — Compile updated COBOL programs, bind DB2 packages, and deploy to the CICS region.
  6. Validate database updates — Confirm the new EMAIL column is populated correctly in DB2.
  7. Verify through the web application — Open the Bank of Z customer details screen and confirm the email field is visible.

6.4 Key Code Changes

The following examples illustrate the types of changes made during the enhancement.

6.4.1 DB2 Schema Change

Add the EMAIL column to the existing CUSTOMER table:

SQL 
ALTER TABLE CUSTOMER
    ADD COLUMN EMAIL VARCHAR(100);

6.4.2 COBOL Copybook Update

Extend the customer data structure copybook (CUSTCOPY) to include the new email field:

COBOL 
01  CUSTOMER-RECORD.
    05  CUST-ID           PIC 9(10).
    05  CUST-FIRST-NAME   PIC X(30).
    05  CUST-LAST-NAME    PIC X(30).
    05  CUST-ADDRESS      PIC X(100).
    05  CUST-PHONE        PIC X(15).
    05  CUST-EMAIL        PIC X(100).    *> NEW FIELD

6.4.3 COBOL SQL SELECT Update

Update the embedded SQL SELECT statement in the COBOL program to retrieve the new column:

COBOL 
EXEC SQL
    SELECT CUST_ID,
           CUST_FIRST_NAME,
           CUST_LAST_NAME,
           CUST_ADDRESS,
           CUST_PHONE,
           EMAIL                          -- NEW COLUMN
    INTO  :CUST-ID,
          :CUST-FIRST-NAME,
          :CUST-LAST-NAME,
          :CUST-ADDRESS,
          :CUST-PHONE,
          :CUST-EMAIL                     -- NEW HOST VARIABLE
    FROM  CUSTOMER
    WHERE CUST_ID = :WS-INPUT-CUST-ID
END-EXEC.

6.4.4 CICS COMMAREA Update

Ensure the COMMAREA structure passed between CICS programs reflects the new field:

COBOL 
01  DFHCOMMAREA.
    05  CA-REQUEST-CODE   PIC X(1).
    05  CA-CUSTOMER-DATA.
        10  CA-CUST-ID        PIC 9(10).
        10  CA-CUST-NAME      PIC X(60).
        10  CA-CUST-PHONE     PIC X(15).
        10  CA-CUST-EMAIL     PIC X(100).  *> NEW FIELD

8. Outcome

After completing this tutorial, you will have:

  • Planned a CICS application enhancement using Z Understand and Bob AI
  • Implemented coordinated changes across DB2, COBOL copybooks, and COBOL programs
  • Deployed the updated application through the Bank of Z build and deployment pipeline
  • Verified the enhancement end-to-end through the Bank of Z web application

You will also have gained practical experience using modern IBM Z development tools to navigate a real-world codebase, reason about the impact of changes, and deliver a working feature enhancement on IBM Z.
