Prerequisites

Before deploying Bank of Z, ensure that your z/OS environment meets all the requirements described on this page. These cover platform components, tooling, access permissions, and external dependencies that must be in place before installation and runtime configuration can begin. Prerequisites are typically provisioned by a system administrator; if any requirement is not yet available in your environment, contact your administrator before proceeding.

For local workstation requirements — IDE, Zowe CLI, and GRUB — see Local Tools Setup. The tools you need depend on your chosen deployment workflow.

1. System Architecture Overview

Bank of Z runs on IBM Z infrastructure and spans multiple middleware layers. The diagram below illustrates how the key platform components relate to one another and to the development workstation.

graph TD WS["💻 Developer Workstation\n(Windows 11 / macOS 26 /\nCodespaces / Dev Spaces)"] USS["z/OS UNIX System Services (USS)\nBuild & Deploy Tooling"] CICS["CICS TS 6.3\nTransaction Server"] IMS["IMS TM + DB V15\nTransaction Manager & Database"] DB2["Db2 for z/OS V13\nSubsystem: DBD1"] MQ["IBM MQ\nMessaging"] ZC["z/OS Connect EE 3.0.101\nAPI Gateway"] ZOS["z/OS 3.1 Operating System"] WS -->|"SSH / Zowe CLI / IDE"| USS USS -->|"DBB Build + Wazi Deploy"| ZOS ZOS --> CICS ZOS --> IMS ZOS --> DB2 ZOS --> MQ ZOS --> ZC ZC --> CICS ZC --> IMS

The developer workstation communicates with z/OS USS via SSH or Zowe CLI. Build artefacts are compiled using IBM Dependency Based Build (DBB) and deployed via Wazi Deploy. At runtime, transactions flow through CICS and IMS, data is persisted in Db2, messages are exchanged over IBM MQ, and external API access is provided by z/OS Connect Enterprise Edition.

4. z/OS Platform Requirements

The target z/OS environment must include the following platform components. Contact your system administrator if any of these are not yet available.

Component Minimum Version
z/OS 3.1
CICS TS 6.3
Db2 for z/OS V13
IMS Transaction Manager (IMS TM) V15
IMS Database V15
z/OS Connect Enterprise Edition 3.0.101
IBM MQ Supported release

Note: A pre-existing Db2 subsystem with subsystem ID DBD1 is required. The setup scripts create the required Db2 database objects within this subsystem but do not create the subsystem itself. IMS, CICS, and z/OS Connect runtime instances are provisioned automatically during deployment.

IBM Dependency Based Build (DBB) 3.0.5 dbb.dbb_home
Z Open Automation Utilities (ZOAU) 1.4.1.0 zoau.zoau_home
z/OS Middleware Configuration Tool (zconfig) 0.7.0 zconfig.zconfig_home

Note: Bank of Z uses zconfig to provision and configure CICS resources, IMS resources, and the z/OS Connect runtime during the environment setup phase.

5.1 USS Access Requirements

In addition to the tools above, the following USS-level access conditions must be satisfied:

Requirement Details
USS write access Your user ID must have write permission on the sandbox path configured in config.yaml
Git available in PATH Required for setup scripts to clone the DBB accelerators repository from GitHub
Network connectivity to github.com The environment phase clones https://github.com/IBM/dbb.git from USS

6. Access and Security Requirements

Ensure that you hold the following access entitlements before proceeding with installation:

Access Requirement Description
TSO user ID and password Required for authentication and system access
USS access Required to access z/OS UNIX System Services resources
Dataset creation permissions Permission to create and modify datasets
Deployment permissions Permission to deploy application resources
Middleware access Access to CICS, IMS, Db2, IBM MQ, and z/OS Connect, as applicable

Appropriate security definitions must also be configured in RACF (or an equivalent security manager) before deployment. The exact definitions required depend on your target environment.

Note: Access to z/OS environments, middleware, USS directories, and dataset resources is typically provisioned by your system administrator. If you do not have the required access, contact your administrator before proceeding.

7. External Tools Requirements

The following external tools and libraries are required to build and deploy Bank of Z. These are installed separately from the z/OS USS tooling described above.

7.1 Python Libraries

Install the required Python libraries on the USS environment by running:

BASH 
pip install pyyaml
pip install jinja2

These libraries are used by the setup and configuration scripts to parse YAML configuration files and render Jinja2 templates during the environment setup phase.

7.2 Gradle

Download the latest supported Gradle binary distribution from the Gradle releases page.

After downloading the archive, install Gradle on z/OS USS by running the following commands:

BASH 
jar xf gradle-9.5.1-bin.zip
chmod +x gradle-9.5.1/bin/gradle
chtag -tc UTF-8 gradle-9.5.1/bin/gradle

Note: Update the version number in the commands above if you download a different Gradle release.

8. Verify Prerequisites

After your system administrator has confirmed all the above are in place, run the prerequisite validation script from USS to confirm that the build and deploy tooling is correctly installed and reachable:

BASH 
.setup/setup-common.sh validate-prereqs

This script performs the following checks:

graph TD A["Run validate-prereqs"] --> B{"DBB version check"} B --> C{"ZOAU version check"} C --> D{"zconfig version check"} D --> E{"Wazi Deploy version check"} E --> F{"Git availability check"} F --> G{"Network connectivity\nto github.com"} G --> H["✅ All checks passed —\nReady to proceed"] B -- Fail --> X["❌ Prerequisite missing —\nContact system administrator"] C -- Fail --> X D -- Fail --> X E -- Fail --> X F -- Fail --> X G -- Fail --> X

Specifically, the script checks:

  • Version compliance for DBB, ZOAU, zconfig, and Wazi Deploy
  • Availability of Git in the USS PATH
  • Network connectivity to github.com

For a full description of each individual check, see Deploy Using Direct USS Access.

9. Next Steps

Once all prerequisites have been validated, continue to Environment Configuration to configure the application settings before deployment.
