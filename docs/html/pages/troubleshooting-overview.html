Troubleshooting Overview

This page provides general troubleshooting guidance for the Bank of Z application, covering common issues encountered during installation, configuration, deployment, and runtime operations. Each section identifies symptoms, likely causes, and step-by-step resolution strategies to help developers and administrators quickly diagnose and resolve problems.

1. Overview

The Bank of Z application runs on a z/OS environment and relies on several interconnected components — including Zowe CLI, DBB (Dependency Based Build), Java, Git on USS, and configuration files — all of which must be correctly installed and configured for the application to function properly.

Troubleshooting in this environment spans multiple layers:

  • Workstation tooling (Zowe CLI, npm)
  • z/OS connectivity (z/OSMF profiles, network, firewall)
  • USS filesystem (permissions, paths, Git availability)
  • Build toolchain (DBB, Java, zBuilder)
  • Repository access (Git cloning, authentication)
  • Configuration management (config.yaml variables and paths)

When an issue occurs, it is important to identify which layer is failing before attempting a fix. The sections below are organized by issue category to guide that process.

2. System Architecture

The following diagram illustrates the high-level architecture of the Bank of Z environment and the relationships between its major components.

graph TD WS[👨‍💻 Developer Workstation] ZOWE[Zowe CLI] ZOSMF[z/OSMF on z/OS] USS[USS Filesystem] GIT[Git Repository] DBB[DBB - Dependency Based Build] JAVA[Java Runtime] CFG[config.yaml] ZBUILDER[zBuilder] APP[Bank of Z Application] WS --> ZOWE ZOWE -->|Profile / Connectivity| ZOSMF ZOSMF --> USS USS --> CFG CFG --> DBB CFG --> JAVA CFG --> ZBUILDER GIT -->|Clone / Sync| USS DBB --> APP JAVA --> APP ZBUILDER --> APP

The developer workstation communicates with z/OS through Zowe CLI, which uses a configured z/OSMF profile to authenticate and interact with the USS filesystem. Source code is cloned from Git into USS, where the config.yaml file drives the build toolchain — coordinating DBB, Java, and zBuilder to produce the final Bank of Z application artifacts.

3. Zowe CLI Issues

Zowe CLI is the primary interface between the developer workstation and the z/OS environment. The following sequence illustrates a typical Zowe CLI interaction:

sequenceDiagram participant Dev as Developer Workstation participant CLI as Zowe CLI participant Profile as z/OSMF Profile participant zOS as z/OS System Dev->>CLI: zowe zosmf check status CLI->>Profile: Load profile credentials Profile-->>CLI: Host / Port / Credentials CLI->>zOS: HTTP request to z/OSMF endpoint zOS-->>CLI: Status response CLI-->>Dev: Connection result (success / error)

3.1 Zowe CLI Not Found

Symptom

Commands such as the following return a command not found error:

BASH 
zowe --version

Possible Cause

Zowe CLI is not installed or is not available in your system path.

Resolution

Verify the installation:

BASH 
zowe --version

If Zowe CLI is not installed, install it using npm:

BASH 
npm install -g @zowe/cli

Ensure that the npm global installation directory is included in your system path.

3.2 Zowe Profile Not Found

Symptom

Zowe commands fail because a profile cannot be located.

Possible Cause

A z/OSMF profile has not been created or configured correctly.

Resolution

List available profiles:

BASH 
zowe profiles list zosmf

Create or update the required profile and verify connectivity:

BASH 
zowe zosmf check status

3.3 Unable to Connect to z/OS

Symptom

Connection validation commands fail.

Possible Cause

Incorrect host information, invalid credentials, network connectivity issues, or firewall restrictions.

Resolution

Verify the configured profile settings and test connectivity:

BASH 
zowe zosmf check status

Confirm that the host, port, and credentials are correct and that the target system is accessible from your workstation.

4. Configuration Issues

The config.yaml file is the central configuration artifact for the Bank of Z setup. The diagram below shows how configuration values flow into the build and deployment process.

graph LR CFG[config.yaml] SB[sandbox.path] DBB[dbb_home] JAVA[java_home] BUILD[Build Process] DEPLOY[Deployment] CFG --> SB CFG --> DBB CFG --> JAVA SB -->|Workspace directory| BUILD DBB -->|DBB libraries| BUILD JAVA -->|JVM runtime| BUILD BUILD --> DEPLOY

4.1 Configuration File Not Found

Symptom

Setup or build processes fail because the configuration file cannot be located.

Possible Cause

The config.yaml file is missing or stored in an unexpected location.

Resolution

Verify that the file exists:

BASH 
ls -la .setup/config/config.yaml

Ensure that you are running commands from the correct repository location.

4.2 Variable Reference Cannot Be Resolved

Symptom

Setup validation reports unresolved variables.

Possible Cause

A referenced configuration value or environment variable does not exist.

Resolution

Verify all variable references. Example of a correctly structured reference:

YAML 
dbb:
  build_dir: ${sandbox.path}/build

Ensure that referenced sections and keys are defined in the configuration file before they are used.

4.3 Invalid Path Format

Symptom

Setup validation fails when processing directory paths.

Possible Cause

A required path is specified as a relative path.

Resolution

Use absolute paths for all configuration values that reference USS directories.

Example:

YAML 
sandbox:
  path: /usr/local/sandboxes/bank-of-z

5. Git and Repository Issues

Git availability on USS is required for cloning and synchronizing source code. The diagram below shows the repository synchronization flow.

sequenceDiagram participant Dev as Developer Workstation participant Repo as Git Repository (Remote) participant USS as USS Filesystem Dev->>USS: Trigger setup / clone step USS->>Repo: git clone Repo-->>USS: Repository contents USS-->>Dev: Clone success / failure

5.1 Git Not Available on USS

Symptom

Repository cloning or synchronization fails on USS.

Possible Cause

Git is not installed or is not available in the USS environment path.

Resolution

Verify the installation:

BASH 
which git
git --version

If Git is not available, contact your z/OS administrator to have it installed and added to the USS path.

5.2 Unable to Clone Repositories

Symptom

Repository clone operations fail during setup.

Possible Cause

Network restrictions, repository access issues, or authentication problems.

Resolution

Verify repository access, network connectivity, and authentication settings. Confirm that the target z/OS environment can reach the repository hosting service.

6. USS Permission Issues

6.1 Permission Denied When Creating Workspace

Symptom

Setup scripts fail when creating directories or deploying artifacts.

Possible Cause

Insufficient USS permissions for the configured user.

Resolution

Verify that you have write access to the configured sandbox directory. Review the sandbox.path value in config.yaml:

YAML 
sandbox:
  path: /usr/local/sandboxes/bank-of-z

Contact your z/OS administrator if additional permissions are required for the target directory.

7. Build and Setup Issues

The following diagram illustrates the build and setup validation flow, including the key components that must be verified before a successful build can complete.

7.1 Setup Completes With Errors

Symptom

The setup process completes, but some stages report failures or warnings.

Possible Cause

A prerequisite component is unavailable or incorrectly configured.

Resolution

Review the setup output and identify the stage that failed. Verify the following components:

Component What to Check
DBB Installation path and availability
Java Runtime path and version
Git Availability on USS
zBuilder Deployment status
Repository Network access and credentials
Configuration Settings in config.yaml

Correct the reported issue and rerun the setup process.

7.2 DBB Validation Fails

Symptom

Build processes cannot locate DBB components.

Possible Cause

The configured DBB installation path is incorrect.

Resolution

Verify the configured location:

BASH 
ls $DBB_HOME/lib

Update the dbb_home setting in config.yaml if the path is incorrect.

7.3 Java Validation Fails

Symptom

Build or setup scripts fail when invoking Java.

Possible Cause

The configured Java runtime is unavailable or incorrectly configured.

Resolution

Verify the Java installation:

BASH 
$JAVA_HOME/bin/java -version

Confirm that the configured java_home value points to a supported Java installation.

8. Getting Additional Help

If the issue cannot be resolved using the guidance in this page, follow these escalation steps:

  1. Review setup output and error messages — Identify the exact stage and error reported.
  2. Verify config.yaml — Confirm all paths, variables, and settings are correct and use absolute paths.
  3. Confirm prerequisites — Ensure that DBB, Java, Git, and Zowe CLI are all installed and accessible.
  4. Consult your z/OS administrator — For environment-specific issues such as USS permissions, network access, or software availability.
  5. Review workflow documentation — Additional setup and configuration details are available in the Bank of Z workflow documentation.
