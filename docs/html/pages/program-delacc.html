DELACC – Delete Account Program

1. Overview

DELACC is a CICS COBOL back-end program responsible for securely deleting a bank account record from the DB2 ACCOUNT table on behalf of a calling application. It operates as a tightly controlled, security-first service: no account data is read or modified until RACF-backed authorization has been positively confirmed.

When invoked via a CICS LINK with a DFHCOMMAREA containing the target account number, DELACC performs the following sequence:

  1. Security gate — Links to BNKSECCK to verify the requesting user is authorized to perform account deletion. The program is fail-closed: processing halts immediately on any security failure.
  2. Account retrieval — Executes a DB2 SELECT against the ACCOUNT table using a composite key of ACCOUNT_NUMBER + ACCOUNT_SORTCODE. The full account profile is captured and returned to the caller via the communication area.
  3. Account deletion — Executes a DB2 DELETE to permanently remove the account row.
  4. Audit trail — Inserts an immutable audit record into the PROCTRAN table, stamping the transaction type (ODA), timestamp, task reference, and the account’s actual balance at the time of deletion.
  5. Return — Returns control to the caller via GOBACK, with all result fields populated in DFHCOMMAREA.

All outcomes — success, security denial, account not found, or DB2 error — are communicated back through dedicated DELACC-DEL-SUCCESS and DELACC-DEL-FAIL-CD fields in the communication area. Unrecoverable DB2 errors trigger a CICS abend (HRAC or HWPT) via the standard abend handler program ABNDPROC.

2. System Architecture

DELACC sits at the intersection of the CICS transaction layer, RACF security infrastructure, and the DB2 relational database. It is always invoked as a called sub-program (never directly by a terminal user) and has no conversational state — it performs a single, atomic operation per invocation.

3. Inputs

3.1 Communication Area (DFHCOMMAREA — Copybook DELACC)

These fields are passed by the calling program via the CICS COMMAREA when invoking DELACC. They represent the program’s primary input contract.

Field Type Description
DELACC-ACCNO PIC 9(8) 8-digit account number identifying the bank account to be deleted. Used as the primary key field in DB2 SELECT and DELETE statements against the ACCOUNT table.
DELACC-DEL-SUCCESS PIC X(1) Read at the start of the main flow to determine whether the account read step succeeded before proceeding with deletion. Also written back to the caller as the overall operation result (Y/N).
DELACC-DEL-FAIL-CD PIC X(1) Single-character failure code written back to indicate the reason for an unsuccessful deletion (1 = not found, 3 = DB2 delete error, S = security access denied, X = security system failure).

3.2 Security Subsystem — BNKSECCK

The program performs a CICS LINK to the security check program BNKSECCK before any data access. The result of this call directs all subsequent processing.

Field Description
BNKSEC-OPERATION Set to 'DELACC '; informs the security program which operation is being authorized.
BNKSEC-FOR-USERID / BNKSEC-USERID User identity fields populated and evaluated by BNKSECCK to determine authorization.
BNKSEC-RESULT Returned by BNKSECCK; A (allowed), D (denied), or E (error). Controls whether WS-SEC-SW is set to SEC-OK or SEC-NOT-OK.
BNKSEC-RESP / BNKSEC-RESP2 CICS response codes returned by the LINK; a non-NORMAL response causes immediate return with failure code X.

3.3 DB2 Database — ACCOUNT Table

The program reads and deletes a row from the DB2 ACCOUNT table. The following host variables are the keys used to locate the row and the data retrieved from it.

Host Variable Description
HV-ACCOUNT-SORTCODE Populated from the internal SORTCODE constant (987654); forms part of the composite key in both SELECT and DELETE SQL statements.
HV-ACCOUNT-ACC-NO Populated from DELACC-ACCNO; the account number half of the composite key, driving both the SELECT (read) and DELETE operations.
HV-ACCOUNT-CUST-NO Retrieved from the ACCOUNT table row; represents the customer who owns the account. Returned to the caller via COMMAREA.
HV-ACCOUNT-ACC-TYPE Account classification (e.g., current, savings) retrieved from the ACCOUNT table and returned to the caller.
HV-ACCOUNT-ACTUAL-BAL Real monetary balance retrieved from the ACCOUNT table. Preserved in ACCOUNT-ACT-BAL-STORE and written as the transaction value in the PROCTRAN audit record.
HV-ACCOUNT-AVAIL-BAL Available balance retrieved from the ACCOUNT table and returned to the caller.
HV-ACCOUNT-OVERDRAFT-LIM Authorized overdraft limit retrieved from the ACCOUNT table and returned to the caller.
HV-ACCOUNT-INT-RATE Interest rate retrieved from the ACCOUNT table and returned to the caller.

3.4 DB2 Database — PROCTRAN Table

After a successful deletion, the program inserts an audit record into the PROCTRAN table. The data fed into this insert is derived from the retrieved account row and CICS system fields.

Source Field Description
EIBTASKN CICS Executive Interface Block field providing the current task number; used to populate HV-PROCTRAN-REF (the transaction reference in the audit record).
EIBTRNID CICS EIB field providing the transaction identifier; used in abend diagnostic records.

3.5 CICS System (EIB) — Inputs

Field Description
EIBTASKN Current CICS task number; used as the transaction reference written to the PROCTRAN audit row.
EIBTRNID Current CICS transaction ID; used in abend handler records.
EIBRESP / EIBRESP2 CICS response codes examined after the LINK to BNKSECCK; a non-normal response triggers the immediate security failure flow.

3.6 Static Configuration

Constant Value Source Purpose
SORTCODE 987654 Copybook SORTCODE The bank’s own sort code. Hard-coded and used to restrict all DB2 reads and deletes to the correct branch.

4.2 DB2 Database Writes

  • ACCOUNT Table — DELETE (DEL-ACCOUNT-DB2 section) — The row in the ACCOUNT table matching the composite key ACCOUNT_SORTCODE + ACCOUNT_NUMBER is permanently removed. On failure, sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = '3'.
  • PROCTRAN Table — INSERT (WRITE-PROCTRAN-DB2 section) — An audit/process transaction history row is written to PROCTRAN only when the DELETE succeeds. The inserted record contains:
    • Eye-catcher 'PRTR'; sort code and deleted account number.
    • Timestamp (date via CICS FORMATTIME, time via CICS ASKTIME).
    • Task number (from EIBTASKN) as the transaction reference.
    • Type code 'ODA' (Branch Account Delete, via PROC-TY-BRANCH-DELETE-ACCOUNT).
    • Description (PROC-TRAN-DESC-DELACC) containing: customer number, account type, last statement date, next statement date, and the literal footer 'DELETE'.
    • Amount (HV-PROCTRAN-AMOUNT) set to ACCOUNT-ACT-BAL-STORE — the actual account balance at the moment of deletion.

4.3 Abend / CICS Error Side Effects

Abend Code Trigger Condition Description
HRAC DB2 SELECT on ACCOUNT returns unexpected SQLCODE (≠ 0 or +100) Issued via EXEC CICS ABEND ABCODE('HRAC') NODUMP. Terminates the transaction abnormally.
HWPT DB2 INSERT on PROCTRAN fails Before the abend, the program LINKs to ABNDPROC passing detailed ABNDINFO-REC diagnostics. Issued via EXEC CICS ABEND ABCODE('HWPT') (with dump).

4.4 Console / Sysout Messages (DISPLAY)

Message Trigger
'Issue with ACCOUNT row select...' Written to the CICS job log when the DB2 SELECT on ACCOUNT returns an unexpected SQLCODE. Includes SQLCODE-DISPLAY, HV-ACCOUNT-ACC-NO, and HV-ACCOUNT-SORTCODE.
'In DELACC (WPD010) UNABLE TO WRITE TO PROCTRAN ROW DATASTORE...' Written to the CICS job log when the INSERT on PROCTRAN fails. Includes SQLCODE-DISPLAY and the contents of HOST-PROCTRAN-ROW.

5.2 Execution Flow Description

5.2.1 Step 1 — Entry and Security Check (SECURITY-CHECK)

The program is invoked by a CICS LINK with a DFHCOMMAREA containing the account number to be deleted (DELACC-ACCNO). The very first action — before any data is read or modified — is a security check. WS-SEC-SW is initialized to N (SEC-NOT-OK), and BNKSEC-COMMAREA is populated with the operation code DELACC . A CICS LINK is made to the sub-program BNKSECCK.

  • If the CICS response is not NORMAL (link failure): DELACC-DEL-SUCCESS = 'N', DELACC-DEL-FAIL-CD = 'X', and the program terminates immediately.
  • If BNKSEC-RESULT = 'A' (Allowed): SEC-OK is set to TRUE and processing continues.
  • If BNKSEC-RESULT = 'D' (Denied): DELACC-DEL-SUCCESS = 'N', DELACC-DEL-FAIL-CD = 'S', and the program terminates.
  • If any other result: DELACC-DEL-SUCCESS = 'N', DELACC-DEL-FAIL-CD = 'X', and the program terminates.

5.2.2 Step 2 — Account Record Read (READ-ACCOUNT-DB2)

Only reached when SEC-OK is TRUE. The bank’s own constant SORTCODE (987654) is moved to the key variable, and DELACC-ACCNO is moved to HV-ACCOUNT-ACC-NO. A DB2 SELECT retrieves all twelve columns from the matching ACCOUNT row using the composite key ACCOUNT_NUMBER + ACCOUNT_SORTCODE.

  • If SQLCODE ≠ 0 and SQLCODE ≠ +100 (unexpected DB2 error): The program collects diagnostics (APPLID, task number, transaction ID, time/date, SQLCODE), populates ABNDINFO-REC, displays an error message, and issues a CICS ABEND with code HRAC.
  • If SQLCODE = +100 (row not found): DELACC-DEL-SUCCESS = 'N', DELACC-DEL-FAIL-CD = '1', the communication area is partially initialized, and processing ends.
  • If SQLCODE = 0 (found): All retrieved fields are mapped from DB2 host variables through the OUTPUT-DATA work area to the DFHCOMMAREA output fields. Dates stored in DB2 in YYYY-MM-DD format are parsed via DB2-DATE-REFORMAT into separate day/month/year sub-fields. The actual balance is preserved in ACCOUNT-ACT-BAL-STORE for later use in the audit record. DELACC-DEL-SUCCESS is set to 'Y'.

5.2.3 Step 3 — Account Row Deletion (DEL-ACCOUNT-DB2)

Only reached when DELACC-DEL-SUCCESS = 'Y' after the read. A DB2 DELETE FROM ACCOUNT is issued using the same composite key host variable values (ACCOUNT_SORTCODE + ACCOUNT_NUMBER) used in the SELECT. If SQLCODE ≠ 0, DELACC-DEL-SUCCESS is set to 'N' and DELACC-DEL-FAIL-CD to '3'; no abend is generated for this condition.

5.2.4 Step 4 — Audit Record Write (WRITE-PROCTRAN / WRITE-PROCTRAN-DB2)

Only reached when DELACC-DEL-SUCCESS = 'Y' after the deletion. A PROCTRAN audit row is constructed:

  • Eye-catcher: PRTR
  • Sort code and account number from host variables
  • CICS task number (EIBTASKN) as transaction reference
  • CICS ASKTIME and CICS FORMATTIME for current time/date formatted as DDMMYYYY date and HHMMSS time
  • Description field (PROC-TRAN-DESC-DELACC) populated with customer number, account type, and last/next statement date components
  • Transaction type set to 'ODA' (Branch Account Delete) via SET PROC-TY-BRANCH-DELETE-ACCOUNT TO TRUE
  • Footer indicator 'DELETE' via SET PROC-DESC-DELACC-FLAG TO TRUE
  • ACCOUNT-ACT-BAL-STORE (balance at time of deletion) moved to HV-PROCTRAN-AMOUNT
  • INSERT INTO PROCTRAN executed

If the INSERT fails (SQLCODE ≠ 0), the program populates ABNDINFO-REC, links to abend handler program ABNDPROC, and then issues CICS ABEND HWPT — a fatal abend, because audit trail integrity is mandatory.

5.2.5 Step 5 — Return (GET-ME-OUT-OF-HERE)

Issues GOBACK to return control to CICS, which passes the populated DFHCOMMAREA back to the calling program.

6. Paragraphs

6.1 A010 — Main Entry Point (PREMIERE SECTION)

Acts as the top-level controller of the program, orchestrating all major processing steps in sequence.

  • Calls SECURITY-CHECK to determine whether the requesting user is authorized to delete accounts.
  • If the SEC-OK flag is true, moves SORTCODE to the required sort code working field, then calls READ-ACCOUNT-DB2 to retrieve the target account row.
  • Conditionally calls DEL-ACCOUNT-DB2 only when DELACC-DEL-SUCCESS is 'Y' after the read.
  • If deletion is also successful (DELACC-DEL-SUCCESS remains 'Y'), calls WRITE-PROCTRAN to write the audit trail entry.
  • Concludes by calling GET-ME-OUT-OF-HERE unconditionally.
COBOL 
A010.
    PERFORM SECURITY-CHECK
    IF SEC-OK
        MOVE SORTCODE TO REQUIRED-SORT-CODE
        PERFORM READ-ACCOUNT-DB2
        IF DELACC-DEL-SUCCESS = 'Y'
            PERFORM DEL-ACCOUNT-DB2
            IF DELACC-DEL-SUCCESS = 'Y'
                PERFORM WRITE-PROCTRAN
            END-IF
        END-IF
    END-IF
    PERFORM GET-ME-OUT-OF-HERE.

6.2 SECURITY-CHECK (SC010)

Enforces a fail-closed RACF authorization barrier before any data is accessed.

  • Initializes WS-SEC-SW to 'N' (SEC-NOT-OK) as a safe default and clears BNKSEC-COMMAREA.
  • Moves the operation name 'DELACC ' to BNKSEC-OPERATION and issues a CICS LINK to security check sub-program BNKSECCK, passing BNKSEC-COMMAREA.
  • Checks WS-CICS-RESP: if the CICS call itself does not return DFHRESP(NORMAL), sets DELACC-DEL-SUCCESS = 'N', DELACC-DEL-FAIL-CD = 'X', and branches to SC999, bypassing all account processing.
  • Uses an EVALUATE TRUE block to interpret BNKSEC-RESULT:
    • BNKSEC-ALLOWED → sets WS-SEC-SW to 'Y' (SEC-OK), allowing processing to proceed.
    • BNKSEC-DENIED → sets failure indicators 'N' / 'S'.
    • WHEN OTHER → sets failure indicators 'N' / 'X' for an unexpected security response.
COBOL 
SC010.
    MOVE 'N' TO WS-SEC-SW
    MOVE LOW-VALUES TO BNKSEC-COMMAREA
    MOVE 'DELACC  ' TO BNKSEC-OPERATION
    EXEC CICS LINK PROGRAM('BNKSECCK')
        COMMAREA(BNKSEC-COMMAREA)
        RESP(WS-CICS-RESP)
        RESP2(WS-CICS-RESP2)
    END-EXEC
    IF WS-CICS-RESP NOT = DFHRESP(NORMAL)
        MOVE 'N' TO DELACC-DEL-SUCCESS
        MOVE 'X' TO DELACC-DEL-FAIL-CD
        GO TO SC999
    END-IF
    EVALUATE TRUE
        WHEN BNKSEC-ALLOWED
            SET SEC-OK TO TRUE
        WHEN BNKSEC-DENIED
            MOVE 'N' TO DELACC-DEL-SUCCESS
            MOVE 'S' TO DELACC-DEL-FAIL-CD
        WHEN OTHER
            MOVE 'N' TO DELACC-DEL-SUCCESS
            MOVE 'X' TO DELACC-DEL-FAIL-CD
    END-EVALUATE.
SC999. EXIT.

6.3 READ-ACCOUNT-DB2 (RAD010)

Retrieves the complete account row from the DB2 ACCOUNT table using the composite key provided in the communication area.

  • Moves DELACC-ACCNO to HV-ACCOUNT-ACC-NO and SORTCODE to HV-ACCOUNT-SORTCODE to populate DB2 host variables.
  • Executes a DB2 SELECT fetching all twelve columns from ACCOUNT into HOST-ACCOUNT-ROW, filtered by ACCOUNT_NUMBER and ACCOUNT_SORTCODE.
  • Error path (SQLCODE ≠ 0 and ≠ +100): Populates ABNDINFO-REC, issues CICS ABEND ABCODE('HRAC').
  • Row not found path (SQLCODE = +100): Clears OUTPUT-DATA, sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = '1', branches to RAD999.
  • Success path (SQLCODE = 0): Sets DELACC-DEL-SUCCESS = 'Y', maps all retrieved fields to DFHCOMMAREA output fields. Parses DB2 date fields (YYYY-MM-DD) into separate DD/MM/YYYY sub-fields via DB2-DATE-REFORMAT. Saves HV-ACCOUNT-ACTUAL-BAL to ACCOUNT-ACT-BAL-STORE for use in the audit record.
COBOL 
RAD010.
    MOVE DELACC-ACCNO    TO HV-ACCOUNT-ACC-NO
    MOVE SORTCODE        TO HV-ACCOUNT-SORTCODE

    EXEC SQL
        SELECT ACCOUNT_EYECATCHER,
               ACCOUNT_CUSTOMER_NUMBER,
               ACCOUNT_SORTCODE,
               ACCOUNT_NUMBER,
               ACCOUNT_TYPE,
               ACCOUNT_INTEREST_RATE,
               ACCOUNT_OPENED,
               ACCOUNT_OVERDRAFT_LIMIT,
               ACCOUNT_LAST_STATEMENT,
               ACCOUNT_NEXT_STATEMENT,
               ACCOUNT_AVAILABLE_BALANCE,
               ACCOUNT_ACTUAL_BALANCE
        INTO  :HOST-ACCOUNT-ROW
        FROM  ACCOUNT
        WHERE ACCOUNT_NUMBER   = :HV-ACCOUNT-ACC-NO
        AND   ACCOUNT_SORTCODE = :HV-ACCOUNT-SORTCODE
    END-EXEC

    IF SQLCODE NOT = 0 AND SQLCODE NOT = +100
        ... populate ABNDINFO-REC ...
        EXEC CICS ABEND ABCODE('HRAC') NODUMP END-EXEC
    END-IF
    IF SQLCODE = +100
        INITIALIZE OUTPUT-DATA
        MOVE 'N' TO DELACC-DEL-SUCCESS
        MOVE '1' TO DELACC-DEL-FAIL-CD
        GO TO RAD999
    END-IF
    IF SQLCODE = 0
        MOVE 'Y'                 TO DELACC-DEL-SUCCESS
        MOVE SPACES              TO DELACC-DEL-FAIL-CD
        MOVE HV-ACCOUNT-ACTUAL-BAL TO ACCOUNT-ACT-BAL-STORE
        ... map all fields to DFHCOMMAREA ...
    END-IF.
RAD999. EXIT.

6.4 DEL-ACCOUNT-DB2 (DADB010)

Deletes the account row from the DB2 ACCOUNT table.

  • Executes a DB2 DELETE FROM ACCOUNT using host variables HV-ACCOUNT-SORTCODE and HV-ACCOUNT-ACC-NO as the composite key predicate.
  • If SQLCODE ≠ 0, sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = '3' to signal a deletion failure to the caller. No abend is triggered for this condition.
COBOL 
DADB010.
    EXEC SQL
        DELETE FROM ACCOUNT
        WHERE ACCOUNT_SORTCODE = :HV-ACCOUNT-SORTCODE
        AND   ACCOUNT_NUMBER   = :HV-ACCOUNT-ACC-NO
    END-EXEC

    IF SQLCODE NOT = 0
        MOVE SPACES TO DELACC-SUCCESS
        MOVE 'N'    TO DELACC-DEL-SUCCESS
        MOVE '3'    TO DELACC-DEL-FAIL-CD
    END-IF.
DADB999. EXIT.

6.5 WRITE-PROCTRAN (WP010)

A lean dispatcher paragraph that delegates the audit record write to the DB2-specific sub-section.

  • Contains a single PERFORM WRITE-PROCTRAN-DB2 call.
  • Provides an indirection layer that allows the audit step to be replaced or extended without altering the calling paragraph.

6.6 WRITE-PROCTRAN-DB2 (WPD010)

Constructs and inserts a process transaction audit record into the DB2 PROCTRAN table to permanently record the account deletion event.

  • Initializes HOST-PROCTRAN-ROW and WS-EIBTASKN12, then populates audit header fields: eye-catcher 'PRTR', sort code and account number from OUTPUT-DATA, and task number from EIBTASKN left-padded to 12 digits as the transaction reference.
  • Issues CICS ASKTIME to obtain the absolute timestamp and CICS FORMATTIME to produce a formatted DDMMYYYY date and HHMMSS time.
  • Populates the PROC-TRAN-DESC-DELACC redefine with customer number, account type, and last/next statement date components; sets the description footer flag to 'DELETE' and transaction type to 'ODA'.
  • Moves ACCOUNT-ACT-BAL-STORE to HV-PROCTRAN-AMOUNT to record the account balance at the time of deletion.
  • Executes the DB2 INSERT INTO PROCTRAN.
  • Error path (SQLCODE ≠ 0): Populates ABNDINFO-REC, links to ABNDPROC, then issues CICS ABEND ABCODE('HWPT').
COBOL 
WPD010.
    INITIALIZE HOST-PROCTRAN-ROW

8. Error Handling

8.1 Security Gate Checks

DELACC implements a strictly fail-closed security policy. WS-SEC-SW is initialized to 'N' (SEC-NOT-OK) before the CICS LINK to BNKSECCK. The switch is only promoted to SEC-OK ('Y') when the link succeeds and the result is explicitly BNKSEC-ALLOWED. All subsequent processing — DB2 read, delete, and audit write — is nested inside the IF SEC-OK condition.

Condition DELACC-DEL-SUCCESS DELACC-DEL-FAIL-CD Action
CICS LINK to BNKSECCK fails (RESP ≠ NORMAL) N X Immediate exit; no data accessed
BNKSEC-RESULT = 'D' (Denied) N S Immediate exit; no data accessed
BNKSEC-RESULT = any other value N X Immediate exit; no data accessed
BNKSEC-RESULT = 'A' (Allowed) (continues) (continues) Processing allowed to proceed

Both abend-triggering paths (HRAC and HWPT) use the same standardized ABNDINFO-REC structure, which aggregates:

9. Constraints

9.1 Security Constraints

  • Fail-closed security gate: WS-SEC-SW is initialized to 'N' (SEC-NOT-OK) before the LINK to BNKSECCK. The switch is only promoted to SEC-OK when BNKSEC-RESULT = 'A' is returned with DFHRESP(NORMAL). Any other result — including a CICS link failure — keeps the gate closed, and no account data is read or deleted.
  • CICS LINK response must be NORMAL: If EXEC CICS LINK PROGRAM('BNKSECCK') returns a response other than DFHRESP(NORMAL), processing terminates immediately with DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = 'X'.
  • Authorization denial: When BNKSECCK returns BNKSEC-DENIED ('D'), DELACC-DEL-SUCCESS is set to 'N' and DELACC-DEL-FAIL-CD to 'S'; no account read or deletion is attempted.

9.2 Input / Key Constraints

  • Account number is the sole mandatory input: DELACC-ACCNO (PIC 9(8)) must be provided in the DFHCOMMAREA before invocation. The program performs no null/space validation — it is passed directly to the DB2 host variable HV-ACCOUNT-ACC-NO.
  • Sort code is implicitly fixed: The row is keyed by the composite (ACCOUNT_SORTCODE, ACCOUNT_NUMBER). The sort code component always comes from the hard-coded SORTCODE constant (VALUE 987654). Any value of DELACC-SCODE in the COMMAREA is ignored on input.
  • Composite key uniqueness: The DB2 SELECT uses WHERE ACCOUNT_NUMBER = :HV-ACCOUNT-ACC-NO AND ACCOUNT_SORTCODE = :HV-ACCOUNT-SORTCODE. Only a single row is expected; there is no cursor or loop, so the table schema must enforce a uniqueness constraint on this composite key.

9.3 Processing Order / Sequencing Constraints

  • Security must complete before data access: PERFORM SECURITY-CHECK is the first action in the PREMIERE section. Account read and deletion are unconditionally skipped if the security gate is not open.
  • Account must be read successfully before deletion: PERFORM DEL-ACCOUNT-DB2 is only invoked within the block protected by IF DELACC-DEL-SUCCESS = 'Y' after PERFORM READ-ACCOUNT-DB2.
  • PROCTRAN audit record is only written after a successful deletion: PERFORM WRITE-PROCTRAN is nested inside a second IF DELACC-DEL-SUCCESS = 'Y' test following PERFORM DEL-ACCOUNT-DB2. A DB2 DELETE failure prevents any audit INSERT.
  • Balance must be captured before the row is deleted: ACCOUNT-ACT-BAL-STORE is populated from HV-ACCOUNT-ACTUAL-BAL during the SELECT phase. This preserved value is written as PROCTRAN_AMOUNT, ensuring the balance at the time of deletion is retained even after the source row is removed.

9.4 DB2 / Data Storage Constraints

  • SQLCODE = 0 is the only successful SELECT result: Any SQLCODE other than 0 or +100 during the SELECT causes an immediate CICS ABEND with code 'HRAC'.
  • Account not found is a defined, non-fatal error: SQLCODE +100 sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = '1', and control returns to the caller without an abend.
  • DB2 DELETE failure is a soft error for the caller, but no abend: When the DELETE returns SQLCODE ≠ 0, DELACC-DEL-SUCCESS is set to 'N' and DELACC-DEL-FAIL-CD to '3'.
  • PROCTRAN INSERT failure is fatal (abend): If INSERT INTO PROCTRAN returns SQLCODE ≠ 0, the program links to ABNDPROC and then issues EXEC CICS ABEND ABCODE('HWPT'). There is no recoverable error path for a failed audit trail write.
  • Host variable sizes constrain acceptable data: HV-ACCOUNT-ACC-NO is PIC X(8) and HV-ACCOUNT-SORTCODE is PIC X(6), matching the DB2 column declarations of CHAR(8) and CHAR(6) respectively.

9.5 Data Format and Field Size Constraints

  • DB2 date format must be YYYY-MM-DD: All three DATE columns (ACCOUNT_OPENED, ACCOUNT_LAST_STATEMENT, ACCOUNT_NEXT_STATEMENT) are retrieved into 10-character host variables and parsed via DB2-DATE-REFORMAT (layout YYYY-MM-DD). Any deviation would produce incorrect day/month/year values in the COMMAREA output.
  • PROCTRAN eye-catcher must be 'PRTR': This literal is hard-coded into HV-PROCTRAN-EYECATCHER before each INSERT.
  • PROCTRAN type must be 'ODA' (PROC-TY-BRANCH-DELETE-ACCOUNT): Set using SET PROC-TY-BRANCH-DELETE-ACCOUNT TO TRUE. This is the only valid type code written for an account deletion on the branch path.
  • PROCTRAN description footer must be 'DELETE': SET PROC-DESC-DELACC-FLAG TO TRUE populates the 6-character footer field with the literal 'DELETE'.
  • PROCTRAN amount is the actual balance at time of deletion: ACCOUNT-ACT-BAL-STORE (PIC S9(10)V99) carries the balance captured during the SELECT and is written directly to PROCTRAN_AMOUNT. The available balance is not recorded in the audit trail.

9.6 Resource and Scope Constraints

  • Single-row operation only: The SELECT retrieves exactly one row (no cursor, no FETCH loop). If the composite key (ACCOUNT_NUMBER, ACCOUNT_SORTCODE) is not unique in the ACCOUNT table, DB2 will raise an error; the program has no handling for multiple rows returned.
  • No retry logic for DB2 operations: Unlike some companion programs that implement retry loops (SYSIDERR-RETRY, FILE-RETRY), the DELETE and INSERT operations have no retry mechanism; a single failure is immediately terminal or reported as a failure code.
  • Sort code scope is fixed at compile/deployment time: The VALUE 987654 constant in the SORTCODE copybook means the program can only operate against a single institution’s data. No runtime override is possible.

10. Examples

10.1 Example 1 — Successful Account Deletion

Input (DFHCOMMAREA):

Field Value
DELACC-ACCNO 00000042
DELACC-DEL-SUCCESS (not yet set — populated by the program)

The bank sort code is internally fixed as 987654 (from the SORTCODE copybook constant).

Program flow:

  1. SECURITY-CHECK calls BNKSECCK via EXEC CICS LINK. BNKSECCK returns BNKSEC-RESULT = 'A' (allowed) with DFHRESP(NORMAL), so WS-SEC-SW is set to 'Y' (SEC-OK).
  2. READ-ACCOUNT-DB2 issues a DB2 SELECT on the ACCOUNT table with key ACCOUNT_NUMBER = '00000042' and ACCOUNT_SORTCODE = '987654'. SQLCODE = 0; the complete account row is retrieved and copied back into the DFHCOMMAREA fields (DELACC-CUSTNO, DELACC-ACC-TYPE, DELACC-AVAIL-BAL, etc.). DELACC-DEL-SUCCESS is set to 'Y'.
  3. DEL-ACCOUNT-DB2 issues a DELETE for the same composite key. SQLCODE = 0 → DELACC-DEL-SUCCESS remains 'Y'.
  4. WRITE-PROCTRAN inserts a row into PROCTRAN with eye-catcher 'PRTR', type 'ODA' (branch account delete), the actual account balance as the transaction amount, and the CICS task number as the reference.

Output (DFHCOMMAREA):

Field Value
DELACC-CUSTNO 0000000123 (the customer number owning the account, from DB2)
DELACC-ACC-TYPE CURRENT
DELACC-ACTUAL-BAL +0000001500.00
DELACC-AVAIL-BAL +0000001500.00
DELACC-DEL-SUCCESS Y
DELACC-DEL-FAIL-CD (space)

A PROCTRAN audit record is written, capturing the deletion event, the balance at time of deletion, and the timestamp.

10.2 Example 2 — Account Not Found

Input (DFHCOMMAREA):

Field Value
DELACC-ACCNO 99999999 (a non-existent account number)

Program flow:

  1. SECURITY-CHECK succeeds as above (SEC-OK = 'Y').
  2. READ-ACCOUNT-DB2 issues the SELECT with ACCOUNT_NUMBER = '99999999'. DB2 returns SQLCODE +100 (row not found).
  3. The program initializes OUTPUT-DATA, populates DELACC-ACCNO with the requested number, sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = '1', and immediately exits READ-ACCOUNT-DB2 via GO TO RAD999.
  4. Since DELACC-DEL-SUCCESS ≠ 'Y', neither DEL-ACCOUNT-DB2 nor WRITE-PROCTRAN executes. No DB2 row is deleted and no PROCTRAN record is written.

Output (DFHCOMMAREA):

Field Value
DELACC-DEL-SUCCESS N
DELACC-DEL-FAIL-CD 1
All other account fields Spaces / zeros (initialized in OUTPUT-DATA)

10.3 Example 3 — Security Denial

Input (DFHCOMMAREA):

Field Value
DELACC-ACCNO 00000042

Program flow:

  1. SECURITY-CHECK calls BNKSECCK. BNKSECCK returns BNKSEC-RESULT = 'D' (denied).
  2. The EVALUATE sets DELACC-DEL-SUCCESS = 'N' and DELACC-DEL-FAIL-CD = 'S'. WS-SEC-SW remains 'N' (SEC-NOT-OK).
  3. The IF SEC-OK guard in the main section is false, so READ-ACCOUNT-DB2, DEL-ACCOUNT-DB2, and WRITE-PROCTRAN are all entirely bypassed.

Output (DFHCOMMAREA):

Field Value
DELACC-DEL-SUCCESS N
DELACC-DEL-FAIL-CD S
All account data fields Unchanged / uninitialized
